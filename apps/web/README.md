# apps/web

The web operator UI for aitmproxy: SolidJS + TypeScript, built with Vite.
`aitm web` serves it and the `/bus` WebSocket bridge (the command bus, the MCP
server in `aitm-mcp`) on one origin, `127.0.0.1:8082` by default. The Vite
build in `dist/` is embedded into the `aitm` binary by `crates/aitm/build.rs`;
`dist/` is git-ignored, and a binary built without it serves a "not built"
page instead of the UI. Design, degradations and the bus contract are in
[`docs/design/operator-ui-foundation.md`](../../docs/design/operator-ui-foundation.md).

## Layout

- `src/` the app. `App.tsx` creates the store from `createBus()`
  (`src/bus/index.ts`); `src/state/` is the store, `src/shell/` the primary
  screen, `src/panels/` the sidebar pages, `src/inspector/` and `src/viewers/`
  the detail views.
- `scripts/` Node scripts: the two generators (`gen-tokens.mjs`,
  `gen-langs.mjs`), the live self-test (`selftest-live.mjs`, with
  `live-env.mjs`), the CUA drivers (`cua-live.mjs`, `cua-l4.mjs`) and
  `size.mjs`.
- `src/styles/tokens.css` and `src/viewers/lang/*.gen.ts` are generated by
  `npm run gen` from `docs/design/tokens.json` and
  `docs/design/languages/*.json`; both are git-ignored.

## Dev loop

1. Build `aitm` (`cargo build -p aitm`) and start it with the UI:
   `./target/debug/aitm web`. It prints a start-up block on stdout whose
   `Web UI` line is `http://127.0.0.1:8082/#t=<token>` (and an `Operator` line
   with `&expect=operator` when operator access is configured). The token is
   the bridge's per-run token; it travels in the URL fragment, which the
   browser never sends to the server. Nothing is opened for you.
2. `npm install` once, then `npm run dev`. Vite serves `src/` on
   `http://127.0.0.1:5173` (`strictPort`) and proxies `/bus` to `AITM_WEB`
   (default `http://127.0.0.1:8082`, see `vite.config.ts`). Set `AITM_WEB` to
   reach an `aitm web` bound elsewhere (`aitm web --listen <addr>`, or
   `AITM_WEB_LISTEN`).
3. Open `http://127.0.0.1:5173/#t=<token>` with the token from step 1.
   `createBus()` reads `#t=` (and `#expect=`), keeps them in `sessionStorage`
   and strips them from the address bar, so a reload in the same tab keeps
   the connection.
4. Send traffic through the proxy and watch the list: with
   `python3 -m http.server 8099 --bind 127.0.0.1` as the upstream,
   `curl -x 127.0.0.1:8080 http://127.0.0.1:8099/` (the proxy address is the
   `Proxy` line of the start-up block).

The built UI is the same code served by `aitm web` itself: `npm run build`
writes `dist/`, `cargo build -p aitm` embeds it, and the `Web UI` URL from
step 1 then serves it without Vite.

## The gate

Run in `apps/web`. A change is done when all three hold.

1. `npm run typecheck && npm test` — the unit tests (vitest, jsdom), with
   their inputs written in the test. `npm test` runs `npm run gen` first.
   There is no sample data set: `src/state/bridgeBus.testkit.ts` is the
   in-memory bus the store suites share (`memoryBus`, `bridgeBus`). It answers
   the few tools the store's bootstrap calls, in the server's wire shapes, and
   every flow in it is a literal written in the testkit or the test.
2. `node scripts/selftest-live.mjs` — the live gate. It spawns a real
   `aitm web` (`AITM_BIN`, default `target/debug/aitm` at the repo root, so
   build `aitm` first), sends real traffic through the real proxy to a local
   target and drives the operator workflow over `/bus`. It prints
   PASS/FAIL/SKIP per step and exits 1 on any FAIL. `--keep` leaves `aitm`
   running and prints the UI URL; `--verbose` echoes `aitm`'s stderr. Needs
   Node 22 or newer; it binds local ports, so in this repo's workflow it runs
   from the Terminal.
3. The UI in a real browser against that `aitm web`: open
   `http://127.0.0.1:5173/#t=<token>` (dev) or the `Web UI` URL `aitm web`
   prints (built UI), make a flow with
   `curl -x 127.0.0.1:<listen> http://127.0.0.1:8099/`, and see it in the
   list.

`?perf=1` (`src/shell/perf.ts`, dev builds only) is a frame probe: it samples
`requestAnimationFrame` deltas for 10 s and reports
`{frames, p50, p95, max, dropped}` to the console and `window.__aitmPerf`
(`perfDelay` and `perfSeconds` adjust it; `src/viewers/perf.ts` logs
inspector timings under the same flag). It now measures real traffic only:
the mock's `rate=` stream that used to feed it is gone, so drive the proxy
yourself while it runs.

## No mock bus

No mock bus exists; do not add one. `createBus()` always returns the
WebSocket bus at `/bus` on the page's origin; `?bus=`, `rate` and `initial`
are not read. The mock bus (`src/bus/mock.ts`) and its fixtures
(`src/bus/fixtures.ts`) were removed on 2026-10-31. A test that needs a
`BusClient` uses the testkit above. Evidence for a UI change is the gate:
real `aitm web`, real proxy, real traffic and a browser capture; no fixture,
snapshot or mock run counts.
