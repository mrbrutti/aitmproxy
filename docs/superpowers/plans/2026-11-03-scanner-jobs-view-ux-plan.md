## Overview

The mac Kit (`AitmproxyKit`, no SwiftUI) gets every pure value first: the
decoders (D1), the merged facts and re-read predicate (D2), the sentences (D4,
D9), the derived progress (D8), the words (D10, D11, D14), the link facts (D6)
and Scan Again's arguments (D13), each pinned by a Swift Testing case with the
spec's literals. The app target (`ScanPanelState`, `ScanPanel+Jobs.swift`)
only wires those values to views (PR 2 splits the Jobs view into
`ScanPanel+Jobs.swift`, `ScanJobCard.swift`, `ScanJobWells.swift` and
`ScanProgressViews.swift`), and the live proof on the real app with a
real core and `aitm-testtarget-serve --latency-ms 400` closes each part. Web
and TUI then copy the same table of inputs and strings (the **parity pin**
below) into their own suites.

Within a part, tasks that share a file are sequential; tasks with disjoint
file lists are marked **independent** and may fan out to parallel coders. The
Kit file `ScanSurface.swift` and its test file are the hot spots, so the Kit
tasks of each mac part run one after another; the app-side tasks fan out once
a skeleton task has split the view file. Each part ends with a tester task
(whole-part ACs and the gate), the three-reviewer panel, and a live-proof task
whose output is an evidence folder under `docs/design/evidence/jobs-view-<date>/`
(`pr1/`, `pr2/`, `web/`, `tui/`) and a PR comment linking it.

### Gates

- **mac** (Terminal): `swift test --scratch-path ~/Library/Developer/Aitmproxy/test-build`
  from `apps/mac`; `tools/grid-lint.sh`; the three tripwires
  `tools/check-connection-words.sh`, `tools/check-capture-operator-only.sh`,
  `tools/check-capture-toggle.sh`; `swift build` warning-free. Every Jobs
  string lives in the Kit (`ScanSurface.swift`), never as a quoted literal in
  `Sources/Aitmproxy` (the connection-words tripwire greps the app target for
  whole-literal `"running"`, `"failed"`, `"stopped"`, `"connected"`, …).
- **Rust** (Terminal, log kept under `/tmp/claude/`): `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`.
  Required for Part 2 (Task 2.1 changes `tokens.json`, which `crates/aitm-tui/build.rs`
  regenerates, and `crates/aitm-tui/src/tokens.rs` pins `TOKENS_VERSION`) and Part 4.
- **web** (from `apps/web`): `npm test` (runs `npm run gen` then `vitest run`) and `npm run build` (`tsc --noEmit && vite build`).

### Coder rules that apply to every task

- TDD: write the failing test, run it and watch it fail, write the minimum
  code, run it green; both runs quoted in the report.
- Commit with a path-limited `git commit -- <paths>` listing exactly the
  task's **Files**; never `git add -A`. Format per file (`swift-format` on the
  touched Swift file if the repo uses it, `rustfmt <file>` on leaf files only,
  `prettier --write <file>` for TS); never `cargo fmt` on a crate root, never
  rustfmt on `lib.rs`.
- `Tokens.swift` is GENERATED by `apps/mac/tools/gen-tokens.swift`; it is never
  hand-edited. The web `src/styles/tokens.css` is generated and gitignored.
- A task that finds the spec or this plan wrong stops and reports.
