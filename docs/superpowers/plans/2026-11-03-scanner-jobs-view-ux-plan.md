## Overview

The mac Kit (`AitmproxyKit`, no SwiftUI) gets every pure value first: the
decoders (D1), the merged facts and re-read predicate (D2), the sentences (D4,
D9), the derived progress (D8), the words (D10, D11, D14), the link facts (D6)
and Scan Again's arguments (D13), each pinned by a Swift Testing case with the
spec's literals. The app target (`ScanPanelState`, `ScanPanel+Jobs.swift`)
only wires those values to views, and the live proof on the real app with a
real core and `aitm-testtarget-serve --latency-ms 400` closes each part. Web
and TUI then copy the same table of inputs and strings (the **parity pin**
below) into their own suites.

Within a part, tasks that share a file are sequential; tasks with disjoint
file lists are marked **independent** and may fan out to parallel coders. The
Kit file `ScanSurface.swift` and its test file are the hot spots, so the Kit
tasks of each mac part run one after another; the app-side tasks fan out once
a skeleton task has split the view file. Each part ends with a tester task
(whole-part ACs and the gate), the three-reviewer panel, and a live-proof task
whose output is an evidence folder under `docs/design/evidence/jobs-view-<date>/`
(`pr1/`, `pr2/`, `web/`, `tui/`) and a PR comment linking it.

### Gates

- **mac** (Terminal): `swift test --scratch-path ~/Library/Developer/Aitmproxy/test-build`
  from `apps/mac`; `tools/grid-lint.sh`; the three tripwires
  `tools/check-connection-words.sh`, `tools/check-capture-operator-only.sh`,
  `tools/check-capture-toggle.sh`; `swift build` warning-free. Every Jobs
  string lives in the Kit (`ScanSurface.swift`), never as a quoted literal in
  `Sources/Aitmproxy` (the connection-words tripwire greps the app target for
  whole-literal `"running"`, `"failed"`, `"stopped"`, `"connected"`, …).
- **Rust** (Terminal, log kept under `/tmp/claude/`): `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`.
  Required for Part 2 (Task 2.1 changes `tokens.json`, which `crates/aitm-tui/build.rs`
  regenerates, and `crates/aitm-tui/src/tokens.rs` pins `TOKENS_VERSION`) and Part 4.
- **web** (from `apps/web`): `npm test` (runs `npm run gen` then `vitest run`) and `npm run build` (`tsc --noEmit && vite build`).

### Coder rules that apply to every task

- TDD: write the failing test, run it and watch it fail, write the minimum
  code, run it green; both runs quoted in the report.
- Commit with a path-limited `git commit -- <paths>` listing exactly the
  task's **Files**; never `git add -A`. Format per file (`swift-format` on the
  touched Swift file if the repo uses it, `rustfmt <file>` on leaf files only,
  `prettier --write <file>` for TS); never `cargo fmt` on a crate root, never
  rustfmt on `lib.rs`.
- `Tokens.swift` is GENERATED by `apps/mac/tools/gen-tokens.swift`; it is never
  hand-edited. The web `src/styles/tokens.css` is generated and gitignored.
- A task that finds the spec or this plan wrong stops and reports.

## Gaps and clarifications found while planning

1. **D2 tie rule (clarification, applied in Task 1.2).** Read literally, `make` lets a stored `cancelling` status with `elapsedMs` equal to the list's `cancelled` row win the shared counters, which is the C1 bug itself. The plan orders the rule: terminal status, then terminal summary, then the higher `elapsedMs`. The tie case is pinned in `jobFactsPickTheNewerTruth`.
2. **`TOKENS_VERSION` pin.** `crates/aitm-tui/src/tokens.rs` asserts `"0.1.0"`; AC23's "bumped `$version`" needs that line changed in Task 2.1. The bump value `0.2.0` is the Architect's call.
3. **`jobSubtitle(facts, now:)`.** The spec's signature carries `now`, but the subtitle's elapsed is the bus's `elapsed_ms` (D16) and nothing else in it is clock-relative; the plan drops `now` and adds `timeZone:` (tests pass a fixed zone). Architect's call.
4. **AC7 / AC29 "command recorder".** The app has no such recorder. The plan proves AC7 by the core's audit log and AC29 by a unified-log line the app writes beside the `NSAccessibility` post. Architect's call.
5. **Web banner kinds.** The web bus exposes open / not open, so `.disconnected` and `.unanswered` wordings are not derivable; the web renders the `reconnecting…` text (AC38 asks for exactly that one). Architect's call.
6. **`ScanEndText` placement.** Kept in `ScanSurface.swift` as the spec says (AC32 greps that file), which is why the Kit tasks of each mac part are sequential.
7. **`ScanFormat.grouped` mechanism (found in Task 1.3).** `en_US_POSIX` has no grouping in ICU (`6468` prints as `6468`), so `grouped` inserts the comma deterministically by hand; the outcome `6,468` is what the spec pins. The web and TUI pins use fixed en-US grouping the same way.
8. **Terminal row before its status lands (found in Task 1.3).** D4's Done/Cancelled sentences quote `checks.*`, which D2 calls detail-only, so `ScanEndText.sentence` returns nil for a terminal row whose `scan.status` has not landed (one beat under D2 rule 2); the view shows the row's state word meanwhile. Pinned as `unread` in `endTextIsTheSpecsSentences`. A `failed` job with an empty-string `error` counts as having no error text. **Amended (2026-11-02, PR 1 panel):** the same holds when a status *has* landed but is itself still non-terminal (the list turned terminal first): `sentence` guards on `status.state.isTerminal`, not on the merged state, so the stale read's numbers never appear for the beat; the `gap` pin is nil (gap 10).
9. **D3 changed one pre-existing test (Task 1.2).** `moveSelectionWalksTheVisibleList` assumed `applyList` leaves nothing selected; under D3 it selects the first job, so the test's expectations moved one row. Not a behaviour regression: it is the spec's rule.
10. **`sentence` requires a terminal stored status (found at the PR 1 panel).** `ScanEndText.sentence` is nil unless `facts.status` is present and `status.state.isTerminal`; a stale non-terminal status under a terminal list row yields nil (gap 8 amended). `Failed after 0:12.` still requires the status. Pinned in `endTextIsTheSpecsSentences` (`gap` → nil).
11. **AC10's suffix is an engine fact (found at the PR 1 panel).** Today's engine sets `crawl.last_error` only when `errors > 0 && pages == 0` (`crates/aitm-scan-model/src/job.rs`), so the dead-target job that fetched 1 page reads `The crawl fetched 1 page and hit 1 error` with no suffix; scanner amendment 89 (T1b follow-up) widens the engine to set `last_error` whenever `crawl.errors > 0`. The UI rule is unchanged on either core: the count sentence always, the ` — <words>` suffix only when `last_error` is present (`crawlTroubleLine`). The suffix literal is a unit pin and the shape it will take, not a PR 1 live acceptance (AC10, AC16 amended).
12. **The age clock is not the poll tick (found at the PR 1 panel, fix 1.5d).** The poll loop is sequential and blocks inside a hung bus read for the client's 30 s timeout, so a `nowMs` advanced per tick froze the clause at `0:02 ago` over 38-s-old values. `nowMs` is set by an independent 1 s task on `ScanPanelState` (`clockTask`, started and cancelled with `poll()`); D16's "no view owns a timer" holds (the state owns it). `valuesAgeMs` is clamped at 0.
13. **Help text (Minor at the PR 1 panel).** Task 1.5's original line quoted the UX section's PR 2 help text; D7 keeps PR 1's words (`Stop this job; its issues stay (⌥⌘.)`, `ScanFormat.cancelHelpText`). The PR 2 wording lands in Task 2.8.
