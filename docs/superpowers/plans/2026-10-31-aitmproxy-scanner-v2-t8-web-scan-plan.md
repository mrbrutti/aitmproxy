## Overview

T8 adds a v2 Scan surface under `apps/web/src/panels/scanner/` on top of the D3 verb family: a typed
model with defensive parsers (Task 1), a token-only stylesheet every view shares (Task 2), pure
helpers and the guarded launch (Tasks 5, 6), a live job model that treats push as a trigger and polls
for truth while any job is live (Task 8), the `scanStore(app)` that outlives the panel (Task 9), four
views (Tasks 10-13), the shell plus the `ScanPanel` three-way switch and Sidebar gate (Task 14), a
development mock (Task 7), and the live-proof script (Tasks 4, 15). The shipped v1 `panels/scan/**`
and `state/app.ts` are never edited. Acceptance is the PASS run of `scan-live.mjs` against a real
core with the T1b engine (Task 16); vitest is the inner loop only.

## Shared facts for every coder

- **TDD per task.** Write the named vitest file first, run `cd apps/web && npx vitest run <file>` and
  quote the red run (a type error on a name that does not exist yet counts as red), implement, quote
  the green run. Before handing back: `npm run typecheck` clean and the full `npx vitest run` green in
  `apps/web`. Known pre-existing flake: `src/state/app.activity.test.ts > the log is capped at 500,
  newest` can time out at 5 s under machine load and passes alone; re-run that one file alone before
  calling it a failure. No `npm run build` is needed per task (Task 16 runs it).
- **Scope of edits.** Never edit `apps/web/src/panels/scan/**`, `apps/web/src/state/app.ts`,
  `apps/web/package.json`, `package-lock.json`, or anything outside `apps/web/**`. The store reaches
  the bus only through `app.call` / `app.bus`.
- **Fixtures are shapes, not evidence.** Tests read `crates/aitm-scan-model/fixtures/<name>.json` with
  `node:fs` via `fixture(name)` = `JSON.parse(readFileSync(resolve(__dirname, '../../../../../crates/aitm-scan-model/fixtures', name), 'utf8'))`
  (define `__dirname` from `import.meta.url`). The fixture README forbids treating a green parse as
  proof of anything; no test or report may call a fixture or `?bus=mock` run acceptance.
- **TypeScript.** `strict`, `exactOptionalPropertyTypes` (an optional prop or field that may be
  absent is written `x?: T | undefined`), `noUncheckedIndexedAccess` (index results are `T |
  undefined`; use `!` only after a length check). Parsers take `unknown`, return `T | null`, never
  throw, cap lists at 1024, default absent counters to `0`, and return `null` when a required
  discriminant (`job`, `state`, `id`, `kind`, an enum token) is missing or unknown.
- **Design tokens only** (W-18): colours come from `var(--color-…)` tokens in
  `apps/web/src/styles/tokens.css`; `--color-severity-<level>-fg/bg` only on the pill, the stacked bar
  and chips; `--color-state-<success|warning|danger|neutral>-fg/bg` for job state and pass/fail; text,
  ground, line and space tokens for everything else. No hex, no `rgb(`, no inline `style` colours.
  Icons: `Icon` from `~/components` with an existing `IconName` (`search`, `check`, `lock`, `x`,
  `plus`, `minus`, `play`, `pause`, `flag`, `globe`, `crosshair`, `chevron-right`, `ellipsis`); never
  add a new lucide import for this track.
- **Interaction rules** (foundation §2.8): hover never moves selection; keyboard actions never
  animate; empty states keep the frame; zero prints as `0`, missing as a grey dash `—`.
- **Test stub.** From Task 8 on, every test uses `stubApp()` from
  `apps/web/src/panels/scanner/testkit.ts` (Task 8 creates it; not collected by vitest). Before that,
  tests use `vi.fn()` calls or plain objects.
- **Commits.** One commit per task, message `feat(scanner-v2): T8 task N - <name>` (or `test(...)`),
  ending with the trailer `Co-Authored-By: Claude Mythos 5.1 <noreply@anthropic.com>`.
- **Sandbox.** vitest, `tsc` and `node --check` run in the sandbox. Anything that binds a port
  (`aitm web`, the test target, `scan-live.mjs`, Chrome) runs in the Terminal panel only.
