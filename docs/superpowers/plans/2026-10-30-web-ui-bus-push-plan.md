### Task 0: Measurement script and note skeleton

- **Satisfies:** AC25 (the instrument; the numbers come in T7)
- **Depends on:** none
- **Files:** `apps/web/scripts/bus-load.mjs` (create), `docs/superpowers/web-ui-bus-push-measurement.md` (create)
- **Amended after the first real run (2026-10-30):** the script counts the `notifications/aitm/agent` lines its own subscription receives, not `agent.activity` reads, because over `aitm web` the ring is empty (spec D6 amendment). The text below describes the original ring-based design; where it says "read the ring", read "collect the agent notification lines". The fix is a follow-up commit to this task.
- **Change:** a Node script in the style of `apps/web/scripts/bus-probe.mjs` (global `WebSocket`, no dependency). It connects to `/bus` with `--token`, sends `initialize` with `clientInfo.name` `aitm-bus-load`, subscribes with `flow.subscribe {}` (to count what a subscriber is sent), and from then on calls only `agent.activity`. Flags: `--url` (default `ws://127.0.0.1:8082/bus`), `--token` (or `AITM_WEB_TOKEN`), `--ui-origin mcp|operator` (default `mcp`), `--idle-secs` (30), `--traffic-secs` (30), `--rate` (20 req/s), `--proxy` (default `127.0.0.1:8080`), `--label before|after`, `--json <path>`, `--selftest`. Behaviour: (1) read `agent.activity {limit:1}` and take the newest entry's `at` as the window start (server clock, no skew); (2) idle window, sleep, then `agent.activity {since: start}`; (3) start a loopback HTTP origin on a free port and send `--rate` plain-HTTP requests per second through `--proxy` using `node:http` in proxy form (absolute URI, `Host` = origin) for `--traffic-secs`, then read the ring again with the traffic window's own start; (4) per window keep entries whose `origin === --ui-origin`, drop `command === 'agent.activity'` (the script's own read, reported separately as excluded), count by command, divide by the window length; warn loudly if a read returns 4096 entries (ring wrapped); (5) after the traffic window call `flow.list` once and report `ids.length` and the byte length of its JSON; (6) report notification lines received by the script's own subscription per kind (`flow`, `agent`, `state`) per second. Output is a table on stdout and the same data as JSON with `--json`. Pure helper `summarize(entries, uiOrigin, startMs, endMs)` returns `{perCommand, total, excluded}`; `--selftest` runs it on a canned array and exits 0 without a network. The note skeleton holds the method from spec D9 (the two-binary A/B, why not `vite preview`, the commands) and empty "before" and "after" tables with the columns: command, idle calls/s, traffic calls/s.
- **Test:** `node apps/web/scripts/bus-load.mjs --selftest` (runs in the sandbox). Canned input: a 30 s window with 60 `flow.list`, 15 `proxy.status` and 3 `agent.activity` entries of origin `mcp`, plus 5 `flow.kill` entries of origin `operator`, `--ui-origin mcp`. Expected stdout (AS BUILT, after the notification-stream amendment: the script makes no `agent.activity` call, so the canned `agent.activity` entries are counted like any other command and there is no `excluded` line) contains the lines `flow.list      2.00/s`, `proxy.status   0.50/s`, `agent.activity 0.10/s`, `total          2.60/s`, and exits 0 (the `operator` entries are not the UI's). Also `node --check apps/web/scripts/bus-load.mjs`.
