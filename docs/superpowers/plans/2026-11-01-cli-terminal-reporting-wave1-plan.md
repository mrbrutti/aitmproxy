## Overview

Wave 1 builds one new library crate, `crates/aitm-term` (capabilities, glyphs, colour roles, text rules, a card, an error panel, a `tracing` layer and the in-place `Reporter`), one new module in the binary crate, `crates/aitm/src/startup/` (flags, pre-boot, tracing composition and the log file, typed startup errors, the ready card), and then lands the whole thing in `crates/aitm/src/main.rs` in a single late task. Fourteen tasks, each sized for one fresh Coder in one sitting. T1 first; the `aitm-term` leaf modules and the `startup/` leaf modules fan out in waves over disjoint files; T12 (the only `main.rs` edit) runs after every other code task; the two source-scan pins (T13) and the live-proof script (T14) close the wave.

**The one rule every task repeats (parallel coders share this ONE worktree and ONE git index):** touch only the files your task lists; format with `rustfmt --edition 2021 <your leaf files>` only (never `cargo fmt`, never `rustfmt` on `lib.rs`/`main.rs`, which reformat the whole crate — verify those two with `cargo fmt -p <crate> -- --check`); never `git add`, `git add -A` or `git commit`; the orchestrator commits each wave with explicit pathspecs. Independent tasks in one wave touch disjoint files by construction (see the table).

### Rules every task obeys

1. **Test first.** Write the failing test the task names, run it, quote the red output; write the minimum code; run it green; quote that too.
2. **Hermetic unit tests.** The Bash sandbox cannot bind sockets, create a pty or reach the network. Unit tests drive the renderer through its `io::Write` seam with a fake `Caps` and a fake clock, the tracing composition through an in-memory `MakeWriter`, `Caps::from_parts` with an env closure, and the log file in a hand-rolled temp dir under `std::env::temp_dir()` (the `tempfile` crate is not in the lock). Anything that needs a port, a pty or the real binary is a LIVE PROOF (T14 + the recipe below), run by the orchestrator from the Terminal panel.
3. **Literal assertions.** Every test asserts an exact string, byte sequence, number or value and would fail if the function body were deleted.
4. **Per-package offline gate** in the sandbox after each task (the target dir is warm):
   `cargo clippy -p <crate> --all-targets --offline -- -D warnings && cargo test -p <crate> --offline [--lib | --test <name>]`, plus `cargo fmt -p <crate> -- --check`. For `aitm`, run `--lib` and the task's own `--test <file>`; the crate's full integration suite binds ports and runs only in the Terminal. The FULL gate (`cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`) runs once, in the Terminal, before the panel.
5. **Zero new crates.** `aitm-term` declares `crossterm = "0.29"` (default features; `aitm-tui` already resolves 0.29.0 with `event-stream`, a superset, so nothing new resolves), `unicode-width = "0.2"` (0.2.3 in the lock), `tracing`, `tracing-subscriber = { version = "0.3", features = ["registry", "std"] }` (0.3.23 in the lock), `anyhow`. `aitm` gains `aitm-term.workspace = true` and `libc = "0.2"` (0.2.191 already in the lock via `aitm-proto-http`). The only `Cargo.lock` delta is the `aitm-term` package entry and two edges on `aitm`.
6. **No token anywhere**: not in a test literal that could be mistaken for a real one, not in a log line, not in a PR body. The one place a bridge token is allowed to appear is the two card URL rows on stderr (spec Anti-goals).
7. **`unsafe_code = "forbid"`** holds; `grep -rn unsafe crates/aitm-term/src crates/aitm/src/startup` is empty.
8. **Stop on gaps.** A Coder that finds the spec or this plan wrong, or needs a file its task does not list, stops and reports with the exact sentence that is wrong.
9. Shared `target/` across worktrees reuses stale artifacts: `touch` the files you changed before a gate whose result looks impossible. Parallel `cargo` runs in one worktree serialize on the build-directory lock; that is expected.

### Plan-level calls (Architect; how the spec is read where it left wording open — veto any)

- **C1** `aitm-term`'s `lib.rs` is written once by T1 (module declarations and doc only, no root re-exports) and never edited again in wave 1; consumers use module paths (`aitm_term::reporter::Reporter`, `aitm_term::caps::Caps`). D1's "`lib.rs` re-exports" is deferred to a later wave so parallel coders never share the crate root.
- **C2** `style::paint` writes the classic 16-colour SGR codes itself (`ESC[34m` accent, `ESC[32m` success, `ESC[33m` warning, `ESC[31m` danger, `ESC[2m` dim, `ESC[1m` bold, reset `ESC[0m`). crossterm 0.29 encodes every named colour as `38;5;n` (the 256-colour form; `src/style/types/colored.rs`), which T2 forbids. crossterm is used for cursor movement, clearing, width and the synchronized-update brackets only. Deviates from D3's "through `SetForegroundColor`"; honours T2.
- **C3** No cursor hide/show in wave 1. D4's claim that Ctrl-C restores the cursor through the `Drop` guard is false during startup (tokio's `ctrl_c` is installed only in the serving `select!`; a SIGINT before that kills the process without running destructors), so a hidden cursor could survive a Ctrl-C mid-spinner. The spinner is redrawn in place with the cursor visible at the end of the last live line.
- **C4** Checklist policy: `Reporter::checklist(true)` (serving modes) prints a done line for every phase, fast or slow; `checklist(false)` (one-shot, the default) prints nothing for a phase that finishes within the 100 ms first-draw delay. `header()` is called only in serving modes.
- **C5** The renderer never truncates or wraps card rows or fix commands (URLs, paths and commands stay copyable); phase and warning lines are end-truncated to the width with the ellipsis glyph. Wave 1 cards draw no rule line (M1/M6 have none).
- **C6** Rich versus plain for cards, panels and warnings follows `caps.animate` (D4): `-v`, `-vv`, `RUST_LOG`, `CI`, `AITM_TERM=plain` and every non-TTY stream get the plain forms.
- **C7** `~` shortening is applied by the caller (`Reporter::display_path`, `ReadyInputs.home`), where `home` is `Some` only when `caps.animate`; `Card`/`Row` stay mode-agnostic so the plain renderer prints full paths (M1p).
- **C8** `Verbosity` lives in `aitm_term::caps` beside `ColorChoice` and `TermMode`, so `startup::args` depends on T1 only.
- **C9** `UiEvent` and `EventSender` live in `aitm_term::event` (T1). `EventSender` wraps an `Arc<dyn Fn(UiEvent) + Send + Sync>` so the tracing layer (T5) and the reporter (T6) are built in parallel. Redaction runs in the layer before the event is sent (no secret ever crosses the channel) and matches a field name equal to, or ending with, `token`, `secret` or `password`, case-insensitively.
- **C10** The render loop is a pure `Renderer` state machine (`handle(Msg)`, `tick()`) owned by the `aitm-term` thread; unit tests drive it directly with a `FakeClock`, never by sleeping. Blocking calls (`card`, `error`, `finish`, `finish_and_clear`) wait for an ack with a 2 s timeout; sink write errors are ignored (a closed stderr never ends startup). After `finish()` the reporter keeps working synchronously in plain-line form, so a WARN during the run still prints.
- **C11** `finish_and_clear` erases every line the reporter wrote below the header, plus the header's trailing blank line, as `ESC[1A ESC[2K` per line, leaving the cursor directly under the header (M7, AC-W1-25).
- **C12** `DEFAULT_LOG_DIRECTIVE` and `build_env_filter` move verbatim from `main.rs` to `startup/log.rs` (made `pub`) with their three unit tests; `DEBUG_LOG_DIRECTIVE` is the same list with `debug` in front. T12 deletes `tui::init_tracing`, `tui::log_path_from`, `tui::open_log_file`, `tui::default_log_file_name` and their three tests (replaced by the shared composition; `TuiLog`, `LOG_PATH_ENV`, `USAGE`, `services`, `run` stay) and `web::startup_summary` with its two tests (dead once the card replaces the `println!`).
- **C13** `crates/aitm` gains `libc = "0.2"` for `O_NOFOLLOW` on the log file, exactly as `crates/aitm-proto-http/src/ca.rs:174` opens the CA key (`OpenOptionsExt::custom_flags`). Zero new lock entries.
- **C14** In tui mode the composition installs the file layer only (no `UiLayer`, no stderr layer): after the handover ratatui owns the terminal and a later WARN must not reach stderr. `-v`/`-vv` in tui mode raise the file filter the way `RUST_LOG` does. The reporter's own `warn()` (log file problem) still prints during the pre-screen.
- **C15** `report_for` on a Usage-kind error takes the first line as `what` and the following lines as `why` up to, not including, the registry's usage dump (the line starting `usage: aitm <command> [--flag value]...`), which the `▸ aitm --help` pointer replaces (W2 restyles help).
- **C16** The `checking CA trust` read is `aitm_ca::store::trust_statuses(cert, platform, exec) -> anyhow::Result<Vec<StoreStatus>>` (new, additive), called by both `ca.status`'s `invoke` and `startup::card::read_ca_trust`, so the word cannot diverge (D1). `CaCert::load`, `Platform::detect` and `RealExecutor::new()` are the existing pub pieces around it. It runs blocking on the runtime thread like the system-proxy recovery, serving modes only.
- **C17** `aitm-browser` gains one additive accessor, `LaunchedBrowser::version(&self) -> Option<&str>` (the obscura `ProbeInfo.version`; `None` for Chrome/Firefox), because D13/T7 pin the plain line `obscura probed <version>` and the version exists only inside `ObscuraDriver::launch`. A non-obscura engine's summary is `browser ready (<engine>)`.
- **C18** `bind_then_recover_system_proxy` returns `anyhow::Result<(T, Recovery)>` (`Recovery::Nothing` when the mode does not manage the system proxy) so `run()` emits `restoring system proxy` only when the recovery did something. Summaries: `Set` → `system proxy set to this proxy`; `Adopted { pid }` → `system proxy adopted · watchdog <pid>`; `Restored { restored, .. }` → `system proxy restored · <n> service(s)`; `Forgot` → `system proxy state file forgotten`; `Failed` prints no phase line (its existing `warn!` reaches the view through the `UiLayer`).
- **C19** `SYNOPSIS` is a `const` built with `concat!(…, env!("CARGO_PKG_VERSION"), …)`. The 17 `GROUPS` are the first segments of the **built-in** registry: what the real 0.5.10 binary registers with a default config and `AITM_NO_BUNDLED_SCRIPTS=1` (verified 2026-11-01 on this worktree's build: `agent browser ca capture config findings flow map poc proxy request scan scope script session tls ws`). Excluded on purpose: `check` (15 verbs) and `l4` (`l4 recon`, `l4 tcp_probe`, `l4 udp_probe`), because both come from the bundled Rhai catalogue (`scripts/bundled/active/*.rhai`, `scripts/bundled/l4/*.rhai`, registered by each script's `load(reg)`), which the operator can turn off or replace (`AITM_NO_BUNDLED_SCRIPTS`, `AITM_BUNDLED_SCRIPTS`, path dedupe); the `L4Module`'s own `l4.*` verbs register only when `l4.enabled` (`wire.rs:514`). `demo` and `egress` exist only in test modules (`aitm-mcp/src/server.rs`, `aitm-cli/src/dispatch.rs`) and are not groups. `script.*` and `findings.*` reach the registry through `ScriptWiring.commands`, so the pin test assembles the way `main` does with an EMPTY tier (`RhaiConfig::default()`, no scripts) plus `FindingsPlugin`, not bare `build_proxy_with`. W2's generated help lists whatever the live registry holds (`check` and `l4` included).
- **C20** `apps/web/scripts/live-env.mjs`: a node `spawn` pipe is a non-TTY, so the card arrives in the plain `Label: value` form; the `Operator` and `Web UI` regexes become colon-tolerant (`/^\s*Operator:?\s+(https?:\/\/\S+)/m`, `/^\s*Web UI:?\s+https?:\/\//m`) and run over `out + stderr`. Three small edits, not one.
- **C21** The Unicode locale rule follows the spec literally: rich glyphs when ANY of `LC_ALL`, `LC_CTYPE`, `LANG` ends in `utf-8`/`utf8` (case-insensitive) and `TERM != linux` and `AITM_TERM` is not `ascii|plain`. The proof sets all three to `C`.
- **C22** `CI` present with any value, including empty, means `ci = true` and plain lines (anstyle's `is_ci`).
- **C23** Channel: `std::sync::mpsc`. Temp dirs in tests: `std::env::temp_dir().join(format!("aitm-term-{tag}-{pid}-{seq}"))`, removed on drop.
- **C24** `-v`/`-vv` append ` · in <n> ms` (dim) to done summaries. The `Browser` row value is one plain string `127.0.0.1:8081  (SSRF-filtered)` in wave 1 (no per-fragment dim).
- **C25** `BusWord::Loopback(0)` displays `loopback 127.0.0.1 (ephemeral port)`; otherwise `loopback 127.0.0.1:<port>`.
- **C26** `split_term_args` runs first on the raw argv, scanning until the first bare word and stepping over the values of `--config`, `--script` and `--bus-endpoint-file`; it strips `-v`, `-vv`, `--verbose` (each occurrence raises one level, capped at Debug), `-q`, `--quiet`, `--color <v>`, `--color=<v>`; tokens after the mode word are left alone. `-V` is never touched (pre-boot already answered it).
- **C27** `Caps`, `Glyphs`, `Card`, `Row`, `ErrorReport`, `FixCommand`, `UiEvent`, `TermOpts`, `LogSink`, `StartupError` derive `Debug` and `PartialEq` (plus `Clone`/`Eq` where the fields allow) so tests compare whole values.
