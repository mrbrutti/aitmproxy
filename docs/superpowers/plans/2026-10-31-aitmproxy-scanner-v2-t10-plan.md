## Shared facts for every coder

- **TDD per task.** Write the named test first, run it, quote the red run (a compile error on a symbol that does not exist yet is red), implement, quote the green run. Both runs go in the report.
- **Sandbox vs Terminal.** `cargo test -p aitm-testtarget --lib --offline`, `cargo clippy -p aitm-testtarget --all-targets --offline -- -D warnings` and `cargo fmt --check` run in the sandbox. **Anything that binds a port runs in the Terminal panel**: `crates/aitm-testtarget/tests/*.rs` (so `cargo test -p aitm-testtarget` without `--lib`), the serve binary, every e2e cell, `python3 tests/e2e/run.py`. Full gate from the worktree root before handing back: `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` (Terminal). Gate on the exit code, never on a grep.
- **Dependencies offline.** Only Task A0 edits `crates/aitm-testtarget/Cargo.toml` (plus A21's dev-dependency line). After the edit run `cargo metadata --offline --format-version 1 >/dev/null; echo $?` and quote it. The packages are all in `Cargo.lock` (`rustls 0.23.46`, `tokio-rustls 0.26.6`, `rcgen 0.14.10`, `serde_json 1.0.154`, `sha1 0.10.7`, `sha2 0.10.9`, `base64 0.22.1`, `h2 0.4.19`, `futures-channel`); hyper's lock entry gains the edges `h2` and `futures-channel`, nothing else may change in `Cargo.lock`. **No new dependency unless named here**; `tokio-tungstenite`, `tokio-util`, `rand`, `uuid`, `regex` are not used.
- **Crate rules.** `[lints] workspace = true` already forbids `unsafe_code`; keep `//!` module docs; **no `unwrap`/`expect` on anything read from a socket or a request** (body, headers, frames, datagrams): parse errors are 400s, protocol errors or `Step::ProtocolError`, never panics. `expect` on `Response::builder()` with constant headers stays as today.
- **The manifest is never served and never read by a served module.** `app.rs`, `routes/*`, `ws.rs`, `tls.rs`, `control.rs`, `speakers/*` do not name `manifest`; markers come from `seed.rs` only. `/` is byte-identical in V and P (`index_links_all_seeded_endpoints` pins it); P-only headers are added in `finalize`, after routing.
- **Speaker `verb`.** Every `Parsed::Message` a speaker (A7-A12) returns carries `verb: Some(..)` naming what it parsed (`PING`, `version`, `fc3`, `CONNECT`, `A`, `frame`, `EHLO`, `USER`, ...; uppercase as the protocol spells it) or `None` when the bytes did not parse; the driver (A19) logs it on the `in` message so a cell can prove no denylisted verb arrived.
- **Wire literals are the spec's.** Every body, status, header, reply byte string, cap and error text is in the child spec D3-D5; a coder who needs one that is missing stops and reports (does not invent).
- **Hermetic seeds.** No file read, no `std::process`, no outbound socket in any seed; every "file", "command" and "entity" resolves to a constant.
- **No verb, no contract re-pin.** `crates/aitm/tests/frontends.rs`, `crates/aitm-tui/src/lib.rs` `CORE_TOOLS`, `crates/aitm-tui/fixtures/bus-fixture.json`, `crates/aitm/tests/bundled_startup.rs`, `crates/aitm-plugin-rhai/tests/bundled_scripts.rs` are not edited; A23/B12 only re-run them.
- **Python cells.** Pure stdlib, `sys.path.insert(0, parents[1])` like the sibling cells, own core on `free_port()`s, never print a token, tag on line 2, every scan verb through `aitm_e2e.scan` (`scan_call`/`scan_try`/`start_job`/...), SKIP 77 via `require_verbs`/`require_lane`/`skip(...)` with a reason naming the missing thing, exit 0/1/77. Cells that need a lane the current build lacks must SKIP, not FAIL, and must still pass `python3 -m py_compile`.
- **`scanner:` boots only on a T1b core.** `crates/aitm/src/config_file.rs` puts `deny_unknown_fields` on the top-level file struct, so a config with a `scanner:` section makes a pre-T1b core **fail to boot** (parse error), not ignore it. Every cell that sets `CoreConfig(scanner=...)` (t1_agent_gates, t6_gates, t10_harness_config, any cell using `ceilings`) first boots a probe core **without** `scanner=`, runs `require_verbs(op, "scan.start", ...)` on it (SKIP 77 when absent), stops it, and only then boots the core with the section. Found by the B1 coder, 2026-11-01.
- **Report.** Each coder's report quotes: the red run, the green run, `cargo fmt --check`/clippy output for the crate, and for Terminal tasks the command lines and their exit codes.
