## Overview

The surface is built bottom-up in two layers that never share a file, inside the files T9 holds. **Kit first** (no SwiftUI): the wire types for every verb result and push line (`ScanModel.swift`), proven by tests that read the 22 fixture-pack JSON files from the repo path (`crates/aitm-scan-model/fixtures/`, the parsing contract, inner loop only); then the state model with the launch gate, the `_confirm` handshake, the push-as-trigger rule, grouping and every text the views render (`ScanSurface.swift`). **App second**: `ScanPanelState` grows the model, the polling loop and the intents; `ScanPanel` becomes a switch between the legacy `scan.discover` form and the new `ScanSurfaceView`; the four tabs and the confirm sheet each live in their own `ScanPanel+<Name>.swift`. The stories and glossary rows are appended. An integration task rebases, runs the gate and the live proofs, and opens the PR.

**Everything in this PR works without any wiring outside T9's files.** The Scan page polls `scan.list` / `scan.status` / `scan.issues` while it is visible (spec D8), so a running job's counters and new issues arrive without the push sink; `ShellView` already renders `ScanPanel(state: session.scan)`; the sidebar keeps reading the legacy `session.scan.points.count`. The push sink, the `flow.subscribe` call and the three command-map rows are **one blocked follow-on task** (Task 12) for a separate additive PR; MS-AC7 and MS-AC12 belong to it.

**Claim ruling (2026-10-31).** Granted now: `apps/mac/Sources/AitmproxyKit/Panels/Scan*.swift`, `apps/mac/Sources/Aitmproxy/Panels/ScanPanel*.swift`, `apps/mac/Tests/AitmproxyKitTests/Scan*.swift`, `apps/mac/docs/STORIES.md` (append-only), `apps/mac/docs/GLOSSARY.md` (append-only). Denied permanently: `Fixtures+Tools.swift`, `SnapshotScenes.swift`, `Bus/FixtureBus.swift` (deleted by the fake-data removal PR) — so there are no snapshot scenes, no fixture-bus answers, no Swift literals of the pack (`Fixtures.scanV2` does not exist) and `scan.*` is not registered in `Fixtures.tools`. Waiting (follow-on PR): `Session.swift`, `Bus/BusService.swift`, `CommandMap.swift`, the Proxy menu in `App.swift`, `docs/BRIEF.md`. Not touched at all: `Session+Palette.swift`, `Shell/SidebarView.swift`, `Shell/ShellView.swift`.

**Fan-out.** Tasks 5, 6, 7, 8 and 9 (Profiles, Jobs, Site map, Issues, Confirm) are independent of each other once Task 4 lands: each edits only its own `ScanPanel+<Name>.swift`, and every Kit helper they bind to lands in Task 3, so no view task touches a Kit file. Task 10 (docs) is independent of every code task. Tasks 2 → 3 → 4 are sequential; Task 11 is last in this PR; Task 12 is the blocked follow-on.

**Every "Done when" below** is run by the orchestrating session in the Terminal panel; coder sub-agents cannot run SwiftPM. The shared gate line is:

```
cd apps/mac && swift test --scratch-path ~/Library/Developer/Aitmproxy/test-build-t9 && tools/grid-lint.sh
```

Coders still work test-first: write the named tests, state in the report which must fail before the change and pass after, write the minimum code, and report. A coder who needs a model helper that is not in Task 3's list, or a product decision the spec does not make, stops and reports the gap; it does not invent one.

**The pack reader (shared by every test file).** `ScanModelTests.swift` declares `enum ScanPack { static let url: URL; static func load(_ file: String) throws -> JSONValue; static var files: [String] }` where `url` is `URL(fileURLWithPath: #filePath)` with five `deletingLastPathComponent()` calls (file → `AitmproxyKitTests` → `Tests` → `mac` → `apps` → repo root) then `.appending(path: "crates/aitm-scan-model/fixtures")`, `load` is `JSONValue.parse(Data(contentsOf:))`, and `files` lists the directory's `*.json` names. The pack is a parsing contract and a development input; it is never evidence (pack README, spec D14).

**Design rules (every view task restates and obeys these).** Flat monochrome SF Symbols, no glass or capsules; hue only on data, which here means the severity pills, the severity section headers and the stacked bar, all from `Tok.Severity.*` (critical, high, medium, low, info); everything else is ink on ground (`Tok.Ink.*`, `Tok.Ground.*`, `Tok.Line.*`). 4 pt grid: spacing from `Space.*`, sizes from `Tok.Size.*`, radii from `Tok.Radius.*`; `tools/grid-lint.sh` must PASS; `Tokens.swift` is generated and never hand-edited. Reuse the kit parts: `PageHeader`, `PaneTabs`, `Badge(text:pair:uppercase:)`, `FlatButton(_:symbol:action:)`, `PrimaryButton(_:hint:action:)`, `FlatMenu(title:width:content:)`, `FlatToggle(_:isOn:)`, `Hint(text:)`, `Rule`, `VRule`; system `Picker(.segmented)` is the one system control allowed (no custom chrome). `.help()` on every icon-only control, with the spec's D12 phrasing (verb first, shortcut last). Accessibility per D13: one element per row with a label that reads the row's words; severity never by colour alone; the severity bar is `accessibilityHidden`; no entrance motion. `ContentUnavailableView` for empty states with D11's exact words. Every number the Jobs surfaces show is a `scan.status` / `scan.list` value. Visual checks happen on the real app against a live core (`DEV_TAG=t9 tools/snap-dev.sh` with `APP_LIVE=1`), never on fixture data.
