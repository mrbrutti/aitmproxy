## Architect's calls (the orchestrator approves or corrects; each is referenced from its task)

- **C1 (83)** — the value branch keeps bare `/` out (`traits_for("/") == []`): a lone slash is every path's first byte and carries no signal, and the name branch is what makes `/redirect?next=/` and `/go?dest=/` `Url` points. The ruling's literal "starts with `/`" is read as "a path with something after the slash"; `//host`, `\/host` and `\\host` are added. Reject if the coordinator meant bare `/` too.
- **C2 (83)** — the name branch applies to every kind except `PathSegment`, `PathFilename` and `EntireBody` (a path segment's "name" is the segment text, the body's is the lane's own label `body`; neither is a parameter name). Names compare ASCII case-insensitively against the ruling's eighteen, exact (not substring): `returnTo`, `REDIRECT_URI` match; `nextpage` does not.
- **C3 (59)** — `HttpResponse` is not a serde type, so the `#[serde(default, skip_serializing_if)]` the ruling spells cannot be applied; the `peer` field is a plain `Option<SocketAddr>` and the wire carrier is `server_conn` (`flow.detail` already emits it). Confirm this satisfies "wire type on `flow.get`/`flow.detail`".
- **C4 (59)** — `ConnInfo` for a client-sent flow: `peer` from the response, `tls = scheme is https`, `sni: None`, `alpn: None`, `established: now`. No attempt to thread SNI/ALPN through `HttpResponse` (the h2/h1 fact is `response.version`). `Http1Sender` (the TUI/web/CLI frontends' replay client, `crates/aitm/src/tui.rs:135`) is not touched in this PR: the binary's scan path and the `aitm` server run through `HttpSender`; a `peer` from `Http1Sender` is a follow-up if the frontends' manual `check.<id>` needs it.
- **C5 (67)** — the shared scrub is `impl Verdict { pub fn scrub(&mut self); pub fn scrubbed(self) -> Self }` in `aitm-scan-model/src/check.rs`, over `aitm_core::redact::scrub_text_wide` and `Evidence::excerpt` (scrub, then bound — amendment 16's order), recursing into `more`. `manual_check.rs`'s three private functions are deleted; the bridge scrubs in one place (`verdict_from_dynamic`) instead of inside `verdict_from_map`.
- **C6 (69)** — the sample goes on a new additive `CheckCounters.skipped_samples: Vec<CheckErrorSample>` (same type, same `MAX_CHECK_ERROR_SAMPLES` cap, same `(check, detail)` dedup), not into `error_samples`: an operator reading `error_samples` must not see skips counted as errors, and `errors` stays equal to the sum of error verdicts.
- **C7 (69)** — a skipped item still settles the point's owed counter (so `points.audited` behaves as today and the amendment-38 pins hold); it does **not** bump `checks.done`. After the fix `done + skipped == scheduled` at the end of a job; `done == scheduled` is no longer promised (no in-tree consumer asserts it).
- **C8 (72)** — recommendation on "required (no default bodies)": make `client()`, `charge()` and `captured()` required; keep `shared()` default-bodied (`None` is the right answer for every inner host — the engine's `ArcHost` is the one `Some`, and that is pinned) and keep `baseline_peer_addr()` default-bodied (`None` = unknown is a legitimate answer with a working fallback). Twelve impls then need code (list in Task 13). Because three of them live in T4/T5/T6 crates, the tightening is Task 13 in PR 3b and fires only on the coordinator's cross-crate OK; Task 12 (the runtime contract over the hosts T1b owns) ships regardless.
- **C9 (72)** — `WsProbeHost`, `PacketHost`, `StreamHost` `captured()` return `None` (no HTTP flow is "the traffic this point came from" for them; the WS handshake stays in `held_flows`), `client()` = `Some(job.client())`, `charge(units)` = `job.charge(units)`.
- **C10 (73a)** — `admit` receives `&targets` (origins ∪ L4 `ip:port`) and the entry stores `origins: targets.clone()`, exactly the two lines the coordinator named; the field's doc now says "the normalized HTTP origins and the L4 `ip:port` targets the job is single-flight on". Side effect accepted: `scan.sitemap { target: "<ip>:<port>" }` resolves to the newest L4 job (an empty sitemap) instead of none.
- **C11 (81)** — recommendation: **option (b)**, hand the guard to the `JobClient` and charge on `AwaitEnd::Timeout`. Reasons: the core cannot tell the scanner's 30 s cap from the job's deadline or a `scan.cancel` — all three drop the same future — so a drop-guard in `send_inner` would charge the breaker for cancels and deadlines, which the ruling excludes; (a) would also change every other `ProxyClient` consumer that drops a send (a Rhai `http.send` under a script timeout), a behaviour change the ruling does not ask for; (b) is ~20 lines, charges under the spelling the guard already keys on (`ladder_key` = `guard_authority`, amendment 74), and excludes deadline/cancel by construction. Shape: a builder `JobClient::with_guard(self, Arc<dyn ScopeRateGuard>) -> Self` so the seven-argument `new` and its 22 test call sites stay.
- **C12 (nosqli-json)** — the script's `entire_body` branch rebuilds the document from `point.example` (scrubbed, so a secret field reads `[redacted]` in the probe — acceptable for a probe value) and degrades to `inconclusive` with the detail `"the JSON document is longer than the point's example; document-level operators need the whole body"` when the example does not parse. It gates itself with `wants_traits: ["json"]` (every `json_value` point and every JSON `entire_body` point carries `json`; a form or XML body does not), so no probe is spent on a non-JSON body. The oracle is a **status flip with a control** (operator document answers 2xx while the baseline and a string control at the same field do not) OR the existing size-delta rule with the control within threshold; the verdict's `location.name` is the field the operator sat in.
- **C13 (nosqli-json, lane-side)** — with the 64-char cap, C12 reaches the seeded `/api/login` body (45 chars) and little else; a real JSON body is almost always longer. Task 11b raises the example cap for `EntireBody` points only, to `MAX_ENTIRE_BODY_EXAMPLE_CHARS = 1024` (scrubbed first, then cut, as today), so document-level checks see the document. This widens what `scan.points` shows for a body point (scrubbed). Strike Task 11b if the orchestrator wants the example to stay 64; the sweep is green either way.
