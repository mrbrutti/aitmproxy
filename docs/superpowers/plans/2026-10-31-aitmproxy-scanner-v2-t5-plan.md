## Overview

T5 flips `aitm_scan_l4_packet::lane()` from `None` to a real `Lane` that fuzzes IPv4/IPv6, UDP and TCP header fields and the raw payload of a crafted `PacketSpec` against operator-declared L4 targets, one `send_recv` per case behind the deny-by-default `L4Guard`, with a liveness oracle, bounded crash triage (reproduce N times, then retire the point) and non-overridable ceilings. It adds exactly one file to `aitm-proto-l4` (`icmp.rs`: ICMP type/code, TCP RST and transport-payload views over an `L4Packet`) plus its `pub mod` line. No shared file is edited until the integration task, which re-pins the one literal T1a's call A23 reserved for lane tracks.

The engine (T1b, in flight) drives a lane as: `discover` yields points; for every admitted `(check, point)` it calls `probe_host_for(point, job)` and then `check.run(point, host)`, which returns one `Verdict`; issues come only from `Outcome::Vulnerable`. The lane therefore runs **one fuzz run per point**, cached and idempotent, that two checks read: `l4-packet-crash` (Critical, the liveness-failed crash) and `l4-packet-reaction` (Info, the ICMP/RST reactions). Whichever check reaches a point first drives the cases; the other reads the cached run and sends nothing.

## Shared facts for every coder

- **TDD per task.** Write the named test first, run it and quote the red run (a compile error on a type that does not exist yet counts as red), implement, quote the green run. No production code without a failing test first.
- **Sandbox vs Terminal.** `cargo test -p aitm-scan-l4-packet --offline`, `cargo test -p aitm-proto-l4 --offline`, `cargo clippy --offline` and `cargo fmt --check` work in the sandbox (offline registry cache). Anything that opens a pcap handle for real (Task 12's live test) or binds a port runs in the Terminal panel. Full gate from the worktree root before handing back: `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`. Gate on the exit code, never on a grep.
- **Dependencies offline.** After any `Cargo.toml` edit run `cargo metadata --offline --format-version 1 >/dev/null; echo $?` and quote the exit code. `rand`/`rand_chacha` are declared in `[workspace.dependencies]` but are **not in the offline cache**: the lane never inherits them (Task 2 hand-rolls a seedable PRNG). No new external dependency anywhere in this track. The lane crate inherits only `aitm-proto-l4`, `aitm-scan-model`, `aitm-poc` (for `Severity` in `CheckMeta`), `aitm-core` (for `aitm_core::Flow` in `ProbeHost::held_flows`), `anyhow`, `futures`, `tokio`, `serde`, `serde_json`; `etherparse` is used only inside `aitm-proto-l4`.
- **Root manifest frozen.** No task edits the root `Cargo.toml` or `crates/aitm/**` except Task 13's one-literal re-pin (T1a call A23). `Cargo.lock` is derived and may change mechanically (new internal edges only).
- **Crate hygiene.** `#![forbid(unsafe_code)]` at the crate root and `[lints] workspace = true` (already present in the skeleton); every module starts with a `//!` doc naming the plan task that owns it.
- **Wire-derived bytes are hostile.** No `unwrap`, `expect`, slice indexing or arithmetic that can panic on bytes that came off the wire (`L4Packet.bytes`, reply frames, captured payloads): use `get`, `split_first`, checked arithmetic, and `etherparse` (inside `aitm-proto-l4`) for header parsing. Our own crafted bytes are trusted only after `PacketSpec::build()` succeeded.
- **Redacting `Debug`.** Every new in-process type that carries wire bytes (`CaseRecord`, `PointRun`, `Sent`, the mock backend's queues) hand-writes `Debug` to print bytes and hex strings as lengths (`<37 bytes>`), never contents, mirroring `aitm_scan_model::point::L4Reply`.
- **Prefix every refusal message with its D3 code** (`invalid_profile:`, `out_of_scope:`, `lane_unavailable:`, `refused_l4:`) so the engine and the harness can match the token; the lane has no other refusal surface.
- **Every send is one `L4Permit`.** `send_recv` mints an `Inject` permit and a `Capture` permit per call and spends one rate token per packet at the wire choke point; the lane never re-implements that, never calls the backend's `inject` directly, and never mutates `dst`, `dst_port`, `src`/`dst` addresses or `ether.*` (pinned by construction; `send_recv`'s C3 check refuses a stimulus whose crafted destination differs from `spec.dst`).
- **`send_recv` is blocking** (one thread per call, one pcap handle per call). Every call from async code goes through `tokio::task::spawn_blocking`.
- **Commit per task**, subject `feat(scan-l4-packet): task N - <name> (plan 2026-10-31-aitmproxy-scanner-v2-t5)`, no `--` in subjects, trailer `Co-Authored-By: Claude Mythos 5.1 <noreply@anthropic.com>`.
- **Tree state.** The worktree carries `origin/feat/scanner-v2-t1a` merged with `main` v0.5.8 at `e0464e0e`. `send_recv`'s signature is unchanged. New since the first survey and usable here: `PacketSpec::endpoints(bytes) -> PacketEndpoints { proto, src, dst, src_port, dst_port }` (all `Option`, `Default` for a non-packet) and `L4Guard::{set_self_ports, add_self_ports, self_ports, admit_frame, admit_endpoints}`: the reply capture inside `send_recv` **drops** a loopback frame whose source or destination port is one of the core's own listener ports (self-exclusion), so the lane never fuzzes the core's own listeners and never picks a self port as its source port (Task 7).
- **Two integration shims** (coordinator amendment). T1b is adding `L4Options.fields: Vec<String>` and a default-bodied `JobCtx::report_l4(&self, counters: L4Counters)`; neither exists on this branch yet and `L4Options` is `deny_unknown_fields`, owned by T1a/T1b. The lane isolates each read/call in **one small function**: `plan::requested_fields(profile) -> Vec<String>` (returns an empty list until Task 13 flips its body to `profile.l4.fields.clone()`) and `state::report_counters(job, counters)` (a no-op until Task 13 flips it to `job.report_l4(counters)`). All validation and counting behind them is pure and unit-tested now, so the profile wiring is a one-line change per shim at integration (calls C1 and C1b).
- **Fixture rule.** `cargo test` with the mock backend is the inner loop. Acceptance for T5-1/T5-2/T5-3 is the real-bus cells `tests/e2e/scan/test_t5_*.py`, owned by **T10** (spec D12) and runnable once T1b's engine is on `main`; this plan creates none of them. ## Ownership model inside the lane (read before Tasks 7-11)

```
PacketLane  (lane.rs)
 ├─ Arc<Shared>          (host.rs)   guard, backend, lane-private case store, seed store, Timing, Arc<LaneState>
 ├─ Arc<LaneState>       (state.rs)  per-job: TargetPlans, minted point ids, counters, stop flag, retired points, PointRun cache (keyed by job_id)
 ├─ Arc<RunnerRegistry>  (host.rs)   (marker, point_id) -> Arc<PointRunner>
 └─ checks: [CrashCheck, ReactionCheck]  (checks.rs)  each holds Arc<RunnerRegistry>

Lane::probe_host_for(point, job)  -> builds Arc<PointRunner> (holds Arc<Shared>, Arc<dyn JobCtx>, TargetPlan, FieldPath),
                                      registers it under (job.marker(), point.id), returns Box<PacketHost { runner }>
Check::run(point, host)           -> registry.get(host.marker(), &point.id) -> runner.run_point().await -> Arc<PointRun>
```

No cycle: registry -> runner -> shared -> state. The check never downcasts `&dyn ProbeHost`; it keys by `host.marker()` (the job's marker, equal to `JobCtx::marker()`) and the point id. `LaneState` keys its per-job tables by `job_id()` and remembers at most `MAX_JOBS_REMEMBERED = 8` jobs (oldest evicted), because no engine hook tells a lane when a job ends (follow-up for T1b, call C2).

## Architect's calls in this plan (for the orchestrator/Matt to approve or correct)

- **C1 Field selection through the `requested_fields` shim** (coordinator decision): the operator's field list is T1b's `L4Options.fields: Vec<String>` (empty = the lane's full default table for the transport). The lane reads it in exactly one `pub(crate) fn requested_fields(profile) -> Vec<String>` in `plan.rs`, empty-bodied until Task 13 flips it; validation is the pure `fields::validate_fields(ip, transport, &[String]) -> Result<Vec<FieldPath>, String>` whose errors start with `invalid_profile: ` and name the pinned/unknown/inapplicable path, unit-tested now. `L4TargetSpec.grammar` is not read by the packet lane. `PacketLane::with_default_fields` supplies the list when the profile requests none (tests and the live test use it until the flip).
- **C1b Counters through the `report_counters` shim** (coordinator decision): `pub(crate) fn report_counters(job: &dyn JobCtx, counters: L4Counters)` in `state.rs`, a no-op until Task 13 flips it to T1b's default-bodied `JobCtx::report_l4(counters)`; the runner calls it after every point run and whenever a job's lane state is stopped. `PacketLane::counters(job_id)` stays regardless (C7).
- **C2 One point run shared by two checks via a `RunnerRegistry` keyed `(host.marker(), point.id)`.** `probe_host_for` builds and registers the `PointRunner`; `Check::run` finds it through the registry without downcasting; `run_point` is idempotent behind an async mutex. `LaneState` keys per-job tables by `job_id()` and remembers at most 8 jobs (oldest evicted) because no engine hook ends a lane's job; a `Lane::job_finished(job_id)` default-bodied method is a T1b follow-up.
- **C3 Reply window 500 ms as a lane constant, with a `Timing` struct** (`reply_window`, `liveness_retry` 500 ms, `replay_spacing` 1 s, `max_raw_bytes` 1472, `dry_run_cases` 50) overridable only through `PacketLane::with_timing` (tests and a later config hook), never through the profile.
- **C4 Interface resolution and loopback-only v2.** Candidates are the literal interfaces of covering `Inject` entries, then the platform loopback name when the target is loopback; the first that passes both `check(Inject, outbound)` and `check(Capture, inbound)` wins. A non-loopback target is `lane_unavailable:` ("the packet lane v2 sends on the loopback interface only"); real NICs need source MACs and a routable source address the lane cannot pin.
- **C5 Seeds.** Order: profile seeds (`hex`/`base64`/`{flow}` resolved against the seed store's outbound, non-injected packets to the target), then captured flows to the declared target (de-duplicated, at most 8), then the 16-byte default = the job marker padded with spaces. Cases cycle through the seeds (`i % n`); `seed_id` is `<ip>:<port>/<proto>#<n>`; the TCP seed is a SYN carrying the payload; source ports are `40000 + k` per target.
- **C6 `Discovery.nodes` stays empty**: no fake HTTP site nodes for L4 points; `url` is `<proto>://<ip>:<port>`.
- **C7 Counters exposure:** `PacketLane::counters(job_id) -> Option<L4Counters>` and `stats(job_id) -> Option<JobStats>` (adds `cases_unsendable`, `rate_waits`, `timeouts`, `consecutive_timeouts`, `cases_cap`, `stopped`) on the concrete type, for tests and a later engine hook that fills `JobStatus.l4`.
- **C8 Lane-private case store.** `send_recv` records every case as a `SendRecv` flow; sending 5000 cases through the operator's shared `L4FlowStore` (4096-flow ring) would evict real captures (an anti-goal). The lane sends through its own `InMemoryL4FlowStore::with_limits(1024, 16)` and reads the shared store only for seeds. Case bytes live in `L4Evidence.sent_hex`.
- **C9 Unsendable cases.** `send_recv`'s C3 check refuses a stimulus whose destination cannot be decoded (bad `ihl`, bad `total_length`) and one whose decoded port differs from `dst_port`. The lane pre-checks decodability (`PacketSpec::summarize`) and logs such cases as rendered-but-unsendable (not charged, not sent, counted in `cases_unsendable`), and passes `dst_port: None` for mutations of transport-hiding fields (`ipv4.{ihl,total_length,flags,fragment_offset,protocol}`, `ipv6.{payload_length,next_header}`, `udp.length`, `tcp.data_offset`) so the kernel still sees them; C3 itself is a security control in a file T5 does not own and stays as it is.
- **C10 Case accounting.** `L4Counters.cases` counts every mutated-case send including the `reproduce_count` replays; the baseline and liveness probes are charged to the job budget but are not cases; `liveness_before` is the most recent liveness (or baseline) verdict before the case. A scheduled liveness probe runs after every `liveness_every` sent cases.
- **C11 Privilege probe at discover time.** `discover` opens and immediately closes one capture handle per interface under a `Capture` permit; `L4Error::Unavailable` becomes `lane_unavailable:` so a privilege-less host is refused before any case (D3's "the platform cannot run it").
- **C12 The reaction check returns `Vulnerable` with severity `Info`** (per the orchestrator's fact 7) so ICMP/RST reactions are observable via `scan.issues`. AC T5-2a's words "recorded as `info` reactions, no issue" are read as "no `l4-crash` issue"; the orchestrator should align the AC wording (or T10's cell) with this.
- **C13 `ProbeResponse.l4` is `None` for a clean reply.** `L4Oracle` has no "clean" variant and `L4Reply.oracle` is not optional (T1a model), so `baseline()`/`probe()` return `l4: Some(L4Reply)` only for a classified reaction. A `L4Oracle::Clean` variant is a model follow-up for T1b (the model's next writer).
- **C14 `icmp.rs` scope.** IPv4 ICMP only (`type_u8`/`code_u8`), `tcp_rst`, and `transport_payload` (src/dst, ports, proto, payload slice) so `etherparse` never enters the lane crate and hostile captured bytes are parsed by one library.
- **C15 Latency outlier** needs at least 10 clean samples and `> 5 x median` of the last 20; it is recorded on the case and reported in the reaction detail, never a verdict trigger on its own.
- **C16 Check metadata details:** both checks `cost: Heavy`, `needs_baseline: true`, `intensity: Intrusive`; crash `cwe: Some(20)`; reaction `cwe: None`.
- **C17 An empty `target.l4` discovers nothing** (`Ok(Discovery::default())`) rather than erroring; a profile that lists `l4_packet` with no L4 target is a scheduling no-op.
- **C18 Lane dependencies** add `aitm-poc` (for `Severity`, not re-exported by the model) and `aitm-core` (for `aitm_core::Flow` in `held_flows`) to the fact-6 list; both are internal path crates already in `[workspace.dependencies]`.
- **C19 `testing` module always compiled**, `#[doc(hidden)]`, so `tests/live_loopback.rs` can reuse the guard, job and profile helpers without a cargo feature or a self dev-dependency.
- **C20 RNG:** splitmix64 for the stream, FNV-1a 64 over `marker || 0 || point_id` plus one mix for `rng_seed`.
- **C21 Raw growth cap 1472 bytes** (`long_run` sizes 256/1024/1472), under the guard's default `max_packet_bytes`; a `PacketTooLarge` from a smaller configured ceiling surfaces as a guard refusal that stops the job.
- **C22 Hex and base64 decoders hand-rolled** in `codec.rs` (no `hex`/`base64` crate in the workspace table).
- **C23 Fragment cases are one mutation setting two fields** (`fragment_offset` and the MF bit of `flags`), labelled `ipv4.fragment_offset=8,ipv4.flags=1`; never a fragment series.
- **C24 Verdict detail carries the `L4Location` facts** (ip, port, proto, field path, mutation) because the lane cannot build the `Issue`; the engine (T1b) may parse them or add a lane hook later.
- **C25 Self-port exclusion respected.** `send_recv`'s reply capture drops loopback frames touching the core's own listener ports (`L4Guard::admit_frame`), so the lane refuses a target whose port is in `guard.self_ports()` (`invalid_profile: ... own listener ports`) and picks its source port from `40000 + k` upwards skipping self ports.
- **C26 Deterministic length pass before RNG raw cases** (coordinator amendment): `grow:<len>` (zero fill, then `grow:<len>:repeat` seed repetition) to `{seed+1, seed+2, seed*2, 16, 64, 256, 1024, 1472}` bounded by `max_raw_bytes`, then `truncate:<len>` to `{seed-1, 1, 0}`, before any `raw:<mutator>@<offset>` case. The positive crash proof uses the operator seed `seeds: [{ hex: "deadbeef0000" }]` with `fields: ["raw"]` against T10's `l4-udp-payload-crash` (trigger `DE AD BE EF` + length >= 8), reached at `grow:8`: a fuzzer pushing a length boundary of a known message, not a rigged case (a 4-byte magic is not reachable from the benign `abc` seed by random bytes).
- **C27 Recovery-aware reproduction** (coordinator amendment): before each replay the runner polls liveness every `recovery_poll` (1 s, charged) up to `recovery_polls` (10) times, i.e. `RECOVERY_WAIT = 10 s`, bounded by the deadline, so every replay has `liveness_before: true`; `reproduced = (k, n)` over the replays attempted; a target that never recovers stops the replays and is still `Vulnerable` with `reproduced` as achieved, `liveness_after: false` and a detail saying "target did not recover within 10s"; a recovered target that fails to reproduce every replay is not a crash. One real crash costs about `reproduce_count x (5 s + 2 s)`.
- **C28 Mock crash-service mode**: `MockBackend::dies_on_pattern(prefix, min_len, silent_frames, repeat)` mirrors T10's service (silent for the trigger and the next N frames, then recovers) so the recovery wait is unit-tested without a socket; `dies_after_injects(n)` keeps modelling a permanent outage.
