## Shared facts for every coder and tester (read before any task)

Treat these as given; they were established by the orchestrator on 2026-11-01.

1. **The Linux rig** is the Lima VM `cis-lab` (Ubuntu 24.04 aarch64, cargo 1.99, passwordless sudo, `tcpdump`). A rebuild drops the caps: re-run `setcap` after every build, and never pass `--build` to the e2e runner (it would rebuild and strip them). `/tmp/claude/t5-linux-run.sh` (copied to the VM as `~/t5-linux-run.sh`) does setcap, a concurrent `tcpdump -i lo -w`, `python3 tests/e2e/run.py scan` and the excerpts.
2. **The self-echo bug** (Task 1): on loopback the capture inside `send_recv` receives the injected stimulus (libpcap on Linux `lo` delivers the RX copy; macOS `lo0` BPF sees sent frames) and `Correlation::classify` under `FiveTuple` classifies it as `Other` (same host, same protocol, wrong port), so every case ends before the real reply. `tcpdump` on the first rig run showed 21 frames, all ours, no ICMP.
3. **Linux ICMP rate limiting** (Task 3): `net.ipv4.icmp_ratelimit = 1000` (ms, per destination, token bucket with a burst of about 6) and `net.ipv4.icmp_ratemask = 6168` (includes destination-unreachable). Of 20 rapid cases against a closed UDP port about one per second draws ICMP; the rest are `Silence`; the liveness probe (the unmutated seed) is rate-limited the same way. Spec D8.4: kernel reactions prove classification, not crashes; a closed port can never be an `l4-crash`.
4. **Evidence rule:** no fixtures, no synthetic captures, no mock run counts as proof. Evidence is the `run.py` ledger, the cells' own output, `tcpdump` excerpts from the rig and the lane's counters, each quoted from a file under `/tmp/claude/t5-proof/` (Mac) or `~/t5-proof/` (VM) with its path.
5. **Secrets in loopback captures.** A loopback capture that includes TCP payload records the bus's plaintext `{"token": ...}` line (lesson of PR #205). Every `tcpdump` this plan runs uses the filter `'icmp or udp or (tcp[tcpflags] & (tcp-syn|tcp-rst) != 0)'` (no TCP payload frames), the pcap files never leave the VM except as the quoted text excerpts, and no pcap is ever attached to a PR or a doc. (Architect's call C4; `/tmp/claude/t5-linux-run.sh` currently captures `'udp or tcp or icmp'` and is narrowed by Task 4b before its next run.)
6. **Matt's Mac:** nothing is installed, no `/dev/bpf*` permission is changed, no `sudo` line is typed or proposed by anyone, no ChmodBPF. The only macOS privilege path is the product's `aitm-l4-helper bpf-permissions` through the app's SMAppService registration, after Matt's explicit yes relayed by the coordinator (silence is not go). Until that unit exists, the macOS cells SKIP 77 with the exact reason `packet-capture permission not granted (aitm-l4-helper phase 1 pending)`.
7. **Gate and merge rules.** Rust changes (Tasks 1, 3, 4a) mean the full Terminal gate `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` before any panel, judged by exit status from a log, not a grep. ### Task 1: `send_recv` ignores its own stimulus on loopback (dispatched)

- **Satisfies:** the precondition of T5-1 and T5-2a/b on every loopback host (without it no live case ever sees a reply); spec D8.4 transport. Needs a spec amendment row (a fourth `sendrecv.rs` fix beyond the three D12's T5 row names; Q4).
- **Depends on:** none.
- **Files:** `crates/aitm-proto-l4/src/sendrecv.rs` (modify: `Correlation`, `Classified`, `decode_reply`/`ReplyInfo`, the test module's `MockBackend`), `crates/aitm-scan-l4-packet/src/testing.rs` (modify: `MockBackend` self-echo default), `crates/aitm-scan-l4-packet/tests/live_loopback.rs` (modify: case-class assertions).
- **Change:**
  1. `ReplyInfo` gains `dst: IpAddr` and `dst_port: Option<u16>`. `Correlation` gains `fn is_own_stimulus(&self, frame: &[u8], info: &ReplyInfo) -> bool`, true when either (a) the frame's network-layer slice (what `crate::craft::parse_frame` yields after the link header: the 4-byte BSD AF word on macOS `lo0`, the 14-byte Ethernet header on Linux `lo`) is byte-equal to the stimulus, or (b) the frame is **same-direction**: `info.dst == self.dst && info.proto == self.proto && info.dst_port == self.dst_port` (a reply from the target never has our destination tuple: an echo comes back to our source port, an ICMP error is another protocol, a RST comes from the target port). `classify` asks `is_own_stimulus` **first, in every `ReplyMatch` mode**, and answers `Classified::Ignore` for it; the `Any` arm's whole-frame byte comparison (which never matched a real captured frame because of the link header) is replaced by the same predicate. Known limit, documented in the `is_own_stimulus` doc comment: a case whose mutated source port equals `dst_port` makes its echo indistinguishable from itself and reads as silence; the liveness probe uses the unmutated seed, so no crash follows.
  2. The `sendrecv.rs` test-module `MockBackend` gains a way to deliver the injected stimulus as the first captured frame, before the scripted replies (name it `MockBackend::with_self_echo_then(replies: Vec<Vec<u8>>)`; because `send_recv` opens the capture before it injects, the mock's source reads the injected list at poll time).
  3. `crates/aitm-scan-l4-packet/src/testing.rs`: `MockBackend` delivers the injected bytes as a captured frame **before** the scripted reply **by default** (`self_echo: bool`, default `true`, with `pub fn without_self_echo(&self)` for a test that counts captured frames). Every lane test therefore drives the real `send_recv` over a self-echoing wire, which is the loopback reality.
  4. `tests/live_loopback.rs`: each live test prints and asserts the case-class histogram of its point run (through the `PointRun` the runner records; if no public accessor exposes it, add `PacketLane::case_classes(&self, job_id: &str) -> Option<Vec<CaseClass>>` in `lane.rs`): closed TCP: `reset` on all 20 cases; echo: `clean` on all 100; closed UDP: at least one `icmp(3,3)` and zero `clean` (Task 3 tightens this to all 20 under the pace).
- **Test:** in `sendrecv.rs`: `send_recv_ignores_the_echoed_stimulus_under_five_tuple` (`with_self_echo_then(vec![udp_reply("127.0.0.1", 9, b"echo")])` → `SendRecvOutcome::Response`, the flow holds 2 packets, `packets[1].bytes` contains `echo`); `send_recv_ignores_the_echoed_stimulus_under_from_host` and `..._under_any` (same, `ReplyMatch::FromHost(127.0.0.1)` / `ReplyMatch::Any` → `Response`); `send_recv_echoed_stimulus_alone_is_silence` (self-echo and no reply → `NoResponse { waited >= timeout }` in all three modes, flow holds exactly 1 packet, the injected one); `send_recv_same_direction_frame_is_ignored` (a frame from our source port to `dst:dst_port` whose payload differs from the stimulus → still `Ignore`, outcome `NoResponse`). In `testing.rs`: `mock_delivers_the_stimulus_echo_before_the_reply` (first captured frame `==` the injected bytes, second is the reply) and the existing `echo_mock_reverses_the_tuple` adjusted to skip the echo frame. Whole-crate proof: `cargo test -p aitm-scan-l4-packet --offline` prints `test result: ok.` with at least 209 passed (207 + the two new) and 0 failed; `cargo test -p aitm-proto-l4 --offline` prints `test result: ok.` with 0 failed; `cargo test -p aitm-scan-l4-packet --test live_loopback --offline` prints `3 ignored` and the four Tester pins pass.
- **Done when:** both crates' tests pass with the self-echo default on, the gate passes, and the coder's report quotes the failing run (before) and the passing run (after) of `send_recv_ignores_the_echoed_stimulus_under_five_tuple`.
