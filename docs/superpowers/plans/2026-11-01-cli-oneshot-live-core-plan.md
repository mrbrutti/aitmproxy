## Overview

Thirteen tasks. Three new homes hold almost all the code: `crates/aitm-mcp/src/pointer.rs` (the pointer file and the process context), `crates/aitm/src/operator_bus.rs` (the default loopback operator bus) and `crates/aitm/src/oneshot/` (flags, verb table, core resolution, the remote path, the refusal panels, the entry point). Small additive edits land in `aitm-mcp`'s transport and server (an operator-only listener, `serve_on`, the pointer write), `aitm-core`'s config (the `operator_bus` default), `config_file.rs`, `operator_token.rs` (minting; `0600` atomic write) and `startup/card.rs` (the `Operator bus` row). `crates/aitm/src/main.rs` is touched once, last, with five listed hooks; `tui.rs`, `wire.rs`, `startup/{mod,args,errors}.rs` and `aitm-term` are never touched. The proof script and the docs close the wave; the live proof runs from the Terminal panel.

**The one rule every task repeats (parallel coders share ONE worktree and ONE git index; memories `aitmproxy-parallel-coders-shared-worktree`, `parallel-coders-shared-git-index`):** touch only the files your task lists; format with `rustfmt --edition 2021 <your leaf files>` only (never `cargo fmt`, never `rustfmt` on a crate root — `lib.rs`, `main.rs` — which reformats the whole crate; verify those with `cargo fmt -p <crate> -- --check`); never `git add`, `git add -A` or `git commit`; the orchestrator commits each wave with explicit pathspecs.

### Rules every task obeys

1. **Test first.** Write the failing test the task names, run it, quote the red output; write the minimum code; run it green; quote that too.
2. **Sandbox versus Terminal.** The Bash sandbox cannot bind or connect a socket, create a pty or reach the network. Every test a Coder runs in the sandbox is pure or in-process: temp directories under `std::env::temp_dir()`, injected closures for the environment, pid liveness and metadata, and `aitm_bus_client::InProcessTransport` over `McpServer::handle_on` for the protocol. Anything that binds (`LoopbackTcp::bind*`, `operator_bus::start`, the real binary) is a **Terminal-run** test: the Coder writes it, runs `cargo test -p <crate> --offline --test <name> -- --list` to prove it compiles, and the orchestrator runs it from the Terminal panel before the panel review.
3. **Literal assertions.** Every test asserts an exact string, byte sequence, number or value and would fail if the function body were deleted.
4. **Per-package offline gate** in the sandbox after each task: `cargo clippy -p <crate> --all-targets --offline -- -D warnings && cargo test -p <crate> --offline [--lib | --test <name>]`, plus `cargo fmt -p <crate> -- --check`. The FULL gate (`cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`) runs once, in the Terminal, before the panel.
5. **Zero new crates, zero new edges.** No `Cargo.toml` changes anywhere.
6. **No token anywhere**: not in a test literal that looks real (use `optoken-test-…`), not in a log line, not in a `Debug` impl, not in the pointer file, not in a PR body.
7. **`unsafe_code = "forbid"`** holds (workspace lint), so there is no FFI anywhere: pointer liveness is the advisory lock (`std::fs::File::try_lock` held by the writer, `try_lock_shared` probed by the reader; stable `std` since Rust 1.89, the toolchain is 1.97.1), and the owner uid is `std::os::unix::fs::MetadataExt::uid()` of the user's own `run/cores` directory (created `0700` by this user), compared with each pointer's and config's `uid()`. A one-shot spawns no process (W1 amendment A): no `ps`, no `kill -0`.
8. **Stop on gaps.** A Coder that finds the spec or this plan wrong, or needs a file its task does not list, stops and reports with the exact sentence that is wrong.
9. Shared `target/` across worktrees serves stale artifacts: `touch` the files you changed before a gate whose result looks impossible (memory `cargo-shared-target-stale-across-worktrees`).

### Plan-level calls (Architect; how the spec is read where it left wording open — veto any)

- **C1** `oneshot/mod.rs` is written once by T4 (module declarations and the module doc only) and never edited again; consumers use paths (`aitm::oneshot::run::run`, `aitm::oneshot::args::split_bus_args`). Same for the `lib.rs` lines.
- **C2** `PointerContext` carries **both** `config: PathBuf` and `run_dir: PathBuf`; the transport never reads the environment. `main.rs` computes `run_dir(&|k| std::env::var(k).ok())` once. A test that binds a listener without publishing proves no file is written without any env juggling.
- **C3** Liveness without `unsafe` or a spawn: the writer locks the temp file exclusively before the rename and keeps the handle in `LoopbackTcp` for its lifetime; the reader's seam is `&dyn Fn(&Path) -> Liveness` with `enum Liveness { Alive, Dead, Unknown }` (`try_lock_shared` → `Err(WouldBlock)` = `Alive`; `Ok` = `Dead`, unlock and delete; any other error = `Unknown`, treated as alive: dial, and R4 on refusal).
- **C4** `mint_if_absent` returns `Minted` (not a `Result`): every failure is `Skipped { reason }` and never ends a boot. The reason strings are the spec's §D3 words: `the mcp: section is written inline`, `cannot write <path>: <io error>`, `<path> is not a regular file`.
- **C5** The operator-bus task is a `tokio::task::JoinHandle` inside `OperatorBus`; `Drop` calls `abort()`. The listener is bound in `start` (awaited) so a fixed-port conflict surfaces as `StartupError::PortInUse { role: "the operator bus".into(), addr, remedy }` before the ready card.
- **C6** The server for a dedicated operator bus is built with `tui::server(cfg, McpTransport::Stdio, services)` (the transport field is a label there, exactly as `tui::build_servers` labels the TUI's in-process server) and served through `McpServer::serve_on`.
- **C7** `oneshot::run::run` returns `Result<Vec<u8>, OneShotError>` where `enum OneShotError { Report(ErrorReport), Other(anyhow::Error) }`; `main.rs` writes the bytes to stdout or calls `exit_with`. The module never calls `std::process::exit` itself, so it is testable.
- **C8** The confirm prompt from the core is sanitized with `aitm_term::text::sanitize` before it reaches the `Confirmer`; everything else from the core reaches the terminal only through `ErrorReport`, which the renderer sanitizes.
- **C9** `remote::prepare` re-implements `Cli::resolve`'s ten lines (path tokens → dotted name, `registry.command`, `--yes` removal) rather than widening `aitm-cli`'s API beyond the one `pub fn parse_flags` line, so wave 2's rewrite of `dispatch.rs` error strings merges cleanly. The usage error texts (`unknown command \`x\`; run with no arguments to list commands`, `expected a command before flags, got \`--x\``) are copied verbatim so W1's `USAGE_PREFIXES` still classify them.
- **C10** The generic flag parser for verbs the local registry lacks: `--k v` → `v` as JSON if `serde_json::from_str` succeeds else a JSON string; `--k=v` the same; a bare `--k` (next token starts with `--` or is absent) → `true`; a repeated key is an error `flag --k given more than once`; the core validates names and types.
- **C11** `absolutize_paths`: for a live verb, an argument named `poc_path` or `path` whose value is a non-empty string not starting with `/` is joined to `std::env::current_dir()`; nothing else is rewritten.
- **C12** `read_operator_token` warns (never refuses) when `mode & 0o077 != 0`; it refuses (`TokenProblem::Foreign`) when the file's `uid()` differs from the run dir's `uid()` (rule 7), and (`NotRegular`) when `metadata().is_file()` is false after following symlinks.
- **C13** The proof script's config files are written by the script with `umask 077`; the minted token is read with `sed -n 's/^  operator_token: //p' "$CFG"` into a shell variable that is only ever used as a `grep -c -F` needle (count must be 0) or written to a `0600` token file for the `--bus --token-file` case; it is never echoed, never passed on a command line in clear (the token file is).
- **C14** Two cores for AC-R14-19: two default-style configs in two `HOME`s? No — the pointer dir is per `HOME`, so both cores must share one `HOME`. The recipe starts core A with the default config and core B with `--config "$CFG_B"` where `$CFG_B` sets `listen: 127.0.0.1:<free>` and `browser.proxy_addr` to a second free port and nothing else; both mint their own token into their own file; neither config path matches the one-shot's effective default path when the one-shot is run with `--config "$CFG_C"` (a third file with only `listen:`), so the preference tie-break yields two candidates → R11. Then `--bus <A's addr> --token-file <A's token file>` succeeds.
- **C15** `term-reporting.sh`: only the verb words change (`scope list` → `ca status` at the §5 and §13 call sites); the §13 timing note's label becomes `aitm ca status median real of 11 runs`; §10's two token greps gain a third needle, the minted token read per C13 from the section's config after the run.
- **C16** The `Operator bus` row is omitted on the `Shared` plan; `bus_row_value` appends ` · operator` to the Bus row instead (`ready · operator` on the Web card). Role: plain for an address, `Role::Warning` for `off · …`.
- **C17** `started_unix` ages: `< 60 s` → `just now`; `< 60 min` → `<n> min ago`; `< 48 h` → `<n> h ago`; else `<n> d ago`. Budgets: `2 s`, `30 s`, `10 min`.
