## Intent

Every scanner v2 track is accepted only by a real scan against a real seeded target observed independently (parent Verification). Today `aitm-testtarget` plants six HTTP vulns over plain HTTP/1 with no request log, no TLS, no WebSocket, no session and two trivial L4 services. T10 turns it into the proving ground: one binary that serves every class T2..T6 need in Vulnerable (V) and Patched (P) modes over plain, TLS-h2 and TLS-h1 listeners, a `/ws` endpoint, nine L4 speakers with a bounded crash window, and a **control origin** on its own port that exposes the target's own logs; plus the Python harness (`scan.py`, the `scanner:` config emitter, the per-verb ledger) and one e2e cell per parent AC.

## Goals

- One `aitm-testtarget-serve` process, flag-selected, serves plain h1, TLS (ALPN `h2, http/1.1`), TLS-h1-only, `/ws`, the control origin and all L4 services; the library builder does the same in-process.
- Every seed in the table below behaves exactly as stated in V and P; the grader-only manifest lists each; nothing served reads the manifest.
- The control origin answers every question a cell asks: which requests arrived (redacted), on which connection, with which ALPN, which WS handshakes/frames, which L4 messages, and when a speaker was down.
- `tests/e2e/scan/` holds one cell per parent AC (T1..T6, T10), each own-core, each SKIP 77 with a loud reason until its lane is live, and `run.py` prints the per-verb ledger.

## Non-goals

- Any scanner, lane or verb code (T1..T6 own those); any UI cell (T7..T9 own `test_t7/8/9_*`).
- Realistic SQL/LDAP/template engines: each seed is a hand-rolled recogniser of the exact payload family named in its row, nothing more.
- A seeded h2-specific positive (parent D8.2 non-goal), MQTT 5, DNS over TCP, FTP data channel, SMTP `DATA` bodies.
- Changing the root `Cargo.toml`, any other crate, or the integration-shared contract lists (T10 adds no verb).

## Anti-goals

- A seed that is dangerous for real: no file read, no shell, no socket opened by a seed; every "command", "file" and "entity" resolves in-process to a virtual constant.
- A control origin reachable from the target origin or linked from `/` (a crawler must never discover it); a raw `Cookie` or `Authorization` value stored in any log.
- A cell that passes on fixture data, on the proxy's own view only, or by hard-coding a verb count.
- A crash window that stays down (a speaker that does not recover in 5 s) or a trigger in P mode that takes the service down.

## Constraints

- **Rust gate** as parent; `#![forbid(unsafe_code)]` already in force via `[lints] workspace = true`; no `unwrap`/`expect` on anything read from a socket. `cargo test -p aitm-testtarget --lib --offline` is hermetic (sandbox); `crates/aitm-testtarget/tests/*.rs` bind ports (Terminal only).
- **Dependencies (T10 call, plus one Architect's call):** only `crates/aitm-testtarget/Cargo.toml` changes. Added: `hyper` feature `http2`; `rustls 0.23` and `tokio-rustls 0.26` with the same features as `crates/aitm-proto-http/Cargo.toml` (`ring, std, tls12, logging` / `ring, tls12, logging`, default-features off); `rcgen 0.14`; `serde_json 1`; `sha1 0.10`; `base64 0.22`; **`sha2 0.10` (Architect's call: the log fields the brief names are SHA-256; `sha2 0.10.9` is in `Cargo.lock`)**. Not added: `tokio-tungstenite` (a hand-rolled RFC 6455 server codec of ~120 lines is smaller and the harness already carries the mirror client in `ws.py`), `tokio-util`, hyper-util `server` features (ALPN is dispatched by hand to `hyper::server::conn::{http1,http2}`). Enabling hyper `http2` adds the edges `h2`, `futures-channel` to hyper's `Cargo.lock` entry; both packages are already locked, so `cargo metadata --offline` passes.
- **Back-compat:** `aitm-testtarget-serve --mode M --port P` prints `listening http://127.0.0.1:P` as its **first** stdout line (`target.py`, `tests/serve_bin.rs`); `TestTarget::start`/`start_on`, `L4Service`/`L4Config`, `manifest()`, `l4_manifest()`, `grade()` keep their signatures; the index `/` is byte-identical in V and P (`index_links_all_seeded_endpoints`).
- **Harness:** pure stdlib Python 3.11+, own-core model, dedicated free ports, tokens never printed; `tests/e2e/aitm_e2e/{bus,core,target,ws,tls,upstream,proxyutil}.py` are not edited.
- **Cross-track pins** (this spec is the source; the T3/T4/T6 child specs must match): issue `class` tokens are T3's list (`sqli, cmdi, ssti, path-traversal, xxe, crlf, nosqli, ldapi, open-redirect, reflected-xss, ssrf, ws-cswsh, ws-injection`; the manifest `class` column below uses them for every new row); the L4 `grammar` names are the speaker table's `grammar` column; T3's `HttpSender` must accept the target's self-signed certificate under `ssl_insecure: true`.

## Design

### D1. Process shape (T10 call)

| Item | Pinned |
|---|---|
| Flags | `--mode vulnerable\|patched` (default vulnerable), `--port N` (plain h1; default 0), `--tls-port N` (TLS, ALPN `[h2, http/1.1]`; **present = enabled**, 0 = ephemeral), `--tls-h1-port N` (TLS, ALPN `[http/1.1]` only), `--control-port N`, `--l4` (all L4 services on ephemeral loopback ports; **requires `--control-port`**, else exit 1 with `--l4 needs --control-port`). Absent flag = listener not started. (Architect's call: presence enables, so the legacy invocation starts nothing new.); `--latency-ms N` (default 0, at most 60000): a sleep of N ms applied once to every HTTP response (routed or 404, V and P alike, incl. the `/ws` 101) and once to every WebSocket server frame (data, pong, echoed and server-initiated close alike), never to the L4 speakers and never to the control origin (D2: `TargetLogs` polling must not be slowed), so an intrusive scan of this target takes long enough for a UI to be observed running (T7 ruling 2026-11-01: ~278 probes finish in ~2 s undelayed; with 40 ms the scan takes >= 10 s) |
| Stdout | Exactly, in order, one per started listener, then `ready`: `listening http://127.0.0.1:P`, `tls https://127.0.0.1:P`, `tls_h1 https://127.0.0.1:P`, `control http://127.0.0.1:P`, `ready`. L4 addresses are **not** printed; cells read `GET /services`. |
| Bind | Every listener and service binds `127.0.0.1` only. |
| TLS | One self-signed `rcgen` certificate per process for `localhost` + `127.0.0.1`; rustls `ServerConfig` built with the `ring` provider via `builder_with_provider` (no global install); ALPN list per listener as above. | Library | `TestTarget::builder(mode) -> TargetBuilder` with `.port(u16)`, `.tls(u16)`, `.tls_h1(u16)`, `.control(u16)`, `.l4(bool)`, `.latency_ms(u64)` (default 0; the 60000 cap is the flag's, see Flags), `async fn start(self) -> std::io::Result<TestTarget>`; `TestTarget` gains `tls_url()`, `tls_h1_url()`, `control_url() -> Option<&str>`, `l4_services() -> &[RunningService]`, `mode()`. `start(mode)` = `builder(mode).start().await.expect(..)`; `start_on(mode, port)` = `builder(mode).port(port).start()`. |

### D2. Control origin API (T10 call; shapes are Architect's calls)

Own loopback port, hyper h1, JSON only, never linked from `/`, never in the HTTP scope. Every log is a ring of **50 000** entries; a full ring drops the oldest and counts `dropped`. Every entry carries `seq` (one global `AtomicU64`, monotonic across all logs), `ts_ms` (epoch ms) and `conn_id` (`c-<8 hex>` per accepted TCP connection; a UDP datagram's `conn_id` is `u-<peer port>`).

| Route | Response |
|---|---|
| `GET /services` | `{"mode":"vulnerable","services":[{"name":"http","proto":"tcp","addr":"127.0.0.1:P","role":"http","alpn":["http/1.1"]},{"name":"tls",...,"alpn":["h2","http/1.1"]},{"name":"tls_h1",...,"alpn":["http/1.1"]},{"name":"control","proto":"tcp","addr":"...","role":"control"},{"name":"l4-tlv-crash","proto":"tcp","addr":"127.0.0.1:P","role":"l4","grammar":"tlv"},...]}`; roles `http\|control\|l4`; `--l4` also lists the legacy `l4-udp-echo`/`l4-tcp-service` with `"grammar":null`. |
| `GET /log/http` | `{"entries":[E...],"dropped":0}`. `E` is `{"kind":"request","seq","ts_ms","conn_id","listener":"plain\|tls\|tls_h1","version":"h1\|h2","conn_req_index":1,"method","path","query","headers":{...},"cookie_names":["session"],"cookie_sha256":"<16 hex>\|null","auth_sha256":"<16 hex>\|null","body_len":0,"body_sha256":"<64 hex>","status":200}` or `{"kind":"tls_handshake","seq","ts_ms","conn_id","listener","alpn":"h2\|http/1.1\|none"}`. `headers` keeps verbatim only `host, origin, referer, user-agent, content-type, content-length, accept, connection, upgrade, sec-websocket-key, sec-websocket-version, sec-websocket-protocol` and any `x-*`; `cookie`/`authorization` are never stored raw (`cookie_names` sorted, one name per `name=value` pair; the two hashes are the first 16 hex of SHA-256 over the raw header value); the `x-*` credential names `x-api-key`, `x-auth-token`, `x-csrf-token`, `x-amz-security-token` are stored as the literal `"<redacted>"` (fix round 1, item 11). `conn_req_index` is the per-connection 1-based counter (AC T3-3). |
| `GET /log/ws` | `{"entries":[...],"dropped":0}` with `{"kind":"handshake","seq","ts_ms","conn_id","listener","path","origin":"...\|null","sec_websocket_key","cookie_names":[...],"session_valid":bool,"accepted":bool,"status":101\|403}` and `{"kind":"frame","seq","ts_ms","conn_id","dir":"in\|out","opcode":"text\|binary\|ping\|pong\|close","len","sha256":"<64 hex>"}`. |
| `GET /log/l4[?service=NAME]` | `{"services":{"l4-tlv-crash":{"accepts":[{"seq","ts_ms","conn_id","peer"}],"messages":[{"seq","ts_ms","conn_id","dir":"in\|out","len","sha256","verb":"PING\|fc3\|CONNECT\|…\|null","classified":"ok\|protocol_error\|denylisted\|trigger"}],"closes":[{"seq","ts_ms","conn_id","reason":"eof\|quit\|trigger\|oversize\|error","bytes_in","bytes_out"}],"downtime":[{"seq","service","conn_id","down_at_ms","up_at_ms","trigger_sha256"}]},...},"dropped":0}`. UDP services log a `messages` entry per datagram and no `accepts`. A TCP service that cannot rebind its port after the crash window writes one open-ended `downtime` row (`conn_id: "-"`, `up_at_ms: 18446744073709551615`, `trigger_sha256` of the empty input) and one stderr line, so a dead speaker is observable (fix round 1, item 6). On `Trigger`/`Fault` the `in` message hash and `trigger_sha256` cover the whole pending buffer, so a cell can match them against what it sent (item 21). `verb` is the parsed command name, Modbus `fc<n>`, MQTT packet type name, DNS `A`/`qtype<n>`, TLV `frame`, or `null` when unparsed (T6: the denylist proof reads `verb` and `classified`). |
| `GET /log/conns` | `{"entries":[{"conn_id","listener","alpn":"h2\|http/1.1\|null","peer","opened_ms","closed_ms":null\|n,"requests":n}]}` for the HTTP listeners (the T3-3 "<= 1 connection per check, <= 8 streams" observer). |
| `POST /reset` | Clears every log and `dropped`; sessions, comments and the flaky counter are kept. `{"reset":true,"seq":<last seq issued before the reset>}`. Any control request carrying an `Origin` header is answered 403 `{"error":"cross-origin"}` before routing (browser CSRF guard; the harness never sends one; item 10). |
| `GET /mode` | `{"mode":"vulnerable\|patched"}`. |
| anything else | 404 `{"error":"not found"}`; `GET /manifest*` and `GET /<seed id>` are 404 on both origins. |

Bounds (fix round 1): the comment store keeps the newest 1 000 comments, the session store the newest 10 000 sessions (oldest evicted), a multipart boundary longer than 70 bytes is 400, a request body that fails mid-read is 400 `request body could not be read` (logged 400), the open-redirect `Location` strips CR/LF instead of panicking, and the serve binary never panics when its stdout reader goes away.

### D4. `/ws` (T10 call)

| Item | Pinned |
|---|---|
| Handshake | On every HTTP listener (h1 only). Checked in this order: V: any `Origin` accepted; P: `Origin` absent **or equal to `<scheme>://<Host header>`**, else 403 `<p>forbidden origin</p>`. Then the login cookie: `session_valid` = the `session` cookie names a live session; V upgrades either way; P answers 401 `<p>login required</p>` when not `session_valid` (T4: CSWSH and auth-bypass get a positive and a negative). `Sec-WebSocket-Protocol`: V echoes the first requested token back verbatim (accepts any subprotocol); P sends no such header. Both modes log a `handshake` entry. |
| First frame | `{"type":"hello","user":"alice"}` when `session_valid`, else `{"type":"hello","user":"anonymous"}`. |
| Echo | Text `{"type":T,"msg":M}` with `T` in `echo` or `chat` (T4 sends `chat`) -> `{"type":T,"msg":M',"html":"<b>M'</b>"}` where `M'` is `M` raw in V and HTML-escaped in P (so P reflects nothing unencoded in any field; serde_json string escaping applies in both). Other JSON or non-JSON text -> `{"type":"error","error":"bad message"}`. Binary -> echoed as binary. |
| Control | Ping -> pong (same payload); close -> close echoed, connection ends. Payload length > 1 048 576 -> close `1009` without reading it. Continuation frames -> close `1003`. Unmasked client frame -> close `1002`. |
| Codec | Hand-rolled RFC 6455 server codec: `decode_frame(&[u8]) -> Option<(Frame, usize)>`, `encode_frame(opcode, &[u8]) -> Vec<u8>`, `accept_key(&str) -> String` (SHA-1 + base64), pure and unit-tested. |
| Log | Every frame in/out as a `frame` entry (opcode, len, sha256); the handshake entry also carries `subprotocol` (the echoed token or `null`); when the loop ends a `{"kind":"close","seq","ts_ms","conn_id","code":1000\|1009\|…\|null}` entry is written and `close_conn` runs, so `/log/conns` shows the upgraded connection's `opened_ms`/`closed_ms`; an upgraded connection is never stamped closed before its frame loop ends (the listener's own close after hyper hands the socket off is suppressed), so a row with `closed_ms: null` is a live WebSocket session (T4: "at most 4 concurrent dialer connections" is read from `/log/conns`). |

### D5. L4 speakers (T10 call; byte literals are Architect's calls)

All `127.0.0.1`, ephemeral ports, started together by `--l4`/`.l4(true)`, listed in `/services` and in `l4_manifest()`. One pure `Speaker` per service drives a shared TCP/UDP driver. **Crash window** = 5 s: on a V trigger the driver logs `downtime {down_at_ms, up_at_ms = +5000, trigger_sha256}`, closes the offending connection, **drops the TCP listener and rebinds the same port after the window** (connects are refused meanwhile) or, for UDP, **drops every datagram** for the window, then serves again. In P the same input gets the row's protocol-error reply, the connection closes and the listener stays up. In P **every close is preceded by a protocol-error reply** (PR C, 2026-11-01, after T6's live run): input that is malformed but not the row's trigger is answered with a specific protocol error and then closed in **both** modes (RESP `-ERR Protocol error: invalid multibulk length` for a garbled or negative `*N`, `-ERR Protocol error: expected '$', got '<c>'` for an array element not starting with `$` (`<c>` = the element's first byte when it is printable ASCII, empty otherwise; never a control, high-bit or lossily decoded byte), `-ERR Protocol error: invalid bulk length` for a garbled `$len`, `-ERR Protocol error: too big inline request` for an inline line past 1 MiB); a partial line at the 200 ms idle (a damaged terminator such as `\r\t`, `get mykey` with no CRLF, a `set` waiting for its data) is not a protocol event and the line speakers (`smtp`, `ftp`, `memcached`, RESP inline) wait for the rest (`Step::Wait`). The only silent closes are V-mode triggers, MQTT's byte-less faults (it has no error reply), an orderly `quit`/`QUIT`/`DISCONNECT`, and a peer EOF. Every message is logged with `classified`.

**Denylist observation (AC T6-3/T6-4):** these arrive, are answered and logged `denylisted` so a cell can assert none came: RESP `FLUSHALL FLUSHDB SHUTDOWN CONFIG DEBUG SAVE` -> `-ERR denylisted command\r\n`; memcached `flush_all` -> `CLIENT_ERROR denylisted\r\n`; Modbus fc 5/6/15/16/22/23 and 8 -> exception `<fc|0x80> 01`; MQTT PUBLISH with retain -> accepted silently; SMTP `RCPT TO` outside `@target.test` -> `550 relay denied\r\n`; FTP `DELE STOR APPE RMD RNFR RNTO MKD` -> `550 denied\r\n`. Line speakers cap a line at 1024 bytes (memcached 2048); TLV at 4096; MQTT at 65 536; RESP/memcached data at 1 MiB (memcached's driver buffer is `2048 + 2 + 1 MiB + 2` bytes, the largest completable `set`). A high-bit or NUL byte in a command's argument never breaks verb matching (`EHLO x\xff` -> `250 target.test`, `USER a\xff` -> `331 password required`, `get k\xff` -> `END`, `ECHO \xff` -> `$1\r\n\xff\r\n`); one in the verb is the row's generic unknown-command reply with the connection kept. A line is over-long when its CRLF lies past the cap **or** no CRLF has arrived within cap + 1 bytes, so a 4096-byte line that arrives complete with its CRLF in one read is the trigger too (T6). The pure trait:

`trait Speaker: Send { fn name(&self) -> &'static str; fn banner(&self) -> Option<Vec<u8>>; fn parse(&mut self, mode: SeedMode, buf: &[u8]) -> Parsed; fn on_idle(&mut self, mode: SeedMode, buf: &[u8]) -> Step; fn max_buffer(&self) -> usize; }` with `Parsed::{Incomplete, Message { consumed, step }}` and `Step::{Reply(Vec<u8>), ProtocolError(Vec<u8>), Denylisted(Vec<u8>), Fault(Vec<u8>), Trigger, Wait, Close(Option<Vec<u8>>)}` (`ProtocolError` = reply and keep the connection; `Fault` = the P-mode answer to a V trigger: reply, if non-empty, then close with reason `error`, listener stays up; `Trigger` = V crash; `Wait` = nothing to send, keep the connection, no log entry: the buffered bytes are a message still arriving, returned from `on_idle`; the driver re-arms the idle timer and still ends the connection on peer EOF, on the crash window, or when the target drops; a speaker never waits past its `max_buffer()`, and a driver that sees one closes `oversize`; because a waiting connection pins up to `max_buffer()` bytes until EOF, the TCP driver accepts at most `MAX_CONNS = 256` concurrent connections per service and lets later connects wait in the listen backlog, never refusing them, so the V "connect refused" oracle stays unambiguous); `CrashWindow` takes `Instant`s so the state machine is testable with a mocked clock. The legacy `L4Service` (UDP echo + TCP banner) is untouched.
