This is an **umbrella** spec: it fixes the shared model, the verb contract, the catalogue contract, the job/issue/session models, each lane at the level of components and seams, and a split into independently buildable tracks with disjoint file ownership. Each track gets its own plan (and, where its plan says so, its own child specs for the detail below this level).

## Intent

The scanner today is three verbs (`scan.discover`, `scan.passive`, `scan.report`) over a browser crawl, two native payload classes and three passive checks; inject, PoC and record run only in tests; the fifteen bundled `check.*` Rhai scripts are operator-invoked one parameter at a time; every long call blocks its bus connection; findings have no dedupe key and no confidence. Matt wants a Burp-Suite-Professional-class scanner for HTTP/1.1, HTTPS, HTTP/2 and WebSocket (crawl and audit, insertion points, profiles, severity x confidence issues, live progress) and an L4 **fuzzer** that looks for defects in protocols and packets themselves, all driven from the three operator UIs and the MCP agent alike, and proven against real seeded targets. Every seam this needs was surveyed in research note 20; the missing pieces are a job model, a push kind, a check catalogue with machine metadata, and the lanes.

## Operator decisions (fixed; recorded as Matt's)

1. Burp-Pro-like scanner for HTTP/1.1, HTTPS, HTTP/2, WebSocket: crawl + audit, insertion points, scan profiles, issue taxonomy with severity x confidence, live progress; plus an L4 **fuzzer** "searching for issues in the protocols or packets themselves".
2. L4 has **both** lanes: a **packet** lane (malformed IP/TCP/UDP/ICMP headers over `PacketSpec` + `l4.send_recv`) and a **stream** lane (new unprivileged TCP/UDP socket client; corpus = captured L4 flows; mutation + grammar generation).
3. Grammar fuzzers for **all** of DNS, MQTT, Modbus/TCP, Redis (RESP), Memcached, SMTP, FTP, and a generic TLV/length-prefixed model inferred from captured traffic. Delivery order is the Architect's call (D8.5 gives it with its rationale).
4. Authenticated scanning = reuse cookies/auth headers observed in in-scope proxied traffic. Recorded login sequences: later milestone.
5. Explicit scans plus the existing live passive detectors. Live **active** audit of proxied traffic: later.
6. The scanner schedules bundled **and** custom Rhai `check.*` scripts and native Rust checks automatically over discovered insertion points: one unified catalogue. Scripts stay human-readable.
7. All three operator UIs get a full Scan surface at parity (profile editor, live progress with cancel, site map / insertion points, issues grouped by severity with evidence + PoC); the MCP agent gets the same via verbs.
8. Proof is the real e2e suite (`tests/e2e`) against seeded targets, not fixtures.

## Goals

- `scan.start` returns a job id immediately; the job runs in the background on owned handles, reports live progress (push + poll), can be cancelled, holds egress confinement and one budget for its whole life, and never blocks a bus connection.
- One **check catalogue**: native Rust checks and Rhai `check.*` scripts (bundled or custom) declare the same metadata (class, insertion kinds, lanes, cost, intensity, technique, typical severity) and return the same structured verdict; the scheduler picks checks per insertion point from that metadata; time-based blind checks get host-measured timing without `sleep`.
- **Insertion points v2**: query, form, nested JSON (typed), XML value/attr, multipart, header, cookie, any path segment, filename, parameter name, entire body; the point owns encoding and `Content-Length`.
- **Issues** with severity x confidence, a dedupe key, evidence, probe flows, optional PoC/finding link, and an operator-settable status; passive issues consolidated per origin.
- **Session reuse** from observed in-scope traffic, with auth-lost detection; session material never appears in a result.
- **HTTP/2** sending (ALPN-negotiated, per-authority cached, overridable) so every HTTP check runs over h2 too, plus observe-only h2-specific checks.
- **WebSocket** active lane: own dialer, frame-field insertion points, CSWSH/auth/injection/oversize checks, and a guarded `ws.*` Rhai namespace.
- **L4 packet** and **L4 stream** fuzz lanes with grammars for the eight protocols, a liveness oracle, bounded reproduction, hard caps and a destructive-command denylist.
- Scan surfaces in TUI, web and macOS at parity, wired to the live core; the same verbs for the agent.
- Seeded `aitm-testtarget` routes and services for every new class and lane, with Vulnerable/Patched modes, and real e2e cells that prove found-on-vulnerable / not-found-on-patched over the real bus.

## Non-goals

- **Live active audit** of proxied traffic (Burp "live audit"): a scan is started explicitly. The shipped passive detectors stay as they are.
- **Recorded login sequences, login macros, self-registration**: session reuse is observation-based only (decision 4).
- **Out-of-band (Interactsh/Collaborator) detection**: no external service, no OOB sink; blind classes use boolean/timing differentials only.
- **Pause/resume of a job** (Architect's call: cancel is enough for v2; pause adds state the UIs must render and a half-held budget; a cancelled job keeps its issues).
- **Exploitation** of anything found: no data extraction past a marker, no second-request smuggling, no DoS confirmation, no crash weaponisation.
- **JavaScript static/dynamic analysis** (Burp's third audit phase) and the permessage-deflate compression oracle.
- **In-path L4 interception** as a fuzz transport (the NFQUEUE path stays as M5 shipped it).
- **Replacing** `scan.discover`/`scan.passive`/`scan.report` in v2: they keep their shipped shapes (see D3) so the shipped UIs keep working while the UI tracks migrate. `scan.discover` is deprecated in v2 (orchestrator's decision on former open question 3) and is removed in a later release once all three UIs run on `scan.map`; that removal is a follow-up outside this spec.
- A seeded **h2-specific positive** in the test target (D8.2 explains why; the h2 lane is proven by h1-class vulns found over h2 and by the observe-only checks' true-negative set).

## Anti-goals

- Any scanner-issued stimulus (HTTP request, WS frame, L4 packet, TCP/UDP datagram) reaching a host outside the operator's HTTP scope or L4 scope, from any caller, in any lane.
- A job that outlives its budget, deadline or cancellation; a verb whose latency is the scan's; a progress line that lies (counters that go backwards or a `done` without a terminal status).
- An agent starting an active or L4 job with the config gate off; a UI that launches an L4 fuzz without the "may disrupt the target" confirmation; a profile that can raise a hard cap.
- A flood-shaped primitive: anything that sends faster than the guard's pacing, more packets than `L4Permit` allows, or keeps hammering a spot that stopped answering.
- A result, issue, push line, PoC, log line or UI cell that carries a cookie, token or auth header the scanner saw.
- Probes evicting real captures from the flow store (issue-only recording is the default).
- A fixture-driven green: any acceptance claim for any track backed by sample data rather than a real scan (see Verification).

## Constraints

- **Rust gate**: `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` before any review; `#![forbid(unsafe_code)]` in every new crate. Default `cargo test` stays hermetic (no sockets, no browser); anything that binds a port runs in the Terminal panel.
- **Deny-by-default stays.** Active lanes are `Sensitive`, scope-gated, rate-paced, budgeted. Agent access to active lanes needs `scanner.allow_agent_active`; L4 lanes additionally need `l4.enabled`, an L4 scope entry with `Inject` capability covering the target (the stream lane authorises with `interface: "*"`, `direction: outbound`, so the operator adds such an entry; D9.5), for an agent **both** `scanner.allow_agent_l4_fuzz` and the existing `l4.allow_agent_inject` (D3 names the same pair), and for every caller the operator `_confirm` handshake whose prompt says the run may disrupt the target. `intensity: intrusive` is operator-only: an agent is capped at `medium` even with `scanner.allow_agent_active` (orchestrator's decision on former open question 2). The L4 destructive-command denylist is never liftable in v2, by any profile, config key or confirmation (orchestrator's decision on former open question 1). Hard caps are not profile-overridable. A crash is a finding to reproduce (bounded N) and record, never to exploit.
- **Core edits are allowed only when generic.** Each `aitm-core`/`aitm-mcp` change is listed in D9 with its justification; none names the scanner.
- **Contract lists are integration-shared.** `crates/aitm/tests/frontends.rs` `EXPECTED_TOOLS`, `crates/aitm-tui/src/lib.rs` `CORE_TOOLS` (the constant only), `crates/aitm-tui/fixtures/bus-fixture.json`, the check-name pins in `crates/aitm/tests/bundled_startup.rs` and the command pins in `crates/aitm-plugin-rhai/tests/bundled_scripts.rs` belong to **no track**. Each track's final integration task (the rebase commit right before its PR merges) re-pins them for the verbs and checks that track adds, in merge order; the orchestrator merges one PR at a time so any conflict is one line. `capture.status` and `proxy.system.*` verbs land before ours: every integration task re-pins against live `tools/list` (and any tool-count assertions) rather than assuming the counts in this spec. No track lists these files as exclusive, and no non-integration task edits them.
- **Sequencing pins.** (a) `claude/scanner-vocab-7d36bb` (redaction consolidation into `aitm_core::redact`, editing `discover.rs`, `reproduce.rs`, `redact.rs`) merges first (PR #199); T1 and T2 branch after it and use `aitm_core::redact::{is_secret_key, scrub_text_wide}` as the single vocabulary; `scrub_embedded` in `reproduce.rs` stays on `scrub_text_wide` (plain `scrub_text` leaks `sid`/`jwt`/`auth`-style pairs). (c) The macOS track requests file claims from the orchestrator before editing `apps/mac`: five sibling sessions hold `Shell/*`, `Session.swift`, `BusService`, Kit `ConnectionSummary`/`FlowSummary`; the Scan panels are unclaimed.
- **Supersessions.** The M5 L4 spec's non-goal "No automated fuzzing/crash-triage engine in the tool" and its sentence "There is no `l4.fuzz` verb and no in-tool crash-triage engine" are **superseded** by decisions 1 and 2. M5's safety argument ("a fuzzing run is many guarded calls, no uncapped path") is replaced by D8.4/D8.5: every stimulus still mints an `L4Permit` per packet (packet lane) or passes `L4Guard::check` per connection and a per-job bytes/packets pacer (stream lane); the engine adds non-overridable ceilings (cases, deadline, consecutive timeouts, element crash threshold, liveness cadence, destructive-command denylist) that a hand-driven loop never had. The active-backend spec (`scan.inject`/`scan.run`/`scan.status` as blocking verbs with a last-campaign snapshot) is **superseded**: its intent (bounded per-class injection, PoC reproduction and recording, one shared budget, confinement for the whole run) is folded into the job model; its verb names are not used except `scan.status`, which is redefined in D3. The scanner-plugin spec's "no edit to `aitm-core`" rule is relaxed per D9. The integration spec's Stage 1 stands; its "progress = poll a running flag" baseline is replaced by D3's push kind. The e2e framework spec (`2026-10-30-aitmproxy-e2e-real-test-framework-design.md`) is **amended**, not superseded: it gains the `tests/e2e/scan/` surface dir, the `aitm_e2e/scan.py` helper, the `scanner:` section in `aitm_e2e/config.py` and the per-verb ledger in `tests/e2e/run.py` (all T10, D12); everything else in it stands.
- **Rhai human-readability** (`docs/research/MEMORY.md`, human-friendly scripting): a check script reads as prose with one declaration map and one closure; no JSON-in-strings, no agent-only encodings.

## Design

### D1. Shape: a kernel, lanes, and one verb family

**(Architect's call)** The scanner becomes a **kernel + lanes** structure so that tracks own disjoint crates:

| Crate | Owner | Role |
|---|---|---|
| `aitm-scan-model` (new) | T1 | Pure types and traits, serde, no I/O: profile, job status, insertion point, check metadata, verdict, issue, session profile, progress, the `Check`/`ProbeHost`/`Lane` traits. Depends only on `aitm-core`, `aitm-poc` (for `Severity` and `Assertion`) and serde. Every other scan crate and every UI fixture consumes it. |
| `aitm-plugin-scanner` (existing) | T1 | The engine: job registry and worker, scheduler, catalogue bridge, issue store, profiles, all `scan.*` verbs, the legacy verbs re-implemented over the job model, and the **interim HTTP lane** (below) over the legacy `crawl.rs`/`discover.rs`/`inject.rs`/`checks.rs`. T2's final integration task deletes those four modules and the interim adapter once `aitm-scan-http::lane()` returns `Some` (the one T2 edit inside this crate, made after T1b is on `main`). |
| `aitm-scan-http` (new) | T2 | HTTP lane: crawler v2 (browser + client), site map, insertion points v2 and request mutation, session reuse, scheduler priority inputs. |
| `aitm-scan-checks-http` (new) | T3 | **Not a lane.** A checks crate exposing `pub fn checks() -> Vec<Arc<dyn Check>>` (empty in the T1a skeleton; T3 fills it); the engine schedules its checks over the HTTP lane's insertion points. Native HTTP checks (boolean/timing blind, h2 observe-only, raw-h2 probe); plus the `HttpSender` h2 work inside `aitm-proto-http` and the bundled Rhai scripts in `scripts/bundled/active`. |
| `aitm-scan-ws` (new) | T4 | WS lane: dialer, frame insertion points, WS checks, `ws` `ProtocolLanguage` namespace. |
| `aitm-scan-l4-packet` (new) | T5 | L4 packet lane over `PacketSpec` + `send_recv`; adds `crates/aitm-proto-l4/src/icmp.rs` (ICMP type/code extraction) and the liveness probe. |
| `aitm-scan-l4-stream` (new) | T6 | L4 stream lane: socket client, mutators, `MessageSpec`, the eight grammars, oracles. |

**Registration without shared files.** T1 creates every lane crate as a skeleton (Cargo.toml, `lib.rs` exposing one `pub fn lane() -> Option<Arc<dyn Lane>>` returning `None`, and for `aitm-scan-ws` also `pub fn language(...) -> Option<Box<dyn ProtocolLanguage>>`) and the checks crate `aitm-scan-checks-http` as a skeleton exposing `pub fn checks() -> Vec<Arc<dyn Check>>` returning an empty list (it has no `lane()`), adds them to the workspace and to `crates/aitm/Cargo.toml`, and wires the calls in `crates/aitm/src/wire.rs` and `main.rs` up front: `wire.rs` collects the five `lane()` results into the lane list and `aitm_scan_checks_http::checks()` into `native_checks`, and hands both to `ScannerPlugin` (`ScanServices.lanes` / `ScanServices.native_checks`, D5). After that, a lane or checks track edits **only its own crate** (plus the files named in its row of D12); no lane track touches `crates/aitm/**`, `aitm-core`, `aitm-mcp`, `aitm-plugin-rhai` or the contract lists. A lane whose crate returns `None` (not yet landed, feature off, platform cannot run it) is absent from `scan.checks` and is **not** a refusal on its own: `scan.start` runs the profile's other lanes, reports the skip in `JobStatus.lanes: { requested, run, skipped: [ { lane, reason } ] }` and in its own result, and fails with `lane_unavailable` only when **every** requested lane is unavailable (D3 defines the code). When two lanes register for the same `Lane` value, the engine prefers a lane crate's lane over the interim one.

**Interim HTTP lane (T1b).** So that every T1 acceptance criterion is provable standalone before T2 lands, T1b ships an interim `Lane` implementation inside `aitm-plugin-scanner` over the legacy modules: the shipped browser crawl (`crawl.rs`), the v1 insertion points (`discover.rs`), the two native payload classes (`inject.rs`: reflected XSS, open redirect) and the three passive checks (`checks.rs`), each adapted to the `Lane`/`ProbeHost`/`Check` traits with full `CheckMeta`. It registers for `Lane::http`. T2 replaces it by flipping `aitm-scan-http::lane()` to `Some`; the engine then ignores the interim lane, and T2's final integration task deletes the legacy modules and the adapter. The interim lane adds no new detection and no new verb; it is the v1 scanner wearing the v2 contract.

**Where a probe goes.** The engine never calls a sender directly. Every HTTP probe goes through the job's `JobClient` (D5), which wraps `aitm_core::ProxyClient` (the `PipelineClient` the binary built: guard, sender, store) and adds budget, pacing, timing, marks and record policy. WS and L4 stimuli go through the lane's own transport, each guarded by the lane's guard (`ScopeRateGuard` by authority for WS; `L4Guard` for both L4 lanes) and metered by the same job budget.

### D2. Shared data model (`aitm-scan-model`)

All types are `Serialize + Deserialize`, snake_case on the wire, and are the **only** shapes verbs emit and UIs parse. Enum wire tokens are listed because UIs and scripts match on them.

- `Lane`: `http | ws | l4_packet | l4_stream`.
- `Intensity` (the safety axis, Burp's): `passive | light | medium | intrusive`. A profile's intensity admits checks with `intensity <= profile.intensity`. `intrusive` requires `_confirm` for every caller.
- `Speed` (request-count axis): `fast | normal | thorough`, maps to payload caps per check (ZAP's strength: e.g. boolean pairs 2/4/8, timing repeats 2/3/5).
- `Accuracy` (retry axis): `fewer_false_negatives | normal | fewer_false_positives`, maps to blind-technique repeat counts 1/2/3 and the confidence floor for recording.
- `InsertionKind`: `query | body_param | json_value | xml_value | xml_attr | multipart_value | multipart_filename | header | cookie | path_segment | path_filename | param_name_query | param_name_body | entire_body | ws_json_value | ws_text | ws_form_param | ws_binary | ws_handshake_header | l4_field` (L4 points are grammar field paths). The shipped `redirect` location becomes a **trait** on a point, not a kind.
- `InsertionPoint`: `{ id, lane, kind, name, path (for json/xml/l4: a dotted/bracket field path), example (redacted per `aitm_core::redact`), flow: Option<FlowId>, site_node: Option<NodeId>, traits: [url | filename | number | email | base64 | json | id | session] , frequency: u32 (how many site nodes carry the same (kind,name)) }`. `session`-trait points are never mutated unless a check declares `targets_session: true` (none in v2).
- `CheckMeta`: `{ id, name, class, lanes: [Lane], kinds: [InsertionKind], intensity, cost: light | medium | heavy (estimated probes per point: <=3, <=10, >10), technique: reflected | error | boolean | timing | handshake | malformed | observe | passive, severity: aitm_poc::Severity (typical), confidence_max: Confidence, needs_baseline: bool, wants_traits: Option<[trait]> (optional; when present the scheduler schedules the check only on points carrying at least one listed trait, unless `speed: thorough`), cwe: Option<u32>, description, remediation: Option<String>, origin: native | bundled(path) | custom(path) }`.
- `Confidence`: `certain | firm | tentative` (Burp). Technique sets the ceiling: reflected marker in the right context and malformed/handshake with a definitive server reaction may be `certain`; error signature, boolean after repeat, timing after correlated repeat are `firm`; anything inferred once is `tentative`.
- `Verdict`: `{ outcome: vulnerable | clean | inconclusive | error, confidence, evidence: Evidence, detail, poc_hint: Option<PocHint> }`. `PocHint { assertions: Vec<aitm_poc::Assertion>, control: Option<ControlHint> }` and `ControlHint { payload: String, expect: Vec<aitm_poc::Assertion> }` (the benign control payload and what its response must satisfy, mirroring `FindingRecord.reproduction.control_passed`) are defined in this crate. A check supplies the hint in its verdict; the engine builds the PoC from the probe request with those assertions (D6). `poc_hint` is consumed in-process and never emitted on the wire: `Verdict` is not a verb result, `Issue` does not carry it, and the field is `#[serde(skip)]` because `aitm_poc::Assertion` has no serde derives (verified in `crates/aitm-poc/src/model.rs`) **(Architect's call)**.
- `Evidence`: `{ payload: Option<String>, matched: Option<String> (a scanner constant or a bounded, scrubbed excerpt <= 256 bytes), probe_flows: [FlowId], baseline_flow: Option<FlowId>, timing: Option<{ requested_s: [f32], observed_ms: [u32], baseline_ms: [u32], slope, r }>, diff: Option<{ baseline_len, true_len, false_len }>, l4: Option<L4Evidence> }`. `L4Evidence`: `{ sent_hex, seed_id, rng_seed, mutation_chain: [String], prior_messages: u32, oracle: protocol_error | reset | icmp(type,code) | silence | liveness_failed | latency_outlier, liveness_before: bool, liveness_after: bool, reproduced: (k, n), scope_entry: String }`.
- `Issue` and `IssueSummary`: D6.
- `ScanProfile`: `{ name, target: { origins: [String] (http(s)://host[:port]), l4: [ { ip, port, proto: tcp | udp, grammar: Option<String> } ] }, lanes: [Lane], intensity, speed, accuracy, checks: { include: [id|class|lane:*], exclude: [...] }, crawl: { strategy: fast | normal | thorough, max_depth, max_pages, submit_forms, click_handlers, robots, sitemap, use_browser: auto | always | never }, audit: { kinds: [InsertionKind], ignore: [ { kind?, name_regex?, trait? } ] (at least one key; a rule matches when every present key matches; the default rule set is `[ { trait: session } ]`, which the operator may remove), max_points_per_request (default 64), frequent_point_threshold (default 8) }, session: { mode: observed | none, from_flow: Option<FlowId>, on_lost: stop | continue }, budget: { probes (default 2000), time_s (default 600), max_issues (default 1024), per_host_errors { consecutive (default 10), ratio (default 0.5) } }, http: { version: VersionPolicy = auto | h1 | h2 | h2c (default `auto`; passed to the sender through `SendOptions.version`, D9.1), record_probes: issues_only | all }, ws: { reply_window_ms (default 1500), max_frame_bytes (default 1 MiB) }, l4: { cases (default 500), reproduce_count (default 3), liveness_every (default 25), consecutive_timeouts (default 20), max_bytes_per_s (default 65536), seeds: [ { flow: FlowId } | { hex } | { base64 } ], dry_run: bool } }`. Hard ceilings live in config, not the profile (D11); a profile value above a ceiling is clamped and reported in `scan.start`'s `clamped` list.
- Built-in profiles (constants in the model crate): `passive-only`, `map-only` (crawl + passive, no probes), `light-http`, `standard` (http+ws, medium, normal), `thorough` (http+ws, medium, thorough, fewer_false_negatives), `l4-stream-safe` (stream lane, dry_run off, cases 200), `l4-full` (both L4 lanes).
- `JobStatus`: D5. `SessionProfile`: D7.
- Traits: `Check` (`meta(&self) -> &CheckMeta`; `run<'a>(&'a self, point: &'a InsertionPoint, host: &'a dyn ProbeHost) -> BoxFuture<'a, Verdict>`), `ProbeHost` (`baseline()`, `probe(payload: &Payload) -> ProbeResponse`, `probe_raw(req: RawProbe)`, `marker() -> String`, `budget_left() -> u32`, `deadline() -> Instant`, `profile() -> &ScanProfile`, `cancelled() -> bool`; each returning `BoxFuture` where it does I/O), `Lane` (`lane(&self) -> Lane`; `discover(target, ctx) -> BoxFuture<Vec<InsertionPoint> + SiteNodes>`; `probe_host_for(point, job) -> Box<dyn ProbeHost>`; `checks(&self) -> Vec<Arc<dyn Check>>` native checks the lane ships). `ProbeResponse`: `{ status: Option<u16>, headers, body (bounded), elapsed_ms, flow: Option<FlowId>, ws_frames: Option<Vec<Frame>>, l4: Option<L4Reply> }`.

### D3. Bus verb contract

Every verb is a plugin-registered `Command` in `aitm-plugin-scanner` with a `ParamSchema`; results are typed `Value::Object`s whose keys are exactly the model types above. Errors are `anyhow` strings of the form `scan: <code>: <message>` where `<code>` is one of `not_found | busy | out_of_scope | refused_agent | refused_l4 | lane_unavailable | invalid_profile | unknown_check | confirm_required`; the MCP layer surfaces them as `isError` text, so every UI and the harness match on the code token. Clamping is not an error (it is the `clamped` list in the `scan.start` result) and cancellation is not an error (it is `JobStatus.state: cancelled`).

The refusal codes a caller is most likely to confuse are defined precisely, and `scan.start` checks them in this order: **`lane_unavailable`** = every requested lane is unavailable, because its crate returned `None` or because the platform cannot run it (for example the packet lane without pcap privilege); a profile with some unavailable lanes and at least one available one is not refused, the unavailable lanes are skipped and reported (D1, D5). **`out_of_scope`** = an HTTP origin of the profile is not in the HTTP scope, or an L4 target is not covered by an L4 scope entry carrying the `Inject` capability (`L4Guard::check(Inject, target)` refused). **`refused_l4`** = the L4 layer is disabled (`l4.enabled: false`), or the caller is an agent lacking `scanner.allow_agent_l4_fuzz` or lacking the existing `l4.allow_agent_inject`. **`refused_agent`** = an agent caller without `scanner.allow_agent_active`, or an agent requesting `intensity: intrusive` (operator-only).

| Verb | Tier | Params | Result |

### D4. The check catalogue contract

**Native checks** implement `Check` and are contributed by a lane's `checks()` or by `aitm-scan-checks-http::checks()` (the `native_checks` slot `wire.rs` fills, D1). **Rhai checks** declare themselves in `load(reg)` with `reg.add_check(<meta map>, <closure>)`, where the meta map's keys are exactly `CheckMeta`'s wire names (`id`, `name`, `class`, `lanes`, `kinds`, `intensity`, `cost`, `technique`, `severity`, `confidence_max`, `needs_baseline`, `wants_traits` (optional), `cwe`, `description`, `remediation`) and the closure takes one argument, the `point` map (`kind`, `name`, `path`, `url`, `method`, `example`, `traits`). The closure returns a verdict map with the `Verdict` wire keys (`outcome`, `confidence`, `evidence: #{ payload, matched }`, `detail`, and optionally `poc_hint: #{ matchers: [..], control: #{ payload, matchers } }` in the PoC YAML `matchers` vocabulary the PoC loader already parses, which the bridge converts to `PocHint`) or a plain string, which the bridge reads as `inconclusive` with that string as `detail` (so an old-style script never breaks the run). Missing or invalid meta is a **load error** naming the key (the catalogue cannot schedule what it cannot classify). **(Architect's call)** Every catalogue entry, **native or Rhai**, also gets a manual `check.<id>` command (`{ url, param, value? }`, `Sensitive`) that synthesizes a `query` point and runs the same check, registered uniformly by the engine's catalogue bridge when the check is added (`add_check` for Rhai; a lane's `checks()` or `aitm-scan-checks-http::checks()` for native), so the shipped manual verbs survive, a check is written once, and native checks are invocable by hand too. Each new `check.<id>` is a new verb for the integration-shared contract lists (Constraints).

**Probe host functions** available inside a check closure (read the current check context the way `option()`/`finding()` read the call tag; refused with a clear error outside a check): `probe.send(payload) -> #{ status, headers, body, elapsed_ms, flow_id }` (the point is mutated with the payload by the lane: encoding and `Content-Length` are the point's business), `probe.baseline() -> same` (cached per point), `probe.raw(#{ method, url, headers, body }) -> same` (same origin only, for handshake/header checks), `probe.marker() -> String` (unique per call), `probe.budget_left() -> int`, `probe.timing_fit(#{ requested_s: [..], observed_ms: [..] }) -> #{ correlated: bool, slope, r }` (ZAP's rule: alternating long/short delays, correlation error 0.15, slope error 0.30), `probe.levenshtein_ratio(a, b)`. `http.send` gains `elapsed_ms` everywhere (measured around the sender call, independent of the store's `duration`), and inside a check it routes through the job's client (D9.3) so budget, pacing, marks and record policy apply to scripts too.

**Timing without `sleep`.** A timing check sends the delay payload and reads `elapsed_ms`; it never waits itself. The host enforces a per-check wall budget (`RunKind::Check`, default 60 s from the profile's `check_timeout`, not the 2 s hook budget) and a per-probe timeout (`min(remaining, 30 s)`). Repeats are governed by `Accuracy`; the native `TimingOracle` in `aitm-scan-checks-http` is the same algorithm `probe.timing_fit` exposes.

**Scheduling.** For each insertion point the scheduler selects catalogue entries whose `lanes` contain the point's lane, whose `kinds` contain the point's kind, whose `intensity <= profile.intensity`, that match the profile's include/exclude, and (Burp's "skip checks unlikely to be effective") whose class matches the point's traits when the check declares `wants_traits` (e.g. `open-redirect` wants `url`, `path-traversal` wants `filename` unless `speed: thorough`). Items are ordered by priority `0.8 x exposure + 0.2 x interest` (research 17 §3.2): exposure = new points the request adds; interest = method (POST/PUT higher), content type (HTML/JSON/XML higher), authenticated (higher). Passive phase runs for all items, then the active phase; within active, `light` checks run before `medium` across all points. A `(kind, name)` with `frequency > frequent_point_threshold` gets `light` checks only (reverts to full on a hit).

**Tier laundering guard.** Scripts' `check.*` commands stay `Sensitive` for manual invocation. Inside a job the gate is the job's: `scan.start` is `Sensitive`, its agent gate was passed at start, and the catalogue runs scripts without a per-call policy decision. That is deliberate and is the reason `scan.start` is `Sensitive` even for a profile that would only run `Write`-grade probes.

### D5. The job model

- **Registry.** `JobRegistry` = `Arc<Mutex<HashMap<JobId, JobEntry>>>` shared by `ScannerPlugin` and every `scan.*` command (the `CaptureRegistry`/`InjectRegistry` shape). `JobEntry { status: Arc<RwLock<JobStatus>>, cancel: CancellationToken, task: JoinHandle<()>, _confine: Option<ConfinementToken>, started_by: { frontend: Frontend, client_label: Option<String> } }`. Job ids are `scan-<8 hex>`.
- **Owned handles.** `ScanServices { store: Arc<dyn FlowStore>, client: Arc<dyn ProxyClient>, guard: Arc<dyn ScopeRateGuard>, browser: Option<Arc<dyn BrowserDriver>>, findings: Option<Arc<FindingStore>>, egress: Option<Arc<EgressConfinement>>, l4: Option<Arc<L4Guard>>, jobs: Arc<JobBus> (D9.2), agent_policy: Arc<dyn Fn() -> AgentPolicy + Send + Sync>, catalogue: Arc<Catalogue>, lanes: Vec<Arc<dyn Lane>>, native_checks: Vec<Arc<dyn Check>> (from `aitm_scan_checks_http::checks()`, D1), rt: tokio::runtime::Handle }` bound late in `wire.rs` (the `LateHandles` precedent), so `scan.start` only validates and spawns.
- **Start.** `scan.start` resolves the profile, clamps to ceilings, resolves each requested lane to a registered `Lane` (preferring a lane crate's over the interim; the unavailable ones go to `lanes.skipped` with a reason, and `lane_unavailable` fires only when none is left), checks every HTTP origin against the scope guard and every L4 target against `L4Guard::check(Inject, target)` **before** spawning (`out_of_scope`), applies the L4-layer and agent gates (`refused_l4`, `refused_agent`, in D3's order), checks `max_jobs` (default 2) and per-origin single flight (`busy`), takes the confinement token, writes `JobStatus { state: queued }`, spawns the worker on `rt`, and returns.
- **Worker phases.** `queued -> crawling -> passive -> auditing -> reporting -> done`, or `cancelled`/`failed` from any phase. `JobStatus`: `{ job, state: queued | running | cancelling | done | cancelled | failed, phase, profile_name, targets, started_by, started_at, finished_at, elapsed_ms, stopped_reason: Option<budget | time | cancelled | session_lost | errors | policy | guard_refused | failed>, probes: { sent, budget, errors, timeouts, rate_waits, by_lane: { lane: sent } }, crawl: { pages, queued, depth, forms_submitted }, points: { found, queued, audited, skipped: { ignored, frequent, limit } }, checks: { scheduled, done, running: [check_id] (<= 8) }, issues: { total, by_severity, by_confidence }, l4: Option<{ cases, crashes, liveness_failures, retired_elements }>, session: Option<{ reused: bool, lost: bool, canary: none | { method: GET | HEAD, path }, browser_partial: bool }>, lanes: { requested: [Lane], run: [Lane], skipped: [ { lane, reason } ] }, clamped: [..], error: Option<String> }`. Counters are monotonic.
- **Budget and pacing.** One `probes` budget per job across lanes; `JobClient` charges one unit per stimulus, waits on `GuardError::RateLimited { retry_after }` instead of aborting (counted in `rate_waits`), and stops the lane at the per-host error ladder (`consecutive` 5xx/transport failures or `ratio` over the last 50). The browser crawl's navigations are charged against the same budget. The deadline is `started_at + time_s`; every await is bounded by `min(remaining, 30 s)`.
- **Record policy.** Default `issues_only`: a probe is sent via `send_opts` with `record: Never`; when a verdict is `vulnerable` the check's probe and baseline flows are re-recorded into the store (they were kept in memory by the `ProbeHost` for the duration of the check, bounded to 16 per point) with marks `scan:<job>`, `issue:<id>` and `is_replay: true`. `all` records every probe (marked), for debugging a target. Under `issues_only` a probe flow never reaches the store except through that issue re-recording. **Crawl flows are different**: browser-crawl navigations are real captures through the proxy listener (the browser is proxied), so they land in the store as ordinary captures; the lane diffs the store around each navigation (bounded: the flows added between the navigation's start and its settle) and marks each resulting flow `scan:<job>` and `crawl`. Client-crawler `GET`s go through `send_opts` like probes, recorded under the same policy with the `crawl` mark.
- **Policy re-check.** An agent-started job reads `agent_policy()` at every scheduling step; `Paused` or `ReadOnly` cancels it with `stopped_reason: policy`. Operator-started jobs ignore agent policy.
- **Cancellation.** `scan.cancel` sets the token; the worker observes it between probes and inside every bounded await; the entry moves to `cancelled` with its issues intact; the confinement token drops with the entry.
- **Persistence.** On every terminal transition the `JobStatus` and the job's issues are written to `<findings.dir>/scan/jobs/<job>.json` (when `findings.dir` is set); `scan.list` reads them back at startup.

### D6. The issue model and dedupe

`Issue { id: "issue-<8 hex>", job, check_id, class, name, severity, confidence, status: open | confirmed | false_positive, lane, target: { scheme, host, port }, location: { method?, path, path_template, kind, name, field_path?, ws_path?, l4: Option<{ ip, port, proto, grammar, field_path, mutation }> }, evidence: Evidence, first_seen, last_seen, occurrences, poc_ref: Option<String>, finding_id: Option<String>, description, remediation: Option<String>, note: Option<String> }`. `IssueSummary` = the same minus `evidence.*` bodies and `description`.

**Dedupe key** = `blake3(class, scheme, host, port, method, path_template, kind, name, field_path)` for HTTP/WS and `blake3(class, ip, port, proto, grammar, field_path, mutation_class)` for L4; `check_id` is **not** in the key, so two checks for one class on one point produce one issue whose `evidence` is the higher-confidence one and whose `occurrences` counts both. **Passive consolidation**: a `technique: passive` check dedupes on `(class, scheme, host, port)` and lists the paths in `evidence.matched` (bounded). A repeat raises `confidence` to the max seen and `last_seen`; it never lowers. Severity is `aitm_poc::Severity` (five levels; the shipped findings already use it) **(Architect's call** over Burp's four).

**Issue vs finding.** Issues live in the scan issue store (`<findings.dir>/scan/issues/<id>.json` + an index). A `FindingRecord` is written **only** when a PoC reproduction ran and passed: for a `vulnerable` verdict with `confidence >= firm` **whose check supplied a `PocHint`** (D2), the engine builds the PoC from the probe request with the hint's assertions (and control, when given) via `StdPocBuilder`, scrubbed with `scrub_text_wide`, runs it exactly once per issue through `StdPocRunner` (bounded, counted against the budget), and records via the existing `record_finding` only when `reproduction.passed`; `finding_id` links back. A verdict without a hint, or whose reproduction did not pass, yields an issue only. The engine holds no class list; the hint is the contract. The shipped checks for `reflected-xss`, `open-redirect`, `sqli-error`, `ssti`, `cmdi`, `path-traversal`, `crlf` and `xxe` **MUST** supply a hint (T3 owns that; the interim lane's two native classes supply one so T1-10 is provable before T3). `scan.report` renders findings and issues; the UIs' Findings surfaces keep showing `FindingRecord`s and the Scan surfaces show issues.

### D7. Session reuse (observed-session mode)

`SessionProfile { origin, cookies: [name], headers: [name], source_flow, observed_at, canary: none | { method: GET | HEAD, path, expected_status } }`. At `scan.start` with `session.mode: observed` the engine picks the newest in-scope **captured** (not replay) flow to each origin that carries a `Cookie` header or a header whose name `is_secret_name` matches (`Authorization`, `X-Api-Key`, ...), or the flow named by `from_flow`. Values are held only in the worker's memory and applied to: every HTTP probe and baseline (header merge: probe-specific headers win, session cookies merged by name), the client crawler (D8.1), and the browser crawl via `document.cookie` for non-HttpOnly cookies (an HttpOnly session cookie cannot reach the browser; the status reports `session.browser_partial: true`; recorded login sequences are the later fix). **Auth-lost detection**: the canary is **GET or HEAD only** and never carries a body: it is the newest in-scope captured `GET`/`HEAD` flow to the origin that carries the session material, replayed with its headers unchanged. `from_flow` must itself be `GET`/`HEAD`; otherwise the engine falls back to that rule and reports the substitution in `JobStatus.session.canary`. With no eligible flow, `session.canary: none`, auth-lost detection is **off**, and `JobStatus.session.canary` says so. Every 25 probes the canary is sent; a status class change (2xx -> 3xx/401/403) sets `session.lost` and, per `on_lost`, stops the audit (`stopped_reason: session_lost`, default) or continues. Session-material points carry the `session` trait and are skipped as insertion points (an `ignore` rule the operator can lift by excluding the trait in `audit.ignore`). `scan.session.preview` shows names only; no verb, push, issue, PoC or log carries a value (AC T2-6).

### D8. Lanes

#### D8.1 HTTP lane: crawler v2, site map, insertion points v2 (T2)

- **Crawler v2** has two engines behind one `Crawler` trait: the **browser** engine (existing `BrowserDriver` navigation plus, new, bounded `click` on pointer-clickable elements and `type`+submit on forms with inert values; `strategy` sets depth/pages/forms/click limits) and a **client** engine (plain `GET`s through the `JobClient` with an HTML link/form extractor; no JS). `use_browser: auto` uses the browser when available and falls back to the client; both honour `robots` and `sitemap` options, treat fragments with `/ \ ? = &` as routing, and fingerprint pages by normalised DOM/body hash so volatile content does not loop. Browser navigations are real proxied captures; the lane marks the flows each navigation produced `scan:<job>` and `crawl` by the store diff of D5, so every flow a job adds to the store carries `scan:<job>` (AC T1-9).
- **Site map**: `SiteNode { id, method, scheme, host, port, path_template (numeric -> {id}, UUID -> {uuid}, 24-hex -> {oid}), flows, params: [(kind,name)], auth: bool }`; built from crawl results and from **already captured in-scope flows** to the origin (so proxied traffic seeds the audit without a crawl).
- **Insertion points v2**: `enumerate_v2(flow) -> Vec<InsertionPoint>` covering every `InsertionKind` of D2 for HTTP, nested JSON with typed replacement (a number stays a number unless the payload is non-numeric, then a string), XML values and attributes, multipart values and filenames, every path segment and the filename, parameter names (only at `intensity >= medium`), entire body (only when the body is not a recognised format), with a per-request cap `max_points_per_request` (default 64, Burp's rule; skipped points counted). `build_request(point, payload, mode: replace | prefix | suffix) -> HttpRequest` is the single mutation function: it re-serialises form/JSON/XML/multipart, re-encodes query/path, and recomputes `Content-Length`; `Header`/`Cookie`/`PathSegment` are mutable (fixing research 20 §3.5).
- The lane's `ProbeHost` wraps `JobClient`, applies the session profile, measures `elapsed_ms`, caches the baseline per point, and bounds bodies at 1 MiB for matching.
- Redaction: every `example` and every excerpt in `Evidence.matched` passes `aitm_core::redact` (post-#199 vocabulary).

#### D8.2 HTTP/2 sender and HTTP checks (T3)

- **`HttpSender`** replaces `Http1Sender`'s behaviour behind the same construction site: it offers ALPN `[h2, http/1.1]`, caches the negotiated protocol per authority (TTL 10 min), dispatches to the h1 path or an h2 path built on `h2::client::handshake` exactly as `h2.rs`'s outbound path does (one connection per authority reused while idle, closed on error), converts via `translate`, and reads `SendOptions.version` (`VersionPolicy`, D9.1): `auto` = ALPN-negotiated and cached per authority; `h1` forces the h1 ALPN; `h2` forces h2 and, when the peer does not negotiate it, returns the sender error `h2_not_negotiated`, which the engine surfaces as a probe error (counted in `probes.errors`, feeding the per-host error ladder) and never as a job failure; `h2c` does prior-knowledge cleartext h2. `HttpRequest.version` stays what the sender observed on the wire. `Http1Sender` remains as a type alias so `wire.rs` is untouched **(Architect's call)**. Response caps stay (60 s, 16 MiB).
- **Raw h2 probe**: a tiny frame writer/reader (preface, SETTINGS, one HEADERS with hand-encoded HPACK literals, read until response/`RST_STREAM`/`GOAWAY`, close) used only by the observe-only h2 checks, because the `h2`/`http` crates refuse malformed headers by construction. It opens at most one connection per check and never more than 8 streams (the test target's per-connection request counter is the oracle, T3-3).
- **Native checks** (all `Check` impls): `sqli-boolean` (control re-send, AND-true must match baseline, AND-false must differ, OR-true variant, repeats by `Accuracy`; `firm`), `sqli-time` and `cmdi-time` (alternating 1 s/3 s (or 2 s/5 s at thorough) delay payloads per DB/shell family, `TimingOracle`, at most 4 probes per family; `firm`), `xss-reflected` (shipped, upgraded: context-aware marker, HTML content-type rule; `certain`), `open-redirect` (shipped; `certain`), `h2-pseudo-header-validation`, `h2-header-crlf-tolerance` (name and value), `h2-cl-te-downgrade-indicator` (single off-by-one `content-length` / `transfer-encoding: chunked` header probe, detect-only, never a second request; `tentative`, `info` severity unless the response desyncs visibly), `h2-rapid-reset-mitigation` (<= 8 open/reset pairs; reports `info` "no reset-rate mitigation observed" or clean), `h2-settings-observe` (reads advertised SETTINGS; `info`). The DoS-adjacent checks are `intensity: medium` and never `intrusive`.
- **Rhai checks**: the fifteen bundled `active/*.rhai` scripts are converted to `reg.add_check` with full metadata and multi-kind support via `probe.send` (they stop building `?param=` URLs by hand), plus new `check-nosqli-json` (json_value kind), `check-header-reflection`, `check-cswsh` lives in the WS lane. Classes stay single-sourced: a class is either native or Rhai, never both (`sqli-error` Rhai, `sqli-boolean`/`sqli-time` native, and so on). `scripts/bundled/README.md` is corrected (`script.findings`, the catalogue section, the `add_check` shape).
- Why no seeded h2-specific positive: a detect-only desync or malformed-pseudo-header positive needs a lax h2 server, and every Rust h2 server (`h2`, hyper) rejects those frames itself; building a hand-rolled permissive HPACK server for the test target is out of proportion. The h2 lane is proven by the h1-class seeds found over h2 and by the observe-only checks' exact expected set on hyper (true negatives).

#### D8.3 WebSocket lane (T4)

- **`WsDialer`**: `tokio-tungstenite` client with a rustls `Connector`; `dial(handshake: &HttpFlow, overrides: HandshakeOverrides) -> WsConn`. It replays the captured handshake's headers except `Host`, `Connection`, `Upgrade`, `Sec-WebSocket-Key`, `Sec-WebSocket-Version` (regenerated) and never sends `Sec-WebSocket-Accept`; keeps `Cookie`, `Origin`, `Authorization`, `Sec-WebSocket-Protocol`, `Sec-WebSocket-Extensions` and custom headers unless an override replaces or strips them. The dial authority passes `ScopeRateGuard` (`check_active` by authority) and the job budget (one unit per dial, one per frame sent). At most 4 connections open per job at once; each closes at the end of its probe; ping/pong and close are handled by the dialer; a conversation is recorded as a `WsFlow` with `is_replay` only under the record policy of D5.
- **Insertion points**: from each captured client->server text frame of the handshake's `WsFlow`: JSON leaves (`ws_json_value`, typed), URL-encoded pairs (`ws_form_param`), else the whole text (`ws_text`); binary frames become one `ws_binary` point (byte mutators, `medium` only); handshake headers become `ws_handshake_header` points (`Origin`, `Cookie`, `Sec-WebSocket-Protocol`).
- **Probe semantics**: `probe.send(payload)` dials, replays the client frames that preceded the chosen frame (the boofuzz prerequisite idea), sends the mutated frame, collects server frames for `reply_window_ms`, closes. The oracle sees `ws_frames`.
- **Checks**: `cswsh` (dial with a foreign `Origin` and the session cookies: upgrade completes and the first server frame matches the authenticated baseline frame -> `high`/`certain`), `ws-auth-bypass-handshake` (dial with `Cookie`/`Authorization` stripped: still 101 and authenticated-looking data -> `high`/`firm`), `ws-input-reflection` (marker in a field reflected unencoded in a reply frame -> `medium`/`certain` for HTML-ish reflection, `low` otherwise), `ws-sql-error`, `ws-ssti`, `ws-cmdi-echo` (reuse the HTTP payload sets and signatures through the WS oracle), `ws-oversize-frame` (one frame at `2 x max observed`, capped by `max_frame_bytes`; reset or error vs accept; `info`/`firm`; `medium`), `ws-subprotocol-observe` (`info`). No compression oracle.
- **`ws` Rhai namespace** via `ProtocolLanguage` (`api_version "1"`): `ws.dial(#{ url, headers? }) -> handle`, `ws.send(handle, text | blob)`, `ws.recv(handle, timeout_ms) -> #{ frames: [..] }`, `ws.close(handle)`; all `Guarded` through the scope guard; handles bounded (4) and closed when the call ends; a hook (`on_ws_*`) cannot call them (commands and checks only).

#### D8.4 L4 packet lane (T5)

- **Plan**: `PacketFuzzPlan { seed: PacketSpec, dst, dst_port, interface, fields: [ { path, mutator } ], expect: ReplyMatch }` where `path` is a `PacketSpec` field path (`ipv4.ihl`, `tcp.flags`, `udp.length`, ..., and `raw` for the `Raw` payload layer of `PacketSpec`, which the lane fuzzes with the byte mutators of D8.5 so that a userland service can observe a case). `dst`, `dst_port`, `interface`, `ether.src/dst`, `ipv4.src`/`ipv6.src` are **non-fuzzable by construction** (scapy's rule; a plan naming them is `invalid_profile`); source spoofing is refused. Seeds come from a captured L4 flow's packet (`seeds: [{flow}]`) or from a crafted spec.
- **Mutators** per field type: boundary and interesting values (0, 1, max, max-1, declared-length +/- 1, off-by-one `ihl`/`data_offset`, reserved bits set, invalid checksum, fragment offset with/without MF, TTL 0/1, ICMP type/code sweep in the valid-but-unexpected set), seeded by `rng_seed` so a case replays.
- **Transport**: each case is one `send_recv` through the existing `SendRecvOutcome` path (per-call `Inject`+`Capture` permits; the per-call capture-handle cost is accepted). Added in `aitm-proto-l4/src/icmp.rs`: `icmp_error(&L4Packet) -> Option<(u8, u8)>` so an `Other` reply yields type/code in evidence.
- **Oracle and liveness**: `Response` -> clean; `Other` with ICMP -> `info` (protocol reaction; type/code recorded in `L4Evidence.oracle`; a real closed UDP port's port-unreachable and a closed TCP port's RST are the kernel-level positive proofs of the oracle, T5-2a); `NoResponse` -> **liveness probe** (the seed itself unmutated, or a TCP SYN to `dst_port`, expecting the baseline reply) immediately and again after 500 ms; an element whose case plus two liveness failures repeat `reproduce_count` times (spaced 1 s) yields an issue of class `l4-crash` (`critical`, `firm`) and that element is **retired** (boofuzz's threshold). A liveness probe runs every `liveness_every` cases regardless, and the lane stops (`stopped_reason: errors`) after `consecutive_timeouts` silent cases.
- **Why `raw` matters.** The target's kernel drops malformed IP/TCP/UDP headers before any userland service sees them, so header-field cases are expected to yield kernel reactions only (ICMP, RST, silence). The crash oracle's positive proof therefore comes from the `raw` layer against T10's userland UDP payload-crash service (T5-2b), while header cases prove the ICMP/RST classification (T5-2a).
- **Caps** (config ceilings, D11): cases per job <= 5000, pps from the scope entry, `L4Permit` per packet, `max_packets_per_call`, no case larger than `max_packet_bytes`, no fragment series longer than 8, dry-run renders the first 50 cases without sending.
- **Dry run stays opt-in** for both L4 lanes **(Architect's call** on research 18 C5, which proposed dry run as the default first step): the per-caller `_confirm` prompt is the safety step, and the built-in `l4-full`/`l4-stream-safe` profiles are already capped by the ceilings above. `scan.start` reports `dry_run: false` (or `true`) in its result for every job with an L4 lane so a UI can offer a dry run first (D3).

#### D8.5 L4 stream lane and grammars (T6)

- **Transport**: `StreamClient` over `tokio::net::{TcpStream, UdpSocket}` (unprivileged). Authorisation: `L4Guard::check(L4Action::Inject, L4Target { ip, port, proto, interface: "*", direction: Outbound })` per connection/datagram **(Architect's call** on research 18 Q10: the L4 guard, because the target vocabulary is IP:port and the operator already declared it there; the lane adds a bytes/s pacer and a per-job connection cap of 4 because `L4Permit` meters packets, not bytes). The lane needs `l4.enabled` and a scope entry with `Inject` capability whose `interface` is `"*"` (the wildcard rule of D9.5, landed by T1a) or the actual egress interface; the operator adds such an entry, and the config reference and UI launch hints say so (D11); it needs **no** capture privilege.
- **Corpus**: (a) captured L4 flows' client->server payload bytes in packet order (per-packet payloads are the message boundaries; no TCP reassembly beyond concatenating in-order payloads of one flow), (b) grammar-generated well-formed messages, (c) operator seeds (`hex`/`base64`). Each seed is parsed by the selected (or port-inferred) grammar into a field tree; unparseable seeds fall to the generic TLV model.
- **`MessageSpec`** (human-readable YAML, boofuzz's shape): typed fields (`bytes`, `u8/u16/u32 be/le`, `varint`, `cstring`, `line`, `token { one_of }`, `delim`) and relations `len { of, width, endian, inclusive, adjust }`, `count { of }`, `checksum { algo, over }`. The generic TLV grammar **infers** a `len` relation from captured traffic by testing candidate `{ offset, width, endian, counts, adjust }` descriptors against every message of the seed set and keeping the one that fits all.
- **Mutators**: byte-level (the 27 LibAFL names, hand-rolled, pure, seeded) and structure-aware (`len` desync +/-1/0/max, `count` mismatch, type-byte substitution, delimiter removal/duplication, long string 256/4096/65535, element repetition, checksum invalidation, varint over-length). Structure-aware first, byte-level second, deterministic order under one `rng_seed`.
- **Grammar trait**: `name()`, `default_ports()`, `parse(&[u8]) -> Option<Tree>`, `generate(&mut Rng) -> Message`, `spec() -> MessageSpec`, `classify_reply(&[u8]) -> Reply { ok | protocol_error | unknown }`, `liveness_probe() -> Message` (a benign exchange: `PING`, `version`, `NOOP`, DNS query for `.`, MQTT CONNECT+DISCONNECT, Modbus read-holding-registers of 1 register, FTP `NOOP`), `denylist(&Message) -> bool` (destructive commands refused by construction: Redis `FLUSHALL/FLUSHDB/SHUTDOWN/CONFIG/DEBUG/SAVE`, memcached `flush_all`, Modbus write function codes 5/6/15/16/22/23 and diagnostics 8, FTP `DELE/STOR/APPE/RMD/RNFR/RNTO/MKD`, SMTP `RCPT` to any domain other than the target's own, MQTT `PUBLISH` with retain; the denylist is on and cannot be lifted by a profile, a config key or a confirmation in v2; orchestrator's decision on former open question 1).
- **Oracles**, cheap to expensive: well-formed reply; protocol error token (`-ERR`, `CLIENT_ERROR`, SMTP/FTP 4xx/5xx, Modbus exception `fc|0x80`, DNS RCODE, MQTT connection close); reset/EOF; ICMP unreachable (UDP socket error); silence past timeout; **liveness probe** (new connection, `liveness_probe()` exchange) immediately and after 500 ms; latency outlier (> 5x median of the last 20). Only silence/reset **and** two failed liveness probes, reproduced `reproduce_count` times, become an `l4-crash` issue (`critical`, `firm`); a reproducible protocol-error-with-reset becomes `l4-parser-fault` (`medium`, `firm`); a latency outlier alone is `info`/`tentative`. Retire the element after a finding.
- **Delivery order (Architect's call, by corpus availability in the test target and grammar cost)**: 1 generic TLV (the seeded crash service is length-prefixed; the inference is the lane's spine), 2 RESP (trivial grammar, clear status tokens), 3 Memcached text (same shape, announced-length relation), 4 DNS (`hickory-proto` does the parsing; UDP path), 5 Modbus/TCP (7-byte MBAP, one `len` relation, exception codes), 6 MQTT 3.1.1 (varint remaining length, reserved flags; MQTT 5 properties deferred), 7 SMTP, 8 FTP (stateful line protocols with the lowest crash yield and a data channel we do not open). The first four are the T6 plan's first half; the T10 L4 seeds cover TLV (TCP) and DNS-like (UDP) so the lane has a positive proof before grammar 5.

### D9. Generic additions to `aitm-core`, `aitm-mcp`, `aitm-plugin-rhai`

1. **`aitm-core`: `SendOptions { record: RecordPolicy (always | never), marks: Vec<String>, version: VersionPolicy (auto | h1 | h2 | h2c, default auto) }` and `ProxyClient::send_opts(&self, req, opts) -> BoxFuture<Result<HttpFlow>>`** with a default implementation that calls `send` (so every existing impl compiles). **Owned by T1a** as part of the contract drop (an additive edit to `crates/aitm-core/src/client.rs`; T1b owns the rest of that file afterwards and implements it on `PipelineClient`: guard first, then the sender with the version policy, then insert only when `record: always`, applying `marks` and `is_replay`). Justification: any bulk sender (the PoC runner's control runs, Rhai batteries, the future live audit) needs to send without flooding the store; nothing here is scanner-shaped.
2. **`aitm-core`: `JobBus`** (`pub struct JobEvent { job: String, kind: String, event: String, seq: u64, payload: Value }`, `JobBus::publish`, `JobBus::subscribe() -> broadcast::Receiver<JobEvent>`), exposed as `CommandHost::jobs() -> Option<Arc<JobBus>>`. **`aitm-mcp`**: `McpServer::with_jobs(bus)` spawns a dispatcher that renders each event as `notifications/aitm/job` and fans it out with `fanout_state` semantics; `wire.rs`/`main.rs`/`tui.rs` hand the one bus to every server (agent, in-process TUI, web bridge). Justification: a progress channel any long-running command can publish to (`session.load`, `l4.capture`, `poc.run`); the server renders a kind it does not interpret.
3. **`aitm-plugin-rhai`**: (a) `reg.add_check(meta, closure)` bridge producing a `ScriptCheck: Check` registered into a `CheckRegistry` the engine reads (the `Registry` already carries commands; checks ride a sibling list on `ScriptServices`); (b) the `probe.*` host fns reading a thread-local check context; (c) `http.send` returns `elapsed_ms` and consults a thread-local **client override** (`with_client(Arc<dyn ProxyClient>, || ...)`) so a check's sends route through the job's client; (d) `RunKind::Check` with a configurable budget. Justification: the scripting tier is where scripts are hosted; a check API is a scripting feature, and the override is the generic way to run any script under a caller-supplied client.
4. **`aitm-proto-http`**: `HttpSender` (D8.2) behind the existing alias. **`aitm-proto-l4`**: `icmp.rs` helper (D8.4). Both additive.
5. **`aitm-proto-l4` guard wildcard (T1a; lands first, tiny)**: an L4 scope entry with `interface: "*"` matches a target on any interface. Today `entry_matches_location` in `guard.rs` compares the string literally (`if entry.interface != target.interface || entry.direction != target.direction { return false; }`, `crates/aitm-proto-l4/src/guard.rs:515` at `5eac2a50`); the change is one clause in that function plus its unit test. Justification: an unprivileged socket client (any future L4 tool, not only the scanner) cannot know the egress interface before connecting; the operator authorises a destination, not a NIC. Direction, CIDR, port and capability matching are unchanged, so the wildcard widens nothing else.

No change to `Command`, `Event`, `Flow`, `FlowMeta` or `ProtocolModule`; the only guard change is D9.5's wildcard clause.

## Verification (real targets only, from day one)

For every track, **no fixture, sample-data, snapshot, in-process-model or mock run counts as acceptance evidence or as a regression check**. `cargo test`, `vitest` and `swift test` are the inner loop and the Rust gate; they are never the proof. Acceptance evidence is a real scan, over the real bus, against a real target, observed independently:

- **Targets**: `aitm-testtarget` in `vulnerable` and `patched` modes (every seeded class is asserted both ways), DVWA/bWAPP for the real-world capstone tier, real obscura for browser crawl cells (`AITM_OBSCURA=1`; cells SKIP 77 loudly without it).
- **Surfaces**: TUI driven over its real bus attach (pty), web over the real `/bus` bridge in a headless browser, the macOS `.app` launched for real and driven by its live-bus self-test; each shows progress and issues produced by a real job against a live core, never a fixture row.
- **Observers**: the test target's own request log (which probes arrived, with which payloads), the findings/issue files on disk after a core restart, `scan.status` counters versus the target's request count (within the budget, never above), the target's liveness (the L4 crash service's own downtime log), the push lines a second subscribed `BusClient` received.
- **Cells**: `tests/e2e/scan/test_<track>_<cell>.py`, tagged `# e2e: tier=T1 surface=scan needs=<lane|obscura|l4>`; each AC below names its cell. A cell's expectation of the tool set comes from live `tools/list` reconciled with `EXPECTED_TOOLS`; no cell hard-codes a count.
- **Ledger**: every `scan.*` verb is exercised by at least one cell at a valid role, and the operator/agent asymmetry for `scan.start` is a positive test. The ledger is produced by `tests/e2e/run.py` (T10): after a `scan` run it prints, per `scan.*` verb of D3, the cells that called it and at which role, and reports any verb no cell called.
- A track's plan may not mark a task "done" on unit tests alone when the task has an AC in this list; the Tester runs the named cell and quotes its output.

## Summary

Scanner v2 turns the scanner into a kernel (`aitm-scan-model` + the engine in `aitm-plugin-scanner`) with pluggable lanes (HTTP, WS, L4 packet, L4 stream) plus a native HTTP checks crate (h2 sender, blind and h2 checks) that separate tracks build in their own crates, wired through pre-created slots so no two tracks share a file; an interim HTTP lane over the legacy modules keeps every engine criterion provable until the real HTTP lane lands. `scan.start` returns a job id at once; a background worker on owned handles runs crawl, passive and audit phases under one budget, one deadline and a held confinement token, pushes `notifications/aitm/job` lines through a generic job bus, and can be cancelled. Native and Rhai checks share one metadata-and-verdict contract and are scheduled automatically over v2 insertion points with Burp's priority, intensity, speed and accuracy knobs; timing checks get host-measured `elapsed_ms`. Issues carry severity x confidence, a dedupe key, evidence and an optional PoC-backed finding link; sessions are reused from observed traffic with auth-lost detection. The L4 lanes keep every stimulus under the L4 guard and add non-overridable ceilings, a liveness oracle, bounded reproduction and a destructive-command denylist. The three UIs and the agent consume the same verbs, and every track is accepted only by real scans against real targets.

### Architect's calls (for Matt to approve or correct)

1. Kernel + per-lane crates (plus one checks crate, `aitm-scan-checks-http`, which is not a lane and exposes `checks()`) with T1-created skeleton slots, so lane tracks never touch `crates/aitm/**`.
2. One verb family (`scan.*`), `scan.start` always `Sensitive`, `scan.map` as the `Write`-tier mapping job; the shipped `scan.discover/passive/report` keep their shapes.
3. Cancel only, no pause/resume, in v2.
4. Progress as a generic `notifications/aitm/job` kind over a core `JobBus`, fanned out like state lines to any `flow.subscribe` connection; push is a trigger, poll is truth.
5. `ProxyClient::send_opts` + record policy `issues_only` by default (probes do not flood the store).
6. Rhai `reg.add_check(meta, |point| ...)` with `probe.*` host fns; `add_check` also registers the manual `check.<id>` command; a class is single-sourced (native or Rhai).
7. Severity stays `aitm_poc::Severity` (five levels); confidence `certain|firm|tentative`; dedupe key excludes `check_id`.
8. Issues are the scan's record; `FindingRecord`s only for PoC-reproduced issues.
9. Session reuse applies to probes and the client crawler fully, to the browser crawl best-effort (`document.cookie`), stops the audit on auth loss by default.
10. `HttpSender` negotiates h2 behind the existing alias; raw h2 probe only for observe-only checks; no seeded h2-specific positive.
11. WS dialer is direct (not through the proxy listener), bounded to 4 connections; no compression oracle.
12. L4 stream lane authorises through the **L4 guard** (IP:port) plus a bytes/s pacer; no capture privilege required.
13. Grammar order: TLV, RESP, Memcached, DNS, Modbus, MQTT, SMTP, FTP.
14. L4 crash finding requires silence/reset plus two failed liveness probes, reproduced 3 times, then the element is retired; the denylist is never liftable in v2 (decided).
15. Hard ceilings live in config (`scanner.ceilings`), never in a profile; profile values are clamped and reported.
16. `scanner.allow_agent_l4_fuzz` is a separate agent gate from `scanner.allow_agent_active`, and an agent needs it **and** the existing `l4.allow_agent_inject` for any L4 lane.
17. `intrusive` is operator-only; an agent is capped at `medium` even with `scanner.allow_agent_active` (decided).
18. `scan.discover` stays through v2 as the deprecated synchronous one-shot (`scan.map` + wait); its removal once all three UIs run on `scan.map` is a follow-up (decided).
19. T1b ships an interim HTTP lane over the legacy modules so every T1 criterion is provable standalone; T2 supersedes it by returning `Some` and deletes the legacy modules in its integration task; an unavailable lane is skipped and reported, and `lane_unavailable` fires only when every requested lane is unavailable.
20. The L4 guard gains a generic `interface: "*"` wildcard (D9.5, T1a, one clause in `entry_matches_location`); the stream lane authorises with it.
21. `SendOptions` carries `version: VersionPolicy`; `h2` forced but not negotiated is a counted probe error (`h2_not_negotiated`), never a job failure.
22. Every catalogue entry, native or Rhai, gets a manual `check.<id>` command; the contract lists and the check/command pins are integration-shared files re-pinned by each track's final integration task.
23. PoC reproduction is driven by a `PocHint` the check supplies (assertions + optional control), not by a class list in the engine; `poc_hint` is `#[serde(skip)]` because `aitm_poc::Assertion` has no serde derives.
24. Probe flows never reach the store except via issue re-recording; browser-crawl navigations are real captures marked `scan:<job>` and `crawl` by a bounded store diff.
25. The session canary is GET/HEAD only, body-less, chosen from captured in-scope flows; with none eligible, auth-lost detection is off and reported.
26. T1a declares every new external dependency in `[workspace.dependencies]` so no lane track edits the root manifest.
27. `aitm-scan-checks-http` is a checks crate, not a lane: it exposes `checks()` (empty in the T1a skeleton), which `wire.rs` hands to the engine as `native_checks` alongside the five lanes.
28. L4 dry run stays opt-in (research 18 C5 proposed it as the default first step): the `_confirm` prompt is the safety step and the built-in L4 profiles are capped; `scan.start` reports `dry_run` for L4 jobs so UIs can offer a dry run first.
