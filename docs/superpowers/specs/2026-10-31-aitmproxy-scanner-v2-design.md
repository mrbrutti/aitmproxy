This is an **umbrella** spec: it fixes the shared model, the verb contract, the catalogue contract, the job/issue/session models, each lane at the level of components and seams, and a split into independently buildable tracks with disjoint file ownership. Each track gets its own plan (and, where its plan says so, its own child specs for the detail below this level).

## Intent

The scanner today is three verbs (`scan.discover`, `scan.passive`, `scan.report`) over a browser crawl, two native payload classes and three passive checks; inject, PoC and record run only in tests; the fifteen bundled `check.*` Rhai scripts are operator-invoked one parameter at a time; every long call blocks its bus connection; findings have no dedupe key and no confidence. Matt wants a Burp-Suite-Professional-class scanner for HTTP/1.1, HTTPS, HTTP/2 and WebSocket (crawl and audit, insertion points, profiles, severity x confidence issues, live progress) and an L4 **fuzzer** that looks for defects in protocols and packets themselves, all driven from the three operator UIs and the MCP agent alike, and proven against real seeded targets. Every seam this needs was surveyed in research note 20; the missing pieces are a job model, a push kind, a check catalogue with machine metadata, and the lanes.

## Operator decisions (fixed; recorded as Matt's)

1. Burp-Pro-like scanner for HTTP/1.1, HTTPS, HTTP/2, WebSocket: crawl + audit, insertion points, scan profiles, issue taxonomy with severity x confidence, live progress; plus an L4 **fuzzer** "searching for issues in the protocols or packets themselves".
2. L4 has **both** lanes: a **packet** lane (malformed IP/TCP/UDP/ICMP headers over `PacketSpec` + `l4.send_recv`) and a **stream** lane (new unprivileged TCP/UDP socket client; corpus = captured L4 flows; mutation + grammar generation).
3. Grammar fuzzers for **all** of DNS, MQTT, Modbus/TCP, Redis (RESP), Memcached, SMTP, FTP, and a generic TLV/length-prefixed model inferred from captured traffic. Delivery order is the Architect's call (D8.5 gives it with its rationale).
4. Authenticated scanning = reuse cookies/auth headers observed in in-scope proxied traffic. Recorded login sequences: later milestone.
5. Explicit scans plus the existing live passive detectors. Live **active** audit of proxied traffic: later.
6. The scanner schedules bundled **and** custom Rhai `check.*` scripts and native Rust checks automatically over discovered insertion points: one unified catalogue. Scripts stay human-readable.
7. All three operator UIs get a full Scan surface at parity (profile editor, live progress with cancel, site map / insertion points, issues grouped by severity with evidence + PoC); the MCP agent gets the same via verbs.
8. Proof is the real e2e suite (`tests/e2e`) against seeded targets, not fixtures.

## Goals

- `scan.start` returns a job id immediately; the job runs in the background on owned handles, reports live progress (push + poll), can be cancelled, holds egress confinement and one budget for its whole life, and never blocks a bus connection.
- One **check catalogue**: native Rust checks and Rhai `check.*` scripts (bundled or custom) declare the same metadata (class, insertion kinds, lanes, cost, intensity, technique, typical severity) and return the same structured verdict; the scheduler picks checks per insertion point from that metadata; time-based blind checks get host-measured timing without `sleep`.
- **Insertion points v2**: query, form, nested JSON (typed), XML value/attr, multipart, header, cookie, any path segment, filename, parameter name, entire body; the point owns encoding and `Content-Length`.
- **Issues** with severity x confidence, a dedupe key, evidence, probe flows, optional PoC/finding link, and an operator-settable status; passive issues consolidated per origin.
- **Session reuse** from observed in-scope traffic, with auth-lost detection; session material never appears in a result.
- **HTTP/2** sending (ALPN-negotiated, per-authority cached, overridable) so every HTTP check runs over h2 too, plus observe-only h2-specific checks.
- **WebSocket** active lane: own dialer, frame-field insertion points, CSWSH/auth/injection/oversize checks, and a guarded `ws.*` Rhai namespace.
- **L4 packet** and **L4 stream** fuzz lanes with grammars for the eight protocols, a liveness oracle, bounded reproduction, hard caps and a destructive-command denylist.
- Scan surfaces in TUI, web and macOS at parity, wired to the live core; the same verbs for the agent.
- Seeded `aitm-testtarget` routes and services for every new class and lane, with Vulnerable/Patched modes, and real e2e cells that prove found-on-vulnerable / not-found-on-patched over the real bus.

## Non-goals

- **Live active audit** of proxied traffic (Burp "live audit"): a scan is started explicitly. The shipped passive detectors stay as they are.
- **Recorded login sequences, login macros, self-registration**: session reuse is observation-based only (decision 4).
- **Out-of-band (Interactsh/Collaborator) detection**: no external service, no OOB sink; blind classes use boolean/timing differentials only.
- **Pause/resume of a job** (Architect's call: cancel is enough for v2; pause adds state the UIs must render and a half-held budget; a cancelled job keeps its issues).
- **Exploitation** of anything found: no data extraction past a marker, no second-request smuggling, no DoS confirmation, no crash weaponisation.
- **JavaScript static/dynamic analysis** (Burp's third audit phase) and the permessage-deflate compression oracle.
- **In-path L4 interception** as a fuzz transport (the NFQUEUE path stays as M5 shipped it).
- **Replacing** `scan.discover`/`scan.passive`/`scan.report` in v2: they keep their shipped shapes (see D3) so the shipped UIs keep working while the UI tracks migrate. `scan.discover` is deprecated in v2 (orchestrator's decision on former open question 3) and is removed in a later release once all three UIs run on `scan.map`; that removal is a follow-up outside this spec.
- A seeded **h2-specific positive** in the test target (D8.2 explains why; the h2 lane is proven by h1-class vulns found over h2 and by the observe-only checks' true-negative set).

## Anti-goals

- Any scanner-issued stimulus (HTTP request, WS frame, L4 packet, TCP/UDP datagram) reaching a host outside the operator's HTTP scope or L4 scope, from any caller, in any lane.
- A job that outlives its budget, deadline or cancellation; a verb whose latency is the scan's; a progress line that lies (counters that go backwards or a `done` without a terminal status).
- An agent starting an active or L4 job with the config gate off; a UI that launches an L4 fuzz without the "may disrupt the target" confirmation; a profile that can raise a hard cap.
- A flood-shaped primitive: anything that sends faster than the guard's pacing, more packets than `L4Permit` allows, or keeps hammering a spot that stopped answering.
- A result, issue, push line, PoC, log line or UI cell that carries a cookie, token or auth header the scanner saw.
- Probes evicting real captures from the flow store (issue-only recording is the default).
- A fixture-driven green: any acceptance claim for any track backed by sample data rather than a real scan (see Verification).

## Constraints

- **Rust gate**: `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` before any review; `#![forbid(unsafe_code)]` in every new crate. Default `cargo test` stays hermetic (no sockets, no browser); anything that binds a port runs in the Terminal panel.
- **Deny-by-default stays.** Active lanes are `Sensitive`, scope-gated, rate-paced, budgeted. Agent access to active lanes needs `scanner.allow_agent_active`; L4 lanes additionally need `l4.enabled`, an L4 scope entry with `Inject` capability covering the target (the stream lane authorises with `interface: "*"`, `direction: outbound`, so the operator adds such an entry; D9.5), for an agent **both** `scanner.allow_agent_l4_fuzz` and the existing `l4.allow_agent_inject` (D3 names the same pair), and for every caller the operator `_confirm` handshake whose prompt says the run may disrupt the target. `intensity: intrusive` is operator-only: an agent is capped at `medium` even with `scanner.allow_agent_active` (orchestrator's decision on former open question 2). The L4 destructive-command denylist is never liftable in v2, by any profile, config key or confirmation (orchestrator's decision on former open question 1). Hard caps are not profile-overridable. A crash is a finding to reproduce (bounded N) and record, never to exploit.
- **Core edits are allowed only when generic.** Each `aitm-core`/`aitm-mcp` change is listed in D9 with its justification; none names the scanner.
- **Contract lists are integration-shared.** The **two** contract pins, `crates/aitm/tests/frontends.rs` `EXPECTED_TOOLS` and `crates/aitm-tui/src/lib.rs` `CORE_TOOLS` (the constant only), together with the check-name pins in `crates/aitm/tests/bundled_startup.rs` and the command pins in `crates/aitm-plugin-rhai/tests/bundled_scripts.rs`, belong to **no track** (PR #244 removed the TUI fixture and snapshot mode, so there is no `bus-fixture.json` and no tool-count test to re-pin; amendment 43). Each track's final integration task (the rebase commit right before its PR merges) re-pins them for the verbs and checks that track adds, in merge order; the orchestrator merges one PR at a time so any conflict is one line. `capture.status` and `proxy.system.*` verbs land before ours: every integration task re-pins against live `tools/list` (and any tool-count assertions) rather than assuming the counts in this spec. No track lists these files as exclusive, and no non-integration task edits them.
- **Sequencing pins.** (a) `claude/scanner-vocab-7d36bb` (redaction consolidation into `aitm_core::redact`, editing `discover.rs`, `reproduce.rs`, `redact.rs`) merges first (PR #199); T1 and T2 branch after it and use `aitm_core::redact::{is_secret_key, is_secret_key_wide, scrub_text_wide}` as the single vocabulary (`is_secret_key_wide` is T2's session-trait test, amendment 54); `scrub_embedded` in `reproduce.rs` stays on `scrub_text_wide` (plain `scrub_text` leaks `sid`/`jwt`/`auth`-style pairs). (b) T3 rebases onto PR #195's `ConnInfo` change in `crates/aitm-proto-http/src/module.rs` before touching `aitm-proto-http`. (c) The macOS track requests file claims from the orchestrator before editing `apps/mac`: five sibling sessions hold `Shell/*`, `Session.swift`, `BusService`, Kit `ConnectionSummary`/`FlowSummary`; the Scan panels are unclaimed.
- **Supersessions.** The M5 L4 spec's non-goal "No automated fuzzing/crash-triage engine in the tool" and its sentence "There is no `l4.fuzz` verb and no in-tool crash-triage engine" are **superseded** by decisions 1 and 2. M5's safety argument ("a fuzzing run is many guarded calls, no uncapped path") is replaced by D8.4/D8.5: every stimulus still mints an `L4Permit` per packet (packet lane) or passes `L4Guard::check` per connection and a per-job bytes/packets pacer (stream lane); the engine adds non-overridable ceilings (cases, deadline, consecutive timeouts, element crash threshold, liveness cadence, destructive-command denylist) that a hand-driven loop never had. The active-backend spec (`scan.inject`/`scan.run`/`scan.status` as blocking verbs with a last-campaign snapshot) is **superseded**: its intent (bounded per-class injection, PoC reproduction and recording, one shared budget, confinement for the whole run) is folded into the job model; its verb names are not used except `scan.status`, which is redefined in D3. The scanner-plugin spec's "no edit to `aitm-core`" rule is relaxed per D9. The integration spec's Stage 1 stands; its "progress = poll a running flag" baseline is replaced by D3's push kind. The e2e framework spec (`2026-10-30-aitmproxy-e2e-real-test-framework-design.md`) is **amended**, not superseded: it gains the `tests/e2e/scan/` surface dir, the `aitm_e2e/scan.py` helper, the `scanner:` section in `aitm_e2e/config.py` and the per-verb ledger in `tests/e2e/run.py` (all T10, D12); everything else in it stands.
- **Rhai human-readability** (`docs/research/MEMORY.md`, human-friendly scripting): a check script reads as prose with one declaration map and one closure; no JSON-in-strings, no agent-only encodings.
- **Dependencies**: `tokio-tungstenite` (present per-crate at 0.28) for the WS dialer; `h2` (present in `aitm-proto-http`) for the h2 sender; `hickory-proto` for DNS; `blake3` for the dedupe key; `tokio-util` for `CancellationToken`; `rand` (seedable) for the mutators; everything else hand-rolled (`nom` optional, builder's call). ## Design

### D1. Shape: a kernel, lanes, and one verb family

**(Architect's call)** The scanner becomes a **kernel + lanes** structure so that tracks own disjoint crates:

| Crate | Owner | Role |
|---|---|---|
| `aitm-scan-model` (new) | T1 | Pure types and traits, serde, no I/O: profile, job status, insertion point, check metadata, verdict, issue, session profile, progress, the `Check`/`ProbeHost`/`Lane` traits. Depends only on `aitm-core`, `aitm-poc` (for `Severity` and `Assertion`) and serde. Every other scan crate and every UI fixture consumes it. |
| `aitm-plugin-scanner` (existing) | T1 | The engine: job registry and worker, scheduler, catalogue bridge, issue store, profiles, all `scan.*` verbs, the legacy verbs re-implemented over the job model, and the **interim HTTP lane** (below) over the legacy `crawl.rs`/`discover.rs`/`inject.rs`/`checks.rs`. T2's final integration task deletes those four modules and the interim adapter once `aitm-scan-http::lane()` returns `Some` (the one T2 edit inside this crate, made after T1b is on `main`). |
| `aitm-scan-http` (new) | T2 | HTTP lane: crawler v2 (browser + client), site map, insertion points v2 and request mutation, session reuse, scheduler priority inputs. |
| `aitm-scan-checks-http` (new) | T3 | **Not a lane.** A checks crate exposing only `pub fn checks_with(ssrf, guard) -> Vec<Arc<dyn Check>>`, the gated constructor the binary calls (amendment 15); the T1a skeleton's gate-free `pub fn checks()` is removed by T3 PR 2a so that no constructor can omit the SSRF/private-network gate (amendment 42); the engine schedules its checks over the HTTP lane's insertion points. Native HTTP checks (boolean/timing blind, h2 observe-only, raw-h2 probe); plus the `HttpSender` h2 work inside `aitm-proto-http` and the bundled Rhai scripts in `scripts/bundled/active`. |
| `aitm-scan-ws` (new) | T4 | WS lane: dialer, frame insertion points, WS checks, `ws` `ProtocolLanguage` namespace. |
| `aitm-scan-l4-packet` (new) | T5 | L4 packet lane over `PacketSpec` + `send_recv`; adds `crates/aitm-proto-l4/src/icmp.rs` (ICMP type/code extraction) and the liveness probe. |
| `aitm-scan-l4-stream` (new) | T6 | L4 stream lane: socket client, mutators, `MessageSpec`, the eight grammars, oracles. |

**Registration without shared files.** T1 creates every lane crate as a skeleton (Cargo.toml, `lib.rs` exposing one `pub fn lane() -> Option<Arc<dyn Lane>>` returning `None`, and for `aitm-scan-ws` also `pub fn language(...) -> Option<Box<dyn ProtocolLanguage>>`) and the checks crate `aitm-scan-checks-http` as a skeleton exposing a gate-free `pub fn checks() -> Vec<Arc<dyn Check>>` returning an empty list (it has no `lane()`; T3 PR 2a removes that function, leaving `checks_with(ssrf, guard)` as the crate's only constructor, amendment 42), adds them to the workspace and to `crates/aitm/Cargo.toml`, and wires the calls in `crates/aitm/src/wire.rs` and `main.rs` up front: `wire.rs` collects the five `lane()` results into the lane list and the checks crate's constructor result into `native_checks`, and hands both to `ScannerPlugin` (`ScanServices.lanes` / `ScanServices.native_checks`, D5). T3's final integration commit changes that single `wire.rs` call site to `aitm_scan_checks_http::checks_with(ssrf, guard)` so the raw-h2 observe probes get the SSRF/scope gate of D8.2 (amendment 15: an authorised integration-shared exception; the gate is never unwired on `main`, and if T3 must merge before the call site changes, the raw-h2 checks ship disabled); the arguments are the binary's `cfg.browser.ssrf` policy and the `LateGuard`-bound proxy guard (T3 PR 2a, amendment 24). Each lane's integration commit also bumps the `collect_lanes` count literal in `wire.rs`'s test module (T4 did so in PR #227). After that, a lane or checks track edits **only its own crate** (plus the files named in its row of D12); no lane track touches `crates/aitm/**`, `aitm-core`, `aitm-mcp`, `aitm-plugin-rhai` or the contract lists. A lane whose crate returns `None` (not yet landed, feature off, platform cannot run it) is absent from `scan.checks` and is **not** a refusal on its own: `scan.start` runs the profile's other lanes, reports the skip in `JobStatus.lanes: { requested, run, skipped: [ { lane, reason } ] }` and in its own result, and fails with `lane_unavailable` only when **every** requested lane is unavailable (D3 defines the code). When two lanes register for the same `Lane` value, the engine prefers a lane crate's lane over the interim one.

**Interim HTTP lane (T1b).** So that every T1 acceptance criterion is provable standalone before T2 lands, T1b ships an interim `Lane` implementation inside `aitm-plugin-scanner` over the legacy modules: the shipped browser crawl (`crawl.rs`), the v1 insertion points (`discover.rs`), the two native payload classes (`inject.rs`: reflected XSS, open redirect) and the three passive checks (`checks.rs`), each adapted to the `Lane`/`ProbeHost`/`Check` traits with full `CheckMeta`. It registers for `Lane::http`. T2 replaces it by flipping `aitm-scan-http::lane()` to `Some`; the engine then ignores the interim lane, and T2's final integration task deletes the legacy modules and the adapter. The interim lane adds no new detection and no new verb; it is the v1 scanner wearing the v2 contract. Once T3's native `xss-reflected` and `open-redirect` checks land, the interim lane drops its two legacy active checks, because the natives carry the same ids and the catalogue refuses a duplicate id; the interim passive checks stay, and they stay registered when `aitm-scan-http::lane()` takes the http slot: the three passives (`check.reflection`, `check.security-header`, `check.cookie-flag`) shipped in v0.5.12 as manual verbs and are pinned by the UI tool counts and the T10 bundled-passive regression cell, so their registration is independent of which lane holds the slot and a unit test pins the three ids with the http lane installed (amendment 61, T2 #223). T3 PR 2a makes that edit to the interim lane's check list, an authorised exception to T1b's ownership that the T3 plan records (amendment 24).

**Where a probe goes.** The engine never calls a sender directly. Every HTTP probe goes through the job's `JobClient` (D5), which wraps `aitm_core::ProxyClient` (the `PipelineClient` the binary built: guard, sender, store) and adds budget, pacing, timing, marks and record policy. WS and L4 stimuli go through the lane's own transport, each guarded by the lane's guard (`ScopeRateGuard` by authority for WS; `L4Guard` for both L4 lanes) and metered by the same job budget.

### D2. Shared data model (`aitm-scan-model`)

All types are `Serialize + Deserialize`, snake_case on the wire, and are the **only** shapes verbs emit and UIs parse. Enum wire tokens are listed because UIs and scripts match on them.

- `Lane`: `http | ws | l4_packet | l4_stream`.
- `Intensity` (the safety axis, Burp's): `passive | light | medium | intrusive`. A profile's intensity admits checks with `intensity <= profile.intensity`. `intrusive` requires `_confirm` for every caller.
- `Speed` (request-count axis): `fast | normal | thorough`, maps to payload caps per check (ZAP's strength: e.g. boolean pairs 2/4/8, timing repeats 2/3/5).
- `Accuracy` (retry axis): `fewer_false_negatives | normal | fewer_false_positives`, maps to blind-technique repeat counts 1/2/3 and the confidence floor for recording.
- `InsertionKind`: `query | body_param | json_value | xml_value | xml_attr | multipart_value | multipart_filename | header | cookie | path_segment | path_filename | param_name_query | param_name_body | entire_body | ws_json_value | ws_text | ws_form_param | ws_binary | ws_handshake_header | l4_field` (L4 points are grammar field paths). The shipped `redirect` location becomes a **trait** on a point, not a kind.
- `InsertionPoint`: `{ id, lane, kind, name, path (for json/xml/l4: a dotted/bracket field path), example (redacted per `aitm_core::redact`), flow: Option<FlowId>, site_node: Option<NodeId>, traits: [url | filename | number | email | base64 | json | id | session] , frequency: u32 (how many site nodes carry the same (kind,name)) }`. `session`-trait points are never mutated unless a check declares `targets_session: true` (none in v2).
- `CheckMeta`: `{ id, name, class, lanes: [Lane], kinds: [InsertionKind], intensity, cost: light | medium | heavy (estimated probes per point: <=3, <=10, >10), technique: reflected | error | boolean | timing | handshake | malformed | observe | passive, severity: aitm_poc::Severity (typical), confidence_max: Confidence, needs_baseline: bool, wants_traits: Option<[trait]> (optional; when present the scheduler schedules the check only on points carrying at least one listed trait, unless `speed: thorough`), scope: point | node | origin (default `point`; an `origin`-scoped check runs once per origin, whether or not a point was discovered on that origin (amendment 38, T1b follow-up), and a `node`-scoped one once per site node instead of once per insertion point; amendment 3, T1b), targets_session: bool (default false; no v2 check sets it), cwe: Option<u32>, description, remediation: Option<String>, origin: native | bundled(path) | custom(path) }`.
- `Confidence`: `certain | firm | tentative` (Burp). Technique sets the ceiling: reflected marker in the right context and malformed/handshake with a definitive server reaction may be `certain`; error signature, boolean after repeat, timing after correlated repeat are `firm`; anything inferred once is `tentative`.
- `Verdict`: `{ outcome: vulnerable | clean | inconclusive | error, confidence, evidence: Evidence, detail, poc_hint: Option<PocHint> }`. `detail` is scrubbed with the same `scrub_text_wide` as `evidence.matched` (amendment 67, T1b PR 3). `PocHint { assertions: Vec<aitm_poc::Assertion>, control: Option<ControlHint> }` and `ControlHint { payload: String, expect: Vec<aitm_poc::Assertion> }` (the benign control payload and what its response must satisfy, mirroring `FindingRecord.reproduction.control_passed`) are defined in this crate. A check may report **several findings** from one run (amendment 19): `Verdict` gains an additive, optional per-finding location override (its exact field shape is T1b's call, kept additive so the T1a fixtures stay valid), the Rhai bridge accepts an array of verdict maps (D4), and the engine raises one issue per entry. A check supplies the hint in its verdict; the engine builds the PoC from the probe request with those assertions (D6). `poc_hint` is consumed in-process and never emitted on the wire: `Verdict` is not a verb result, `Issue` does not carry it, and the field is `#[serde(skip)]` because `aitm_poc::Assertion` has no serde derives (verified in `crates/aitm-poc/src/model.rs`) **(Architect's call)**.
- `Evidence`: `{ payload: Option<String>, matched: Option<String> (a scanner constant or an excerpt scrubbed with `aitm_core::redact::scrub_text_wide` **before** it is bounded to 256 bytes (`MAX_EXCERPT_BYTES`), so a secret is never truncated into a fragment the scrubber would miss; amendment 16; the scrub runs on every path that leaves the plugin, the job worker, the Rhai bridge and the manual `check.<id>` verb alike, amendment 56), probe_flows: [FlowId], baseline_flow: Option<FlowId>, timing: Option<{ requested_s: [f32], observed_ms: [u32], baseline_ms: [u32], slope, r, correlated: bool (default false; set by the timing oracle under ZAP's rule: r within 0.15 of 1 and slope within 30% of 1000 ms/s; amendment 2, T1b) }>, diff: Option<{ baseline_len, true_len, false_len }>, l4: Option<L4Evidence> }`. `L4Evidence`: `{ sent_hex, seed_id, rng_seed, mutation_chain: [String], prior_messages: u32, oracle: protocol_error | reset | icmp(type,code) | silence | liveness_failed | latency_outlier, liveness_before: bool, liveness_after: bool, reproduced: (k, n), scope_entry: String }`.
- `Issue` and `IssueSummary`: D6.
- `ScanProfile`: `{ name, target: { origins: [String] (http(s)://host[:port]), l4: [ { ip, port, proto: tcp | udp, grammar: Option<String> } ] }, lanes: [Lane], intensity, speed, accuracy, checks: { include: [id|class|lane:*], exclude: [...] }, crawl: { strategy: fast | normal | thorough, max_depth, max_pages, submit_forms, click_handlers, robots, sitemap, use_browser: auto | always | never }, audit: { kinds: [InsertionKind], ignore: [ { kind?, name_regex?, trait? } ] (at least one key; a rule matches when every present key matches; the default rule set is `[ { trait: session } ]`, which the operator may remove), max_points_per_request (default 64), frequent_point_threshold (default 8) }, session: { mode: observed | none, from_flow: Option<FlowId>, on_lost: stop | continue }, budget: { probes (default 2000), time_s (default 600), check_timeout_s (default 60; the per-check wall budget D4 names, clamped by the config ceiling), max_issues (default 1024), per_host_errors { consecutive (default 10), ratio (default 0.5) } }, http: { version: VersionPolicy = auto | h1 | h2 | h2c (default `auto`; passed to the sender through `SendOptions.version`, D9.1), record_probes: issues_only | all }, ws: { reply_window_ms (default 1500), max_frame_bytes (default 1 MiB) }, l4: { fields: [String] (default empty = the packet lane's full default field table; an entry naming a pinned path (`ipv4.src`, `ipv6.src`, `dst`, the ports; D8.4) or an unknown path makes `Lane::discover` fail with `scan: invalid_profile: ...`, surfaced as the `invalid_profile` code; amendment 4: field T1b, use T5), cases (default 500), reproduce_count (default 3), liveness_every (default 25), consecutive_timeouts (default 20), max_bytes_per_s (default 65536), icmp_pace_ms (default 1100; the spacing of an ICMP-baseline point, clamped **up** to the `l4_icmp_pace_ms_min` ceiling; amendment 46), seeds: [ { flow: FlowId } | { hex } | { base64 } ], dry_run: bool } }`. Hard ceilings live in config, not the profile (D11); a profile value above a ceiling is clamped and reported in `scan.start`'s `clamped` list.

### D3. Bus verb contract

Every verb is a plugin-registered `Command` in `aitm-plugin-scanner` with a `ParamSchema`; results are typed `Value::Object`s whose keys are exactly the model types above. Errors are `anyhow` strings of the form `scan: <code>: <message>` where `<code>` is one of `not_found | busy | out_of_scope | refused_agent | refused_l4 | lane_unavailable | invalid_profile | unknown_check | confirm_required`; the MCP layer surfaces them as `isError` text, so every UI and the harness match on the code token. The codes are `aitm_scan_model::ScanErrorCode` (nine variants, `as_str`, and `parse_message` for the `scan: <code>: <message>` form; `h2_not_negotiated` is a sender error, not a verb code). A lane raises `invalid_profile` by failing `Lane::discover` (or a probe) with a message starting `scan: invalid_profile: `, and `out_of_scope` with one starting `scan: out_of_scope: ` (amendments 4, 5, 9); a packet-lane `l4.fields` entry naming a pinned or unknown path is the first such case. Clamping is not an error (it is the `clamped` list in the `scan.start` result) and cancellation is not an error (it is `JobStatus.state: cancelled`).

The refusal codes a caller is most likely to confuse are defined precisely, and `scan.start` checks them in this order: **`lane_unavailable`** = every requested lane is unavailable, because its crate returned `None` or because the platform cannot run it (for example the packet lane without pcap privilege); a profile with some unavailable lanes and at least one available one is not refused, the unavailable lanes are skipped and reported (D1, D5). **`out_of_scope`** = an HTTP origin of the profile is not in the HTTP scope, or an L4 target is not covered by an L4 scope entry carrying the `Inject` capability (`L4Guard::check(Inject, target)` refused). **`refused_l4`** = the L4 layer is disabled (`l4.enabled: false`), or the caller is an agent lacking `scanner.allow_agent_l4_fuzz` or lacking the existing `l4.allow_agent_inject`. **`refused_agent`** = an agent caller without `scanner.allow_agent_active`, or an agent requesting `intensity: intrusive` (operator-only).

### D4. The check catalogue contract

**Native checks** implement `Check` and are contributed by a lane's `checks()` or by `aitm-scan-checks-http::checks_with(ssrf, guard)` (the `native_checks` slot `wire.rs` fills, D1; amendment 42). **Rhai checks** declare themselves in `load(reg)` with `reg.add_check(<meta map>, <closure>)`, where the meta map's keys are exactly `CheckMeta`'s wire names (`id`, `name`, `class`, `lanes`, `kinds`, `intensity`, `cost`, `technique`, `severity`, `confidence_max`, `needs_baseline`, `wants_traits` (optional), `scope` (optional, default `point`), `cwe`, `description`, `remediation`) and the closure takes one argument, the `point` map (`kind`, `name`, `path`, `url`, `method`, `example`, `traits`). The closure returns a verdict map with the `Verdict` wire keys (`outcome`, `confidence`, `evidence: #{ payload, matched }`, `detail`, and optionally `poc_hint: #{ matchers: [..], control: #{ payload, matchers } }` in the PoC YAML `matchers` vocabulary the PoC loader already parses, which the bridge converts to `PocHint`) or a plain string, which the bridge reads as `inconclusive` with that string as `detail` (so an old-style script never breaks the run). A check may return **several findings** (amendment 19): the closure may return an array of verdict maps instead of one map, and each map may carry `location: #{ path }` (optionally `name`) which overrides the issue's location, so the bridge raises one issue per entry; a native check gets the same through the additive `Verdict` field of D2. Until a script is converted, an origin-level script check yields one issue listing the paths in `evidence.matched`. Missing or invalid meta is a **load error** naming the key (the catalogue cannot schedule what it cannot classify). **(Architect's call)** Every catalogue entry, **native or Rhai**, also gets a manual `check.<id>` command (`{ url, param, value? }`, `Sensitive`) that synthesizes a `query` point and runs the same check, registered uniformly by the engine's catalogue bridge when the check is added, and the manual path hands the check the same `shared()`-capable wrapped host the job worker does (amendments 62, 75) (`add_check` for Rhai; a lane's `checks()` or `aitm-scan-checks-http::checks_with(ssrf, guard)` for native), so the shipped manual verbs survive, a check is written once, and native checks are invocable by hand too. Each new `check.<id>` is a new verb for the integration-shared contract lists (Constraints). **Check ids** are unprefixed (no `check-`/`check.`) and form a namespace distinct from classes (D6): the converted bundled scripts keep the id that was their shipped verb suffix (`sqli`, `ssti`, `command-injection`, `cors`, ... so `check.sqli` keeps working, AC T3-5), and the native `xss-reflected` and `open-redirect` checks replace `check-xss.rhai` and `check-open-redirect.rhai` (amendment 10).

**Probe host functions** available inside a check closure (read the current check context the way `option()`/`finding()` read the call tag; refused with a clear error outside a check): `probe.send(payload) -> #{ status, headers, body, elapsed_ms, flow_id }` (the point is mutated with the payload by the lane: encoding and `Content-Length` are the point's business), `probe.baseline() -> same` (cached per point), `probe.raw(#{ method, url, headers, body }) -> same` (same origin only, for handshake/header checks), `probe.marker() -> String` (unique per call: `aitm` + 8 hex mixing a per-job random nonce into the counter, so a target that knows aitmproxy cannot forge a canary echo; amendment 55), `probe.budget_left() -> int`, `probe.timing_fit(#{ requested_s: [..], observed_ms: [..] }) -> #{ correlated: bool, slope, r }` (ZAP's rule: alternating long/short delays, correlation error 0.15, slope error 0.30; the same `correlated` flag is what the oracle writes into `Evidence.timing`, amendment 2), `probe.levenshtein_ratio(a, b)`. `http.send` gains `elapsed_ms` everywhere (measured around the sender call, independent of the store's `duration`), and inside a check it routes through the job's client (D9.3) so budget, pacing, marks and record policy apply to scripts too.

**Timing without `sleep`.** A timing check sends the delay payload and reads `elapsed_ms`; it never waits itself. The host enforces a per-check wall budget (`RunKind::Check`, default 60 s from the profile's `check_timeout`, not the 2 s hook budget) and a per-probe timeout (`min(remaining, 30 s)`). Repeats are governed by `Accuracy`; the native `TimingOracle` in `aitm-scan-checks-http` is the same algorithm `probe.timing_fit` exposes.

**Scheduling.** For each insertion point the scheduler selects catalogue entries whose `lanes` contain the point's lane, whose `kinds` contain the point's kind, whose `intensity <= profile.intensity`, that match the profile's include/exclude, and (Burp's "skip checks unlikely to be effective") whose class matches the point's traits when the check declares `wants_traits` (e.g. `open-redirect` wants `url`, `path-traversal` wants `filename` unless `speed: thorough`). A check with `scope: origin` is scheduled once per origin, whether or not any insertion point was discovered on that origin (amendment 38), and one with `scope: node` once per site node, however many points qualify (amendment 3). Items are ordered by priority `0.8 x exposure + 0.2 x interest` (research 17 §3.2): exposure = new points the request adds; interest = method (POST/PUT higher), content type (HTML/JSON/XML higher), authenticated (higher). Passive phase runs for all items, then the active phase; within active, `light` checks run before `medium` across all points. A `(kind, name)` with `frequency > frequent_point_threshold` gets `light` checks only (reverts to full on a hit).

**Tier laundering guard.** Scripts' `check.*` commands stay `Sensitive` for manual invocation. Inside a job the gate is the job's: `scan.start` is `Sensitive`, its agent gate was passed at start, and the catalogue runs scripts without a per-call policy decision. That is deliberate and is the reason `scan.start` is `Sensitive` even for a profile that would only run `Write`-grade probes.

### D5. The job model

- **Registry.** `JobRegistry` = `Arc<Mutex<HashMap<JobId, JobEntry>>>` shared by `ScannerPlugin` and every `scan.*` command (the `CaptureRegistry`/`InjectRegistry` shape). `JobEntry { status: Arc<RwLock<JobStatus>>, cancel: CancellationToken, task: JoinHandle<()>, _confine: Option<ConfinementToken>, started_by: { frontend: Frontend, client_label: Option<String> } }`. Job ids are `scan-<8 hex>`.
- **Owned handles.** `ScanServices { store: Arc<dyn FlowStore>, client: Arc<dyn ProxyClient>, guard: Arc<dyn ScopeRateGuard>, browser: Option<Arc<dyn BrowserDriver>>, findings: Option<Arc<FindingStore>>, egress: Option<Arc<EgressConfinement>>, l4: Option<Arc<L4Guard>>, jobs: Arc<JobBus> (D9.2), agent_policy: Arc<dyn Fn() -> AgentPolicy + Send + Sync>, catalogue: Arc<Catalogue>, lanes: Vec<Arc<dyn Lane>>, native_checks: Vec<Arc<dyn Check>> (from `aitm_scan_checks_http::checks_with(ssrf, guard)`, D1), rt: tokio::runtime::Handle }` bound late in `wire.rs` (the `LateHandles` precedent), so `scan.start` only validates and spawns.
- **Start.** `scan.start` resolves the profile, clamps to ceilings, resolves each requested lane to a registered `Lane` (preferring a lane crate's over the interim; the unavailable ones go to `lanes.skipped` with a reason, and `lane_unavailable` fires only when none is left), checks every HTTP origin against the scope guard and every L4 target against `L4Guard::check(Inject, target)` **before** spawning (`out_of_scope`), applies the L4-layer and agent gates (`refused_l4`, `refused_agent`, in D3's order), checks `max_jobs` (default 2) and per-origin single flight (`busy`; `admit` also takes the profile's L4 `ip:port` targets, so a second job on an active L4 target is refused `busy`, amendment 73, T1b PR 3), takes the confinement token, writes `JobStatus { state: queued }`, spawns the worker on `rt`, and returns.
- **Worker phases.** `queued -> crawling -> passive -> auditing -> reporting -> done`, or `cancelled`/`failed` from any phase. `JobStatus`: `{ job, state: queued | running | cancelling | done | cancelled | failed, phase, profile_name, targets, started_by, started_at, finished_at, elapsed_ms, stopped_reason: Option<budget | time | cancelled | session_lost | errors | policy | guard_refused | failed>, probes: { sent, budget, errors, timeouts, rate_waits, by_lane: { lane: sent } }, crawl: { pages, queued, depth, forms_submitted, forms_skipped (additive: forms whose markers look destructive, D8.1; amendment 35), errors (additive: failed crawls, for example a browser crawl that timed out or a crawl whose every request failed; amendments 26, 30, 39), last_error: Option<h2_not_negotiated | connect_refused | tls | timeout | transport | other> (a closed token set, per failed request; the classifier tests the TLS words before `connect` and h2-negotiation failures before transport refusals; amendments 39b, 68, 78) }, points: { found, queued, audited, skipped: { ignored, frequent, limit } }, checks: { scheduled, done, skipped (an origin-scoped item the lane cannot host, with a sample; amendment 69, T1b PR 3), errors, error_samples: [ { check, point, detail } ] (the first N, scrubbed; a check's `Outcome::Error` verdict bumps `errors`, keeps a sample and logs `warn!` once per distinct detail, so an inert lane leaves a trace; amendment 58), running: [check_id] (<= 8) }, issues: { total, by_severity, by_confidence } (an issue counts for this job when the job is in its `jobs`, i.e. it found or re-found it; amendment 27c), l4: Option<{ cases, crashes, liveness_failures, retired_elements }>, session: Option<{ reused: bool, lost: bool, canary: none | { method: GET | HEAD, path }, browser_partial: bool }>, lanes: { requested: [Lane], run: [Lane], skipped: [ { lane, reason } ] }, clamped: [..], error: Option<String> }`. Counters are monotonic. Lanes feed two of these blocks through the `JobCtx` hooks of D2 (amendment 5): `report_l4(L4Counters)` fills `l4` and `report_session_lost()` sets `session.lost`; the engine folds those calls and the `scan: session_lost: ` / `scan: invalid_profile: ` / `scan: out_of_scope: ` error prefixes into the same status. `probes.sent` also counts the units a lane charges through `ProbeHost::charge` for raw or observe-only connections that bypass `probe()` (amendment 16), so a raw-h2 connection is budgeted, paced and visible like any probe. A browser crawl that fails or times out is counted in `crawl.errors` and the client crawler stands in; it is never silent (amendments 26, 30). A job whose crawl fails on every request ends `done` with `stopped_reason`/`error` null, `crawl.errors > 0` and `crawl.last_error` set to one closed token (`h2_not_negotiated | connect_refused | tls | timeout | transport | other`), reported per failed request at client send and at browser load/DOM/return/submit/click; `stopped_reason` is for jobs that stopped early (budget, cancel, session_lost), and a UI shows `crawl.last_error` on a done job with zero points (amendment 39b, which supersedes 39's "never `done` with both null"; h2-negotiation failures classify before transport refusals, amendment 78).
- **Budget and pacing.** One `probes` budget per job across lanes; `JobClient` charges one unit per stimulus, waits on `GuardError::RateLimited { retry_after }` instead of aborting (counted in `rate_waits`), and stops the lane at the per-host error ladder (`consecutive` transport errors or timeouts, or their `ratio` over the last 50). The ladder counts **transport errors and timeouts only**: a 5xx answer to an injection payload is evidence, not a host failure (amendment 40). The browser crawl's navigations are charged against the same budget. The deadline is `started_at + time_s`; every **probe** await is bounded by `min(remaining, 30 s)`, while **discovery** (the crawl of `scan.map` or of `scan.start`) is bounded only by the job deadline and cancellation, never by a per-step clamp (a 30 s clamp on `scan.map` was a defect; amendments 26, 30).
- **Record policy.** Default `issues_only`: a probe is sent via `send_opts` with `record: Never`; when a verdict is `vulnerable` the check's probe and baseline flows are re-recorded into the store (they were kept in memory by the `ProbeHost` for the duration of the check, bounded to 16 per point) with marks `scan:<job>`, `issue:<id>` and `is_replay: true`. `all` records every probe (marked), for debugging a target. Under `issues_only` a probe flow never reaches the store except through that issue re-recording. **Crawl flows are different**: browser-crawl navigations are real captures through the proxy listener (the browser is proxied), so they land in the store as ordinary captures; the lane diffs the store around each navigation (bounded: the flows added between the navigation's start and its settle) and marks each resulting flow `scan:<job>` and `crawl`. Client-crawler `GET`s go through `send_opts` like probes, recorded under the same policy with the `crawl` mark. The crawler's seed fetches (`robots.txt`, `sitemap.xml`) carry the job mark only, never the `crawl` page mark, so `pages_crawled` counts pages and `max_pages` bounds it (amendment 76); they must still carry a mark the record policy recognises (the job mark plus a `seed` kind) or bypass the recorder, so no seed leaves a probe row without an `issue:<id>` in the store (amendment 79, T2 follow-up).
- **Policy re-check.** An agent-started job reads `agent_policy()` at every scheduling step; `Paused` or `ReadOnly` cancels it with `stopped_reason: policy`. Operator-started jobs ignore agent policy.
- **Cancellation.** `scan.cancel` sets the token; the worker observes it between probes and inside every bounded await; the entry moves to `cancelled` with its issues intact; the confinement token drops with the entry.
- **Persistence.** On every terminal transition the `JobStatus` and the job's issues are written to `<findings.dir>/scan/jobs/<job>.json` (when `findings.dir` is set); `scan.list` reads them back at startup.

### D6. The issue model and dedupe

`Issue { id: "issue-<8 hex>", job, jobs: [JobId] (every job that found or re-found the issue; the first entry is `job`, the first finder; amendment 27c), check_id, class, name, severity, confidence, status: open | confirmed | false_positive, lane, target: { scheme, host, port }, location: { method?, path, path_template, kind, name, field_path?, ws_path?, l4: Option<{ ip, port, proto, grammar, field_path, mutation }> }, evidence: Evidence, first_seen, last_seen, occurrences, poc_ref: Option<String>, finding_id: Option<String>, description, remediation: Option<String>, note: Option<String> }`. `IssueSummary` = the same minus `evidence.*` bodies and `description` (it keeps `jobs`).

**L4 location (amendment 29).** For an `l4_stream` or `l4_packet` verdict (the packet lane emits one `SiteNode` per target so its issues fill `location.l4` too; T5 cells PR) the engine's issue builder fills `location.l4` from the point's `SiteNode` (`host`/`port`/`scheme` give `ip`/`port`/`proto`), `grammar` = the node's `path_template` without its leading `/`, `field_path` = `InsertionPoint.path`, and `mutation` = `Evidence.l4.mutation_chain[0]` truncated at its first `(`, which is also the dedupe key's `mutation_class` below (per the T6 child spec S6.3). Owner: T1b follow-up PR.

**Dedupe key** = `blake3(class, scheme, host, port, method, path_template, kind, name, field_path)` for HTTP/WS and `blake3(class, ip, port, proto, grammar, field_path, mutation_class)` for L4 (`field_path` is in the L4 key on purpose: each field path that triggers a seeded bug is a distinct issue, the lane retires by (node, field path), and collapsing them would hide which fields are unsafe, which is why AC T6-4 reads "at least one"; amendment 28); `check_id` is **not** in the key, so two checks for one class on one point produce one issue whose `evidence` is the higher-confidence one and whose `occurrences` counts both. **Passive consolidation**: a `technique: passive` check dedupes on `(class, scheme, host, port)` and lists the paths in `evidence.matched` (bounded). A repeat raises `confidence` to the max seen and `last_seen`; it never lowers. Dedupe is across jobs on one core: a later job that re-finds an issue is appended to `Issue.jobs`, the issue counts in that job's `scan.issues { job }` list and `status.issues` tally, and an `issue` push line fires for it (amendment 27c; before this, a job on a core that had already scanned the target owned none of its re-finds). Severity is `aitm_poc::Severity` (five levels; the shipped findings already use it) **(Architect's call** over Burp's four).

**Class vocabulary (amendments 18, 18b).** `class` is the vulnerability **family** and the dedupe unit; the technique (error, boolean, timing, ...) lives in `CheckMeta.technique` and in the evidence, never in the class token. The tokens:

| Class token | Family | Notes |
|---|---|---|
| `reflected-xss`, `stored-xss` | cross-site scripting | |
| `sqli` | SQL injection | replaces `sqli-error`; error, boolean and time are techniques of this one class |
| `nosqli`, `ldapi`, `ssti`, `cmdi`, `path-traversal`, `crlf`, `xxe`, `ssrf`, `open-redirect` | the remaining injection and request-forgery families | |
| `cors` | permissive CORS | also used by the origin-level CORS check |
| `information-disclosure` | generic leaks only | never for the origin-level checks below |
| `h2-*` | the observe-only h2 checks | one token per check, as named in D8.2 |
| `cswsh`, `ws-auth-bypass`, `ws-input-reflection`, `ws-oversize-frame`, `ws-subprotocol` | WebSocket | Injection carried over WebSocket frames uses the family tokens (`sqli`, `ssti`, `cmdi`, ...), so an SQLi reachable over HTTP and over WS is one family. These are the names `aitm-scan-ws` shipped in PR #227. |
| `l4-protocol-reaction`, `l4-parser-fault`, `l4-crash` | L4 lanes | `l4-protocol-reaction` is the Info reaction class of D8.4 (amendment 20) |
| `missing-security-headers`, `risky-http-methods`, `exposed-path` | origin-level HTTP checks | distinct tokens so dedupe does not merge them; `exposed-path` raises one issue per path through the per-finding location of D4 |

Check ids are a separate namespace from classes (D4). Several checks may share a class (the Rhai `sqli` check and the native `sqli-boolean`/`sqli-time` all report `sqli`), and the dedupe rule above is what keeps them one issue per point; the "a class is either native or Rhai" rule of D8.2 now applies to check ids, not classes. The WS checks merged in PR #227 predate this decision and carry `cswsh`, `ws-input-reflection`, `ws-oversize-frame`, `ws-subprotocol` and the HTTP family names for the three injection checks, and those names are adopted as the WS vocabulary (Amendment log, row 18).

**Issue vs finding.** Issues live in the scan issue store (`<findings.dir>/scan/issues/<id>.json` + an index). A `FindingRecord` is written **only** when a PoC reproduction ran and passed: for a `vulnerable` verdict with `confidence >= firm` **whose check supplied a `PocHint`** (D2), the engine builds the PoC from the probe request with the hint's assertions (and control, when given) via `StdPocBuilder`, scrubbed with `scrub_text_wide`, runs it exactly once per issue through `StdPocRunner` (bounded, counted against the budget), and records via the existing `record_finding` only when `reproduction.passed`; `finding_id` links back. A verdict without a hint, or whose reproduction did not pass, yields an issue only. The engine holds no class list; the hint is the contract. The PoC file is written through `aitm-poc`'s runner under `<findings.dir>/scan/pocs/`, which the runner places in a per-run private subdirectory (`<out_dir>/aitm-poc-<id>-<pid>-<seq>-<nanos>/<id>.poc.yaml`); `poc_ref` names that file. **Known gap (amendments 32, 32b):** `poc.list`/`poc.get` enumerate only the top-level `*.yaml` of `config.poc.dir`, so a scan `poc_ref` is not loadable through `poc.get`, even when the operator points `poc.dir` at the scan pocs dir. The fix belongs to `aitm-poc`'s owner and is not a scanner-v2 track row: `poc.list`/`poc.get` recurse one level into the per-run dirs and take a second root under `findings.dir` (or `poc.dir` defaults to the scan pocs dir). Until then the UIs' "Open PoC" reaches only the fallback toast (D10, AC UI-2). The shipped checks for `reflected-xss`, `open-redirect`, `sqli` (the error-technique script), `ssti`, `cmdi`, `path-traversal`, `crlf` and `xxe` **MUST** supply a hint (T3 owns that; the interim lane's two native classes supply one so T1-10 is provable before T3). `scan.report` renders findings and issues; the UIs' Findings surfaces keep showing `FindingRecord`s and the Scan surfaces show issues.

### D7. Session reuse (observed-session mode)

`SessionProfile { origin, cookies: [name], headers: [name], source_flow, observed_at, canary: none | { method: GET | HEAD, path, expected_status } }`. At `scan.start` with `session.mode: observed` the engine picks the newest in-scope **captured** (not replay) flow to each origin that carries a `Cookie` header or a header whose name `is_secret_name` matches (`Authorization`, `X-Api-Key`, ...), or the flow named by `from_flow`. Values are held only in the worker's memory and applied to: every HTTP probe and baseline (header merge: probe-specific headers win, session cookies merged by name), the client crawler (D8.1), and the browser crawl via `document.cookie` for non-HttpOnly cookies (an HttpOnly session cookie cannot reach the browser; the status reports `session.browser_partial: true`; recorded login sequences are the later fix). **Auth-lost detection**: the canary is **GET or HEAD only** and never carries a body: it is the newest in-scope captured `GET`/`HEAD` flow to the origin that carries the session material, replayed unchanged; the **reported** `canary.path` drops the query string and masks `id`/`uuid`/`oid`/token-like segments (amendments 25, 54, T2). Flows the scanner produced itself (`crawl` or `scan:<job>` marks) are never chosen by the session search; `from_flow` is exempt (amendment 54). `from_flow` must itself be `GET`/`HEAD`; otherwise the engine falls back to that rule and reports the substitution in `JobStatus.session.canary`. With no eligible flow, `session.canary: none`, auth-lost detection is **off**, and `JobStatus.session.canary` says so. Every 25 probes the canary is sent; a status class change (2xx -> 3xx/401/403) sets `session.lost` and, per `on_lost`, stops the audit (`stopped_reason: session_lost`, default) or continues. Session-material points carry the `session` trait and are skipped as insertion points (an `ignore` rule the operator can lift by excluding the trait in `audit.ignore`). A cookie or header carries the `session` trait only when its name, or its JSON/XML path, is secret-looking (`is_secret_key_wide`); membership in the session material withholds only the point's `example` (amendments 25, 54, T2); the default `audit.ignore` rule `[ { trait: session } ]` is what counts such points (cookie `sid`, `Authorization`, token-like parameter names) in `points.skipped.ignored`, and the engine itself never excludes the canary's point; only the `audit.ignore` rule does (amendment 36). Seeding rule, also in `docs/scanner.md` "Session reuse" (amendment 36): a fabricated `Authorization: Bearer` header in the seed flow makes every probe unauthenticated against a cookie-session target; seed the session on `/` with the `Cookie` only. `scan.session.preview` shows names only; no verb, push, issue, PoC or log carries a value (AC T2-6). In the lane structure the **HTTP lane drives the canary** (T2: it owns the session material and the probe path) and reports loss through `JobCtx::report_session_lost()` or a probe error prefixed `scan: session_lost: `; the engine applies `on_lost` and writes `session.lost` and `stopped_reason` (amendment 5).

### D8. Lanes

#### D8.1 HTTP lane: crawler v2, site map, insertion points v2 (T2)

- **Crawler v2** has two engines behind one `Crawler` trait: the **browser** engine (existing `BrowserDriver` navigation plus, new, bounded `click` on pointer-clickable elements and `type`+submit on forms with inert values; `strategy` sets depth/pages/forms/click limits; forms whose markers look destructive (delete/remove/logout-style) are skipped and the skip is counted in `JobStatus.crawl.forms_skipped`, never an error; the exact marker list is in #232's Review-log row; amendment 35) and a **client** engine (plain `GET`s through the `JobClient` with an HTML link/form extractor that also harvests `data-href` attributes; no JS; amendment 25). `scan.map` runs this same crawl, forms included when `crawl.submit_forms` is set (amendments 25, 30). `use_browser: auto` uses the browser when available and falls back to the client; both honour `robots` and `sitemap` options, treat fragments with `/ \ ? = &` as routing, and fingerprint pages by normalised DOM/body hash so volatile content does not loop. Browser navigations are real proxied captures; the lane marks the flows each navigation produced `scan:<job>` and `crawl` by the store diff of D5, so every flow a job adds to the store carries `scan:<job>` (AC T1-9).
- **Site map**: `SiteNode { id, method, scheme, host, port, path_template (numeric -> {id}, UUID -> {uuid}, 24-hex -> {oid}), flows, params: [(kind,name)], auth: bool }`; built from crawl results and from **already captured in-scope flows** to the origin (so proxied traffic seeds the audit without a crawl).
- **Insertion points v2**: `enumerate_v2(flow) -> Vec<InsertionPoint>` covering every `InsertionKind` of D2 for HTTP, nested JSON with typed replacement (a number stays a number unless the payload is non-numeric, then a string), XML values and attributes, multipart values and filenames, every path segment and the filename, parameter names (only at `intensity >= medium`), entire body for **every** body, including recognised JSON/XML documents, flagged `structured: true` so value-level checks skip it through `wants_kinds` (document-level checks, `xxe`'s DOCTYPE injection and `nosqli-json`'s operator objects, cannot be expressed from value points and must not re-parse documents themselves; amendment 65, T2 follow-up), with a per-request cap `max_points_per_request` (default 64, Burp's rule; skipped points counted). Every point carries the D2 `traits` the lane derives (`url`, `filename`, `number`, `email`, `base64`, `json`, `id`, `session`; unit-pinned, no live trait cell), without which `wants_traits` checks run only under `speed: thorough` (amendments 63, 65). `build_request(point, payload, mode: replace | prefix | suffix) -> HttpRequest` is the single mutation function: it re-serialises form/JSON/XML/multipart, re-encodes query/path, and recomputes `Content-Length`; `Header`/`Cookie`/`PathSegment` are mutable (fixing research 20 §3.5).
- The lane's `ProbeHost` wraps `JobClient`, lends it through `client()` and charges raw units through `charge()` (amendment 72, #295), applies the session profile, measures `elapsed_ms`, caches the baseline per point, and bounds bodies at 1 MiB for matching.
- Redaction: every `example` and every excerpt in `Evidence.matched` passes `aitm_core::redact` (post-#199 vocabulary).

#### D8.2 HTTP/2 sender and HTTP checks (T3)

- **`HttpSender`** replaces `Http1Sender`'s behaviour behind the same construction site: it offers ALPN `[h2, http/1.1]`, caches the negotiated protocol per authority (TTL 10 min), dispatches to the h1 path or an h2 path built on `h2::client::handshake` exactly as `h2.rs`'s outbound path does (one connection per authority reused while idle, closed on error), converts via `translate`, and reads `SendOptions.version` (`VersionPolicy`, D9.1): `auto` = ALPN-negotiated and cached per authority; `h1` forces the h1 ALPN; `h2` forces h2 and, when the peer does not negotiate it, returns the sender error `h2_not_negotiated`, which the engine surfaces as a probe error (counted in `probes.errors`, feeding the per-host error ladder) and never as a job failure; `h2c` does prior-knowledge cleartext h2. `HttpResponse.version` records what the sender observed on the wire (the stored request is the caller's, so the T3-1/T3-2 oracle is `flow.detail`'s `response.version`; amendment 1). `Http1Sender` remains as a type alias so `wire.rs` is untouched **(Architect's call)**. Response caps stay (60 s, 16 MiB).
- **Raw h2 probe**: a tiny frame writer/reader (preface, SETTINGS, one HEADERS with hand-encoded HPACK literals, read until response/`RST_STREAM`/`GOAWAY`, close) used only by the observe-only h2 checks, because the `h2`/`http` crates refuse malformed headers by construction. It opens at most one connection per check and never more than 8 streams (the target's per-connection `requests` and `streams` counters witness every connection, `streams` counting rejected and cancelled heads too (amendment 51), with the driver's pre-dial cap `RawH2Plan.streams` as the second guard; AC T3-3, amendments 14b, 51). **Security note (amendments 8, 15, 16).** A raw-h2 observe-only probe bypasses the guarded client, so three rules bind it: (a) it may accept any server certificate **only** when opened to the same authority after `host.baseline()` has passed through the guarded client for that point, and it never carries session headers; the security reviewer signs this per PR; (b) it dials the address the guarded baseline validated, via the default-bodied `ProbeHost::baseline_peer_addr() -> Option<SocketAddr>` (T1b), so there is no DNS-rebinding window between the scope check and the connect (amendment 52 made every raw-h2 check Inconclusive with the hook `None`; amendment 59 rules that, until `HttpResponse.peer` reaches `server_conn.peer` (D9.1), the `None` branch falls back to the gated name resolution, the SSRF gate plus a live scope permit per resolved address, with a `tracing::warn` and the verdict detail "dialled by name (baseline peer unknown)", so the five `h2-*` checks never regress on `main`; the strict peer dial engages automatically once 59's core half lands, and the fallback stays as the defensive path), and the checks are constructed through `aitm_scan_checks_http::checks_with(ssrf, guard)`, which the binary's `wire.rs` calls (T3's integration commit; if T3 merges before that call site changes, the raw-h2 checks ship disabled; never unwired on `main`); (c) every raw connection spends job budget through `ProbeHost::charge(units)` so it is paced and counted in `scan.status.probes` (`h2-settings-observe` charges 1, so the five checks' `probes.sent` per authority read 1/8/3/2/2).
- **Native checks** (all `Check` impls): `sqli-boolean` (control re-send, AND-true must match baseline, AND-false must differ, OR-true variant, repeats by `Accuracy`; `firm`), `sqli-time` and `cmdi-time` (alternating 1 s/3 s (or 2 s/5 s at thorough) delay payloads per DB/shell family, `TimingOracle`, at most 4 probes per family; `firm`), `xss-reflected` (shipped, upgraded: context-aware marker, HTML content-type rule; its `kinds` include `cookie` so the seeded cookie reflection is found; amendment 25, T3 PR 2a; `certain`), `open-redirect` (shipped; `certain`), `h2-pseudo-header-validation`, `h2-header-crlf-tolerance` (name and value), `h2-cl-te-downgrade-indicator` (single off-by-one `content-length` / `transfer-encoding: chunked` header probe, detect-only, never a second request; `tentative`, `info` severity unless the response desyncs visibly), `h2-rapid-reset-mitigation` (<= 8 open/reset pairs; reports `info` "no reset-rate mitigation observed" or clean), `h2-settings-observe` (reads advertised SETTINGS; `info`). The five `h2-*` checks are `scope: origin` (D2) and run once per origin, and the blind timing oracle (`blind_timing`) writes `Evidence.timing.correlated` (amendment 24, T3 PR 2a). The DoS-adjacent checks are `intensity: medium` and never `intrusive`.
- **Rhai checks**: the fifteen bundled `active/*.rhai` scripts are converted to `reg.add_check` with full metadata and multi-kind support via `probe.send` (they stop building `?param=` URLs by hand), plus new `check-nosqli-json` (json_value kind), `check-header-reflection`, `check-cswsh` lives in the WS lane. **Check ids** stay single-sourced: a check id is either native or Rhai, never both; converted scripts keep their shipped verb suffix as the id (`sqli`, `ssti`, `command-injection`, ...), and the native `xss-reflected`/`open-redirect` replace `check-xss.rhai`/`check-open-redirect.rhai` (amendment 10). Classes are the family tokens of D6, shared across techniques (the Rhai `sqli` check reports class `sqli` with `technique: error`; the native `sqli-boolean`/`sqli-time` report the same class with `boolean`/`timing`) and dedupe into one issue per point (amendment 18). `scripts/bundled/README.md` is corrected (`script.findings`, the catalogue section, the `add_check` shape).
- Why no seeded h2-specific positive: a detect-only desync or malformed-pseudo-header positive needs a lax h2 server, and every Rust h2 server (`h2`, hyper) rejects those frames itself; building a hand-rolled permissive HPACK server for the test target is out of proportion. The h2 lane is proven by the h1-class seeds found over h2 and by the observe-only checks' exact expected set on hyper (true negatives).

#### D8.3 WebSocket lane (T4)

- **`WsDialer`**: `tokio-tungstenite` client with a rustls `Connector`; `dial(handshake: &HttpFlow, overrides: HandshakeOverrides) -> WsConn`. It replays the captured handshake's headers except `Host`, `Connection`, `Upgrade`, `Sec-WebSocket-Key`, `Sec-WebSocket-Version` (regenerated) and never sends `Sec-WebSocket-Accept`; keeps `Cookie`, `Origin`, `Authorization`, `Sec-WebSocket-Protocol`, `Sec-WebSocket-Extensions` and custom headers unless an override replaces or strips them. The dial authority passes `ScopeRateGuard` (`check_active` by authority) and the job budget (one unit per dial, one per frame sent). At most 4 connections open per job at once; each closes at the end of its probe; ping/pong and close are handled by the dialer; a conversation is recorded as a `WsFlow` with `is_replay` only under the record policy of D5.
- **Insertion points**: from each captured client->server text frame of the handshake's `WsFlow`: JSON leaves (`ws_json_value`, typed), URL-encoded pairs (`ws_form_param`), else the whole text (`ws_text`); binary frames become one `ws_binary` point (byte mutators, `medium` only); handshake headers become `ws_handshake_header` points (`Origin`, `Cookie`, `Sec-WebSocket-Protocol`).
- **Probe semantics**: `probe.send(payload)` dials, replays the client frames that preceded the chosen frame (the boofuzz prerequisite idea), sends the mutated frame, collects server frames for `reply_window_ms`, closes. The oracle sees `ws_frames`.
- **Checks**: `cswsh` (dial with a foreign `Origin` and the session cookies: upgrade completes and the first server frame matches the authenticated baseline frame -> `high`/`certain`), `ws-auth-bypass-handshake` (dial with `Cookie`/`Authorization` stripped: still 101 and authenticated-looking data -> `high`/`firm`), `ws-input-reflection` (marker in a field reflected unencoded in a reply frame -> `medium`/`certain` for HTML-ish reflection, `low` otherwise), `ws-sql-error`, `ws-ssti`, `ws-cmdi-echo` (reuse the HTTP payload sets and signatures through the WS oracle), `ws-oversize-frame` (one frame at `2 x max observed`, capped by `max_frame_bytes`; reset or error vs accept; `info`/`firm`; `medium`), `ws-subprotocol-observe` (`info`). No compression oracle.
- **`ws` Rhai namespace** via `ProtocolLanguage` (`api_version "1"`): `ws.dial(#{ url, headers? }) -> handle`, `ws.send(handle, text | blob)`, `ws.recv(handle, timeout_ms) -> #{ frames: [..] }`, `ws.close(handle)`; all `Guarded` through the scope guard; handles bounded (4) and closed when the call ends; a hook (`on_ws_*`) cannot call them (commands and checks only): the language's guards read the run kind through `HostCallContextSource::run_kind()` (D9.3, amendment 6) and refuse a hook caller. Class tokens for the WS checks follow D6 (`cswsh`, `ws-auth-bypass`, `ws-input-reflection`, `ws-oversize-frame`, `ws-subprotocol`, and the family tokens `sqli`/`ssti`/`cmdi` for injection carried over frames; amendment 18).

#### D8.4 L4 packet lane (T5)

- **Plan**: `PacketFuzzPlan { seed: PacketSpec, dst, dst_port, interface, fields: [ { path, mutator } ], expect: ReplyMatch }` where `path` is a `PacketSpec` field path (`ipv4.ihl`, `tcp.flags`, `udp.length`, ..., and `raw` for the `Raw` payload layer of `PacketSpec`, which the lane fuzzes with the byte mutators of D8.5 so that a userland service can observe a case). `dst`, `dst_port`, `interface`, `ether.src/dst`, `ipv4.src`/`ipv6.src` are **non-fuzzable by construction** (scapy's rule; a plan or an `l4.fields` entry naming them, or naming an unknown path, makes `Lane::discover` fail with `scan: invalid_profile: ...`, surfaced as the `invalid_profile` code; amendment 4); source spoofing is refused. The profile's `l4.fields` list (D2) selects which paths are fuzzed; empty means the lane's full default field table. Seeds come from a captured L4 flow's packet (`seeds: [{flow}]`) or from a crafted spec.
- **Mutators** per field type: boundary and interesting values (0, 1, max, max-1, declared-length +/- 1, off-by-one `ihl`/`data_offset`, reserved bits set, invalid checksum, fragment offset with/without MF, TTL 0/1, ICMP type/code sweep in the valid-but-unexpected set), seeded by `rng_seed` so a case replays.
- **Transport**: each case is one `send_recv` through the existing `SendRecvOutcome` path (per-call `Inject`+`Capture` permits; the per-call capture-handle cost is accepted). Added in `aitm-proto-l4/src/icmp.rs`: `icmp_error(&L4Packet) -> Option<(u8, u8)>` so an `Other` reply yields type/code in evidence. Three pre-existing primitive bugs the lane's mutators exposed are fixed under T5's granted `craft.rs`/`sendrecv.rs` extension (amendments 17, 20, 21): `PacketSpec::build()` panicked (pnet `set_payload` assert) when a verbatim `ihl`/`total_length`/`data_offset` shrank the payload window; now the payload is written while the header is well-formed and the verbatim length bytes are stamped afterwards, so a deliberately wrong length ships unchanged and `build()` never panics; `build()` also no longer panics on an oversize (> 65515 B) payload reachable through `l4.craft`/`l4.send`; and `send_recv` takes the reply-correlation protocol from `packet_target(&bytes)` instead of the spec's layers, so a stimulus given as a single `Layer::Raw(frame)` no longer correlates every reply as `Other`. **Two further pre-existing transport defects, found by the T5 live proof on a real Linux kernel (amendments 45 and 49, `docs/research/experiments/2026-11-01-t5-live-proof.md`):** (a) *self-echo invariant*: on loopback the capture `send_recv` opens receives the injected stimulus itself (libpcap on Linux `lo`, BPF on macOS `lo0`); `Correlation` now asks `is_own_stimulus` first in every `ReplyMatch` mode (byte-equal to the stimulus, or same-direction: our destination address, port and protocol) and ignores it, so a reply is never pre-empted by our own frame; a mock backend echoes the stimulus first so unit tests run over the loopback reality. (b) *Linux loopback injects at layer 3*: a frame written at layer 2 on Linux `lo` is sniffable but never processed by the IP stack, so `PcapBackend::inject` on Linux, for a device libpcap flags `IFF_LOOPBACK` (the flag, never the name), reads the frame as Ethernet-framed IP (libpcap reports `lo` as `DLT_EN10MB`), strips the link header and writes the IP packet through a header-included raw socket (`SOCK_RAW` + `IP_HDRINCL`/`IPV6_HDRINCL`, `socket2`, no `unsafe`) to the packet's own destination, cross-checked against the guard's parse of the same frame; the socket lives inside the call and `L4Guard` is unchanged upstream; every other interface and all of macOS keep `sendpacket`. Limitation of that path: Linux `raw_send_hdrinc` rewrites `tot_len` and recomputes the IPv4 header checksum, so `ipv4.total_length` and `ipv4.checksum` mutations cannot be fuzzed on Linux loopback (every other field is delivered verbatim). Prior art: scapy `L3RawSocket`. **Two more, found by the T5 cells on the rig (amendments 66, 77, T5 cells PR):** (c) *strict reply correlation*: `Correlation::classify` under `FiveTuple` accepted any captured frame whose source host equalled the stimulus destination as `Other` when protocol or ports mismatched, so on loopback (every frame is from 127.0.0.1) bus TCP, the target's control HTTP and other cells' UDP read as protocol reactions within ~100 ms and real silence could never be observed on a busy interface; now `Response` = the reversed tuple plus the protocol, `Other` = only an ICMP error whose quoted packet is our stimulus (which also excludes the kernel's port-unreachables for the target's replies to our socketless source port) or a RST from the target port, and everything else is ignored until the window ends; baseline and liveness probes pin `raw` like replays (amendment 66; security review on the diff). (d) *non-blocking capture reads*: `PcapBackend::open_capture` opened a blocking libpcap handle and trusted the read timeout to bound `next_frame`, but on Linux 6.8 + libpcap 1.10.4 a blocking `pcap_next_ex` on an interface where no frame passes the filter never returns, so `await_reply`'s deadline and the capture thread's stop flag were never consulted on a quiet interface (silent cases hung to the 60 s check timeout and `l4.capture.stop` hung on the join; masked by parallel cells keeping `lo` busy); now immediate mode + `setnonblock()`, and `PcapCaptureSource::next_frame` enforces `read_timeout` itself (non-blocking read, 1 ms nap doubling to 20 ms, `Ok(None)` at the deadline), pinned by the ignored rig test `linux_quiet_interface_read_returns_within_the_timeout`; `aitm-l4-helper`'s `PcapWire` has the same blocking handle and is unified per amendment 50 (amendment 77). Each job's stimulus source port is derived from the job id within 16384..32768 (below Linux's ephemeral range 32768-60999), and `scan.start`'s `admit` also single-flights L4 `ip:port` targets (D5), so two concurrent packet-lane jobs never share a stimulus tuple (amendments 73, 73b).
- **Oracle and liveness**: `Response` -> clean; `Other` with ICMP, or a TCP RST -> an **Info-severity issue of class `l4-protocol-reaction`**, one per reacting point, never "no issue" (type/code or `reset` recorded in `L4Evidence.oracle`; a real closed UDP port's port-unreachable and a closed TCP port's RST are the kernel-level positive proofs of the oracle, T5-2a; amendment 20); `NoResponse` -> **liveness probe** (the seed itself unmutated, or a TCP SYN to `dst_port`, expecting the baseline reply) immediately and again after 500 ms; an element whose case plus two liveness failures repeat `reproduce_count` times (spaced 1 s) yields an issue of class `l4-crash` (`critical`, `firm`) and that element is **retired** (boofuzz's threshold). A liveness probe runs every `liveness_every` cases regardless, and the lane stops (`stopped_reason: errors`) after `consecutive_timeouts` silent cases.
- **ICMP-paced points** (amendment 46). When a point's baseline reply class is an ICMP error (the target host's kernel answers for a closed port), the lane **paces** that point: consecutive cases, liveness probes and replays on it are spaced at least `l4.icmp_pace_ms` apart (profile knob, default 1100; hard ceiling `scanner.ceilings.l4_icmp_pace_ms_min`, default 1000, below which a profile value is clamped up and reported in `clamped`). A silent case on an ICMP-paced point is recorded as `no_reply` with the note `icmp_ratelimit` and is **not a crash candidate on its own**; the crash rule (silence/reset plus two failed liveness probes, reproduced N times) is unchanged for points whose baseline is a correlated reply. The kernel reactions prove classification, never a crash, so a closed port can never produce `l4-crash`. The pace supersedes the "immediately and again after 500 ms" probe timing above for an ICMP-baseline point only. Basis: the rig's sysctls (`net.ipv4.icmp_ratelimit = 1000` ms per destination, `icmp_ratemask = 6168` covering destination-unreachable); the live proof itself showed that loopback is **exempt** from the per-peer limit (`icmpv4_xrlim_allow`: "No rate limit on loopback"; 105 unpaced ICMP errors to one address at 73–126 ms on the rig), so the limit and the pace are for remote targets, and the loopback run proved the pace's mechanics (20 of 20 `icmp(3,3)`, 1.1 s wire spacing), not the limit (`docs/research/experiments/2026-11-01-t5-live-proof.md`, sections iii and iv).
- **Why `raw` matters.** The target's kernel drops malformed IP/TCP/UDP headers before any userland service sees them, so header-field cases are expected to yield kernel reactions only (ICMP, RST, silence). The crash oracle's positive proof therefore comes from the `raw` layer against T10's userland UDP payload-crash service (T5-2b), while header cases prove the ICMP/RST classification (T5-2a).
- **Caps** (config ceilings, D11): cases per job <= 5000, pps from the scope entry, `L4Permit` per packet, `max_packets_per_call`, no case larger than `max_packet_bytes`, no fragment series longer than 8, dry-run renders the first 50 cases without sending.
- **Dry run stays opt-in** for both L4 lanes **(Architect's call** on research 18 C5, which proposed dry run as the default first step): the per-caller `_confirm` prompt is the safety step, and the built-in `l4-full`/`l4-stream-safe` profiles are already capped by the ceilings above. `scan.start` reports `dry_run: false` (or `true`) in its result for every job with an L4 lane so a UI can offer a dry run first (D3).

#### D8.5 L4 stream lane and grammars (T6)

- **Transport**: `StreamClient` over `tokio::net::{TcpStream, UdpSocket}` (unprivileged). Authorisation: `L4Guard::check(L4Action::Inject, L4Target { ip, port, proto, interface: "*", direction: Outbound })` per connection/datagram; a target that is a loopback address on one of the core's own listener ports (`L4Guard::self_ports()`) is refused before any socket is opened, as a per-point `scan: out_of_scope: ` refusal that is counted and skipped (amendment 9) **(Architect's call** on research 18 Q10: the L4 guard, because the target vocabulary is IP:port and the operator already declared it there; the lane adds a bytes/s pacer and a per-job connection cap of 4 because `L4Permit` meters packets, not bytes). The lane needs `l4.enabled` and a scope entry with `Inject` capability whose `interface` is `"*"` (the wildcard rule of D9.5, landed by T1a) or the actual egress interface; the operator adds such an entry, and the config reference and UI launch hints say so (D11); it needs **no** capture privilege. Before any connect, the lane refuses a loopback target whose port is one of the core's own listener ports (`L4Guard::self_ports()`), so no socket is ever opened toward the bus, proxy or web listener (amendment 9).
- **Corpus**: (a) captured L4 flows' client->server payload bytes in packet order (per-packet payloads are the message boundaries; no TCP reassembly beyond concatenating in-order payloads of one flow), (b) grammar-generated well-formed messages, (c) operator seeds (`hex`/`base64`). Each seed is parsed by the selected (or port-inferred) grammar into a field tree; unparseable seeds fall to the generic TLV model.
- **`MessageSpec`** (human-readable YAML, boofuzz's shape): typed fields (`bytes`, `u8/u16/u32 be/le`, `varint`, `cstring`, `line`, `token { one_of }`, `delim`) and relations `len { of, width, endian, inclusive, adjust }`, `count { of }`, `checksum { algo, over }`. The generic TLV grammar **infers** a `len` relation from captured traffic by testing candidate `{ offset, width, endian, counts, adjust }` descriptors against every message of the seed set and keeping the one that fits all.
- **Mutators**: byte-level (the 27 LibAFL names, hand-rolled, pure, seeded) and structure-aware (`len` desync +/-1/0/max, `count` mismatch, type-byte substitution, delimiter removal/duplication, long string 256/4096/65535, element repetition, checksum invalidation, varint over-length). Structure-aware first, byte-level second, deterministic order under one `rng_seed`.
- **Grammar trait**: `name()`, `default_ports()`, `parse(&[u8]) -> Option<Tree>`, `generate(&mut Rng) -> Message`, `spec() -> MessageSpec`, `classify_reply(&[u8]) -> Reply { ok | protocol_error | unknown }`, `liveness_probe() -> Message` (a benign exchange: `PING`, `version`, `NOOP`, DNS query for `.`, MQTT CONNECT+DISCONNECT, Modbus read-holding-registers of 1 register, FTP `NOOP`), `denylist(&Message) -> bool` (destructive commands refused by construction: Redis `FLUSHALL/FLUSHDB/SHUTDOWN/CONFIG/DEBUG/SAVE`, memcached `flush_all`, Modbus write function codes 5/6/15/16/22/23 and diagnostics 8, FTP `DELE/STOR/APPE/RMD/RNFR/RNTO/MKD`, SMTP `RCPT` to any domain other than the target's own, MQTT `PUBLISH` with retain; the denylist is on and cannot be lifted by a profile, a config key or a confirmation in v2; orchestrator's decision on former open question 1).
- **Oracles**, cheap to expensive: well-formed reply; protocol error token (`-ERR`, `CLIENT_ERROR`, SMTP/FTP 4xx/5xx, Modbus exception `fc|0x80`, DNS RCODE, MQTT connection close); reset/EOF; ICMP unreachable (UDP socket error); silence past timeout; **liveness probe** (new connection, `liveness_probe()` exchange) immediately and after 500 ms; latency outlier (> 5x median of the last 20). Only silence/reset **and** two failed liveness probes, reproduced `reproduce_count` times, become an `l4-crash` issue (`critical`, `firm`); an **`l4-parser-fault`** (`medium`, `firm`) is a peer that closes with **no** protocol-error token in its reply (empty or unknown) while the immediate liveness probe still passes, reproduced `reproduce_count` times; a protocol-error reply followed by a close is a clean refusal (real Redis and memcached behave so), and MQTT is excluded from this oracle because its specification mandates the close (amendment 11); a latency outlier alone is `info`/`tentative`. Retire the element after a finding.
- **Delivery order (Architect's call, by corpus availability in the test target and grammar cost)**: 1 generic TLV (the seeded crash service is length-prefixed; the inference is the lane's spine), 2 RESP (trivial grammar, clear status tokens), 3 Memcached text (same shape, announced-length relation), 4 DNS (`hickory-proto` does the parsing; UDP path), 5 Modbus/TCP (7-byte MBAP, one `len` relation, exception codes), 6 MQTT 3.1.1 (varint remaining length, reserved flags; MQTT 5 properties deferred), 7 SMTP, 8 FTP (stateful line protocols with the lowest crash yield and a data channel we do not open). The first four are the T6 plan's first half; the T10 L4 seeds cover TLV (TCP) and DNS-like (UDP) so the lane has a positive proof before grammar 5.

## Verification (real targets only, from day one)

For every track, **no fixture, sample-data, snapshot, in-process-model or mock run counts as acceptance evidence or as a regression check**. `cargo test`, `vitest` and `swift test` are the inner loop and the Rust gate; they are never the proof. Acceptance evidence is a real scan, over the real bus, against a real target, observed independently:

- **Targets**: `aitm-testtarget` in `vulnerable` and `patched` modes (every seeded class is asserted both ways), DVWA/bWAPP for the real-world capstone tier, real obscura for browser crawl cells (`AITM_OBSCURA=1`; cells SKIP 77 loudly without it); for the packet lane, a Linux rig as root first and then Matt's Mac through our own `aitm-l4-helper` phase 1 (Open questions, amendments 44, 48).
- **Surfaces**: TUI driven over its real bus attach (pty), web over the real `/bus` bridge in a headless browser, the macOS `.app` launched for real and driven by its live-bus self-test; each shows progress and issues produced by a real job against a live core, never a fixture row.
- **Observers**: the test target's own request log (which probes arrived, with which payloads), the findings/issue files on disk after a core restart, `scan.status` counters versus the target's request count (within the budget, never above), the target's liveness (the L4 crash service's own downtime log), the push lines a second subscribed `BusClient` received, and the core's own log, which the harness keeps on the opt-in `AITM_E2E_KEEP_WORKDIR=1` (amendment 58). An L4 pacing cell measures over a 2 s window or allows max(10 %, 4 KiB) of slack (20480 B over 1 s at the cell's `max_bytes_per_s: 16384`), because speaker receive timestamps jitter under concurrent checks while the lane's pacer is a strict sliding window over its own writes (amendment 31).
- **Cells**: `tests/e2e/scan/test_<track>_<cell>.py`, tagged `# e2e: tier=T1 surface=scan needs=<lane|obscura|l4>`; each AC below names its cell. A cell's expectation of the tool set comes from live `tools/list` reconciled with `EXPECTED_TOOLS`; no cell hard-codes a count. A cell that does not need a browser pins `crawl.use_browser: never` (amendment 25, a T1b-sanctioned edit of T10's cells). The harness sets `AITM_BUNDLED_SCRIPTS=<repo>/scripts/bundled` for every core it spawns (the core finds `scripts/bundled` only through that variable or a dev-checkout fallback relative to the exe, so a /tmp-built binary used to load no bundled scripts), and a cell asserts that `scan.checks` lists a `source: rhai` check on the default build (amendment 60).
- **Ledger**: every `scan.*` verb is exercised by at least one cell at a valid role, and the operator/agent asymmetry for `scan.start` is a positive test. The ledger is produced by `tests/e2e/run.py` (T10): after a `scan` run it prints, per `scan.*` verb of D3, the cells that called it and at which role, and reports any verb no cell called.
- A track's plan may not mark a task "done" on unit tests alone when the task has an AC in this list; the Tester runs the named cell and quotes its output.

## Summary

Scanner v2 turns the scanner into a kernel (`aitm-scan-model` + the engine in `aitm-plugin-scanner`) with pluggable lanes (HTTP, WS, L4 packet, L4 stream) plus a native HTTP checks crate (h2 sender, blind and h2 checks) that separate tracks build in their own crates, wired through pre-created slots so no two tracks share a file; an interim HTTP lane over the legacy modules keeps every engine criterion provable until the real HTTP lane lands. `scan.start` returns a job id at once; a background worker on owned handles runs crawl, passive and audit phases under one budget, one deadline and a held confinement token, pushes `notifications/aitm/job` lines through a generic job bus, and can be cancelled. Native and Rhai checks share one metadata-and-verdict contract and are scheduled automatically over v2 insertion points with Burp's priority, intensity, speed and accuracy knobs; timing checks get host-measured `elapsed_ms`. Issues carry severity x confidence, a dedupe key, evidence and an optional PoC-backed finding link; sessions are reused from observed traffic with auth-lost detection. The L4 lanes keep every stimulus under the L4 guard and add non-overridable ceilings, a liveness oracle, bounded reproduction and a destructive-command denylist. The three UIs and the agent consume the same verbs, and every track is accepted only by real scans against real targets.
