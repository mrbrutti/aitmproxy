## Intent

Each of the three frontends ships a mode that renders sample data instead of a core: the macOS app's `APP_FIXTURES=1` / `APP_SNAPSHOT` / `APP_KIT_GALLERY` / fixture `--selftest` session, the web UI's `?bus=mock` / `vite dev` mock bus, and the TUI's `--fixture` / `--snapshot` recorded bus. They rendered wrong numbers (sidebar counts, Apps) and let broken builds look healthy. This change deletes every such mode from the shipped code, every tool and document that tells someone to run one, and every test whose subject was the sample set, so that nobody can cite a fake-data run again. Verification of a frontend from now on is the real frontend against a real core with real traffic, plus unit tests of pure logic whose inputs are written in the test.

## Goals

- No shipped binary or bundle in `apps/mac`, `apps/web` or `crates/aitm-tui` can render sample data or accepts a fixture flag, query parameter or environment variable.
- Every frontend has one documented gate made only of: unit tests with inline inputs, source tripwires, and the real frontend on a real core with real traffic.
- The pure-logic unit tests that used the sample rows as inputs keep running, on a copy of those rows that lives only inside a test target and can never reach a user.
- The live paths behave exactly as before, except the handful of places where a fixture fallback was reachable on the live path; each of those is listed in Design D3 with its reason.
- The three source tripwires in `apps/mac/tools` stay honest (no `expect`/`has` on a file that no longer exists) and exit 0.

## Non-goals

- Renaming `CoreID.fixture` (the id for rows that did not come over a bus: imports, tests). It is not a mode; its doc comment is reworded here and the rename is a follow-up card.
- Changing the web UI's tolerant decoding in `src/bus/normalize.ts` and `src/bus/types.ts`, or the `scope.list` tolerance in `src/state/app.ts`. They accept the wire shape and a model shape; that is defensive decoding, not a fixture mode, and changing it is out of scope. Only their comments change.
- Replacing the deleted TUI bus-task tests (`tester_bus_task.rs`) with a scripted-transport harness. A follow-up card (Open question Q3).
- Rewriting history: `apps/mac/docs/FIXLOG.md`, `review-2026-10-31.md`, `architecture-review-*.md`, `ARCHITECTURE-REVIEW-M1.md`, `ANIMATION-AUDIT.md`, `animation-plans/*`, `docs/testing/**`, old specs and plans, `docs/design/operator-ui-foundation.md` §2.10, and the acceptance records of done stories in `apps/mac/docs/STORIES.md` other than the lines named in D9 keep their words.
- New live tooling. `tools/selftest-live.sh`, `tools/selftest-live-embedded.sh`, `tools/cua-ne-drive.sh`, `scripts/selftest-live.mjs`, `crates/aitm/tests/tui_live_bus.rs` already exist and become the gate as they are.
- The L4 parity work. Its plan already assumes this change (`R`) and rebases on each frontend's merge SHA.

## Anti-goals

- A "temporary" or "dev-only" sample path surviving under a new name (a `--demo` flag, a `DEV` branch in `createBus`, a seeded store). Rule 1 of the brief: nothing shipped may render sample data or accept a fixture flag or env after this.
- A green unit suite that passes because it asserts the shape of the sample set it was given (`rows.count == 14`, "the fixture offers exactly the 59 core tools"). Such tests are deleted, not moved.
- Breaking a real path to make the deletion easier: a live self-test that now hangs on an alert, a dev bundle that seeds pins into a shared store, a `FlowActions` that silently mutates the session before the bus is installed.
- A tripwire script that still "passes" because a removed `has` line was replaced by nothing and the PASS count silently fell, or that fails because it pins a file that is gone.
- A PR body that cites a snapshot, gallery, mock or fixture run as evidence. Rule 6: every PR proves the real app with a real core and real traffic.

## Constraints

- **Sandbox.** Coders cannot run SwiftPM, bind ports or reach GitHub. Swift compiles happen in the Terminal panel by the orchestrator between mac tasks, and compiler output comes back as a fix task. `cargo` works offline in the sandbox; `cargo test -p aitm --test tui_live_bus`, `aitm web`, `aitm tui` against a bus, the mac bundle, `npm ci`, `git push` and `gh` run in the Terminal.
- **Gates must stay green.** `swift test` (Terminal), `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`, and `npm run typecheck && npm test` pass at the end of every task that claims a gate, and CI stays green. A deleted test that leaves an unused import behind is a clippy error.
- **Three PRs against `main`, opened in this order: web, TUI, mac** (the orchestrator's sequencing of 2026-10-31: the L4-parity, ca-trust and system-proxy PRs wait on the web and TUI merges; the mac PR follows them and goes before the other pending mac PRs). Branches: mac = `claude/nice-pare-a04795` in the worktree root `/Users/matt/Security/aitmproxy/.claude/worktrees/nice-pare-a04795`; web = `chore/no-fixtures-web` in `.wt/web`; TUI = `chore/no-fixtures-tui` in `.wt/tui` (both nested worktrees already exist at `c8cf56a5`). The three groups are file-disjoint and fan out. The mac PR goes before the other pending mac PRs, and the orchestrator receives the mac file list before the PR opens (A-PR coordination, brief "Sequencing"). The L4 parity plan's `R` is each frontend's merge SHA; the orchestrator sends it on.
- **Keep the isolation foundation.** `SettingsDomain`'s isolated, wiped defaults suite under `APP_STORE` / `APP_LIVE`, the `Store.isOverridden` guards, `Store.defaults` and `Store.url` stay exactly as they are: they are what lets a dev bundle run a real core without touching Matt's settings, and the live gate stands on them.
- **Keep the live self-test's scaffolding.** `SelfTest+Live.swift` depends on the `--selftest` entry point and on `settle` / `check` / `finish` / `armWatchdog` in `SelfTest.swift`. Only the fixture checks and the fixture store seeding go.
- **The language conformance data is not UI sample data.** `docs/design/languages/*.conformance.json`, consumed by `apps/web/scripts/gen-langs.mjs` (lines 58–76), `apps/mac/tools/gen-langs.swift` and `crates/aitm-tui/tests/complete.rs`, is the shared completion contract of the three surfaces. Untouched.
- **No new dependencies** in any of the three trees.
- **Evidence before claims.** Every "done" quotes the command and its output (`superpowers:verification-before-completion`).

### D3. Live-path behaviour changes

Every other `usesFixtures` collapse is a no-op on the live path (the live arm is kept verbatim). These are the places where a fixture fallback was reachable live, or where the live self-test changes. Each is deliberate.

1. **`Session.actions` before the bus is installed** (`Session.swift` 224: `lazy var actions: any FlowActions = FixtureActions(session: self)`). Replaced by `final class OfflineActions: FlowActions` in `Bus/FlowActions.swift`, every method `throws BusError.disconnected` (`OfflineActions` has no stored state; **Architect's call**: no `session` parameter, it needs none). `ShellView` installs `BusService` in `.task` before any user action can land, so the only observable difference is that an action in that window surfaces "the bus connection closed" in the status bar (via `Session+Verbs` `lastError`) instead of silently mutating the session.
2. **Edit & Replay without a loaded detail** (`Session+Editing.swift` 16: `details[id] ?? Fixtures.detail(for: row)`). Now `guard let detail = details[id] else { lastError = "Flow detail not loaded yet — select the flow and try again"; return }`. The live path fetches the detail on selection (`ensureDetail`); a missing detail must not be invented.
3. **PoC parameter candidates without a loaded detail** (`Panels/PocSheets.swift` 98: `session.details[flowID] ?? Fixtures.detail(for: row)`). Now `guard let detail = session.details[flowID] else { return [] }`: no candidates until the real detail is there.
4. **`poc.build` results** (`Panels/FindingsPanel.swift` `resolveBuilt`). Never synthesize YAML. `resolveBuilt` `throws` (amended 2026-11-01 after the quality review, which replaced the first draft's empty-string sentinel): a path that cannot be read → `PocBuildError.unreadable(path)` ("could not read <path>"); neither YAML nor a path → `PocBuildError.noYAMLOrPath` — a file-private `LocalizedError`, since these are the app's own judgements, not something the core reported. The caller's existing `catch` shows `build PoC: <message>` in the status bar and inserts no finding.
5. **The live self-test gains the S-069 menu audit.** The two refusals (no `APP_STORE`; no `APP_LIVE=1`) are evaluated in `AppDelegate.applicationDidFinishLaunching`, right after `armWatchdog()`, BEFORE any window, `BusService`, the connection model's `activate()` or `ExtensionController` exists (`NSApp.activate()`, which only brings the process to the foreground, may precede them) — `SelfTest.refusal() -> String?` returns the message, the delegate prints it and `exit(1)`s (security review 2026-11-01: with the fixture arm gone, a refusal evaluated inside `ShellView.task` would have activated the live stack on the operator's real defaults first). `runIfRequested` keeps the same two guards as a second line of defence. The `APP_LIVE=1` refusal text: `print("SELFTEST refused: the fixture self-test was removed on 2026-10-31; run tools/selftest-live.sh (APP_LIVE=1)"); finish(code: 1)`. `runLive` (`SelfTest+Live.swift`) calls `checkMenuCoverage()` and `await checkTypingIsNotAVerb(session)` right before `finishLive()` on its happy path, so the menu bar is still audited on every self-test run. `checkTypingIsNotAVerb` asserts `rows.count` unchanged and works on a live session. The two helpers lose `private` (they are `private static` in `SelfTest.swift` 498 and 516; Swift `private` is file-scoped, and `runLive` lives in another file). Open question Q1 (default: include).
6. **Self-test-only: the import-refusal alert.** `Session+Transfer.swift` 70, `guard !Store.usesFixtures else { return }`, becomes `guard !SelfTest.requested else { return }`. On a normal launch both guards were false, so the alert shows as before. Under `APP_LIVE=1 --selftest` the old guard let a modal `NSAlert` open and hang the run; the new one suppresses it. The same substitution applies to the capture guards (`Bus/CoreHealthState.swift` 68–70, `Bus/ExtensionController.swift` 125–127): `guard !SelfTest.requested else { return false / return }` — the live self-test must still never start the extension, and `APP_SNAPSHOT` no longer exists to check.

7. **`poc.run` results without a verdict** (`Panels/FindingsPanel.swift` `run(_:target:vars:)`, line 99: `result.objectValue?["passed"] != nil ? result : syntheticResult(for: finding)`). Found by the M1 Coder, amended by the orchestrator on 2026-10-31: when the core's `poc.run` answer carries no `passed` field, the app invented a **passing** finding with every assertion `matched: true`. Now: no finding is inserted, `session.lastError = "poc.run returned no verdict (no passed field)"`, and `syntheticResult(for:)` is deleted. The same rule as item 4: never synthesize a result.

8. **The removed switches fail closed** (security review 2026-11-01, orchestrator's call mirroring the TUI's `unknown argument` exit 2): a launch with `APP_FIXTURES`, `APP_SNAPSHOT`, `APP_SNAPSHOT_PAGES`, `APP_KIT_GALLERY` or `APP_L4_EMBEDDED` set prints `<VAR> was removed on 2026-10-31 with the fixture modes; see apps/mac/CLAUDE.md` and exits 1 in `applicationDidFinishLaunching`, before any window or live stack. Without this, a stale invocation from a script, alias or memory note would silently run the full live app on the operator's real defaults. A Kit pure function (`RemovedModes.refusal(environment:) -> String?`) carries the list and is unit-tested.

Web and TUI have no live-path change: `onFlowEvent` is already the trigger path on a real bus, `startPolling()` already ran on every real address, and `aitm tui` (in-process) does not touch the deleted code. Two developer-facing changes, by design: `vite dev` now talks to a running `aitm web` through the `/bus` proxy (`vite.config.ts` 5–7, `AITM_WEB`) instead of a mock (Open question Q6), and `aitm-tui --fixture` / `--snapshot` are unknown arguments.

## Summary

This change deletes every fake-data mode from the three frontends — the macOS fixture/snapshot/gallery session and fixture self-test, the web mock bus and its `?bus=mock` / `vite dev` fallback, the TUI `--fixture` / `--snapshot` recording — together with the tools and documents that told someone to run them and the tests whose subject was the sample set, so that no green fake-data run can be cited again. It keeps what is real: the Kit unit tests (each now declares the literal inputs it needs; no shared sample catalogue survives anywhere — Matt's ruling of 2026-11-01), `HAR` / `QueryPairs`, `CoreID.fixture`, the `APP_STORE` / `APP_LIVE` isolation and `Store.isOverridden`, the live self-test and its scaffolding (now also running the menu audit), `CORE_TOOLS` pinned by the real-server test `tui_live_bus.rs`, and the shared completion-conformance contract. Six live-path differences are listed in D3, each a removal of an invented fallback. Each frontend gets one gate: unit tests with inline inputs, source tripwires, and the real frontend on a real core with real traffic, documented in its own file.

Architect's calls in this spec: `OfflineActions` takes no `session`; `--cols` / `--rows` leave the TUI binary with the snapshot; the web testkit exports `TEST_VERSION = '0.0.0-test'` and a `memoryBus` / `flow` builder with wire-shaped flows preferred; the TUI gets `render_buffer` / `render_text` (`src/ui/mod.rs`, `cfg(test)`) and `connected_app` helpers in `src/lib.rs` and `tests/common/mod.rs`; the two menu-audit helpers lose `private`; D3 item 6 (self-test-only alert and capture guards) is listed as a behaviour change rather than hidden; `check-capture-operator-only.sh`'s deny list is trimmed rather than left to NOTE about ghosts; the deleted tools are each named in `apps/mac/CLAUDE.md` with their replacement; the defaults for Q1–Q7 above.
