Every feature, by hand or by agent.

What follows is the surface of aitmproxy. Under each one you will find the same action twice: once as a person does it, in a UI or at the command line, and once as an assistant calls it over MCP. They are the same call into the same core. The one-shot CLI (aitm <family> <verb>) runs a single command in its own process, so for anything that acts on live flows the hand side is a UI action instead.

Intercept and edit by rule

A rule says which flows to hold: by method, host or URL pattern (a wildcard or a regex), and whether to hold at the request, the response, or any phase. When interception is armed and a rule matches, the flow stops inside the proxy and shows as Paused. You can read it, change any part of it and resume, or kill it.

Interception can be armed and disarmed without restarting anything. With no rules, arming holds every request. Rules come from the macOS app (Breakpoint Rules) or from flow.intercept over MCP; the web UI and the TUI arm and disarm with i.

  • Edit method, URL, headers and body of a held request.
  • Edit status, headers and body of a held response.
  • An edited flow keeps its original, so the inspector can diff it and revert the edits.

Replay and compose

Replay sends a captured request again and records the result as a new flow, marked as a replay. Compose builds a request from nothing: method, URL, headers, body. Both go out through the proxy's own client rather than the capture path, so intercept rules and plugins do not fire on them, and both are scope- and rate-guarded: a host outside the scope is refused.

Replays are how you turn a hunch into evidence: edit a captured request, send it again, and compare the two responses.

handweb UI or TUI select a flow, press r to replay, n to compose
agentflow.replay({ id: "<flow-id>" })
hand$ aitm request send --authority shop.example.com --scheme https --path /api/products
agentrequest.send({ authority: "shop.example.com", scheme: "https", path: "/api/products" })

The one-shot CLI runs its own core, so the flow it captures is gone when it exits. To keep flows and edit them, drive a running core from a UI or over MCP.

Map Local and Map Remote

Map Local answers a matching request from a file on disk: a JSON fixture, an HTML page, an image. The client never knows. It is the fastest way to test a UI against a response that does not exist yet, or one that is hard to trigger.

Map Remote rewrites where a request goes: send production hostnames to a local server, or point a mobile build at staging without rebuilding it. The new target is an active destination, so it must be in scope.

Map Local serves files from the directory set as maps.root in config.yaml; with no root, Map Local is unavailable. An agent can author rules only when maps.allow_agent_authoring is on.

handweb UI, operator session ⌘K → map.add: kind local, url */api/flags, file flags.json
agentmap.add({ kind: "local", condition: { method: "GET", url: "*/api/flags" }, action: { path: "flags.json" } })
handweb UI, operator session ⌘K → map.add: kind remote, host api.example.com, to localhost:4000
agentmap.add({ kind: "remote", condition: { host: "api.example.com" }, action: { to: { authority: "localhost:4000", scheme: "http" } } })

WebSocket inspect, inject and edit

A WebSocket is a flow too. After the upgrade, aitmproxy shows every frame in both directions as it happens: text or binary, with size, timing and direction. Hold a frame with a rule, change it, and let it continue or drop it. Or inject a frame of your own toward the client or the server. Injection is active traffic, so it is refused unless the flow's host is in scope.

handweb UI ⌘K → ws.send: pick the flow, direction c2s, opcode text, data {"op":"subscribe","ch":"orders"}
agentws.send({ id: "<flow-id>", dir: "c2s", opcode: "text", data: '{"op":"subscribe","ch":"orders"}' })
handweb UI ⌘K → ws.intercept, then ws.frame on the parked frame: forward (optionally edited) or drop
agentws.intercept({ rules: [{ ws_dir: "c2s" }] }); ws.frame({ id: "<flow-id>", index: 3, action: "forward", data: "…" })

HTTP/2, decrypted per stream

Modern apps speak HTTP/2, so aitmproxy does too. It negotiates h2 with the client over ALPN, decrypts the connection with the local CA, and presents each multiplexed stream as an ordinary flow — request and response, headers and body — that you read and edit before it goes on. The multiplexing is handled for you.

  • The client's ALPN offer is mirrored upstream, so both halves of a connection speak the same HTTP version.
  • A held stream suspends only itself; its sibling streams keep running. Killing a stream resets it.
  • Interception, Map Local and Map Remote, and plugins see each stream as an ordinary flow.
handweb UI select the paused stream, press e, edit the body, Apply & Resume

Raw L4 packet interception

Not everything is HTTP. At layer 4 aitmproxy captures TCP and UDP packets on an interface, crafts and injects packets of your own, sends a probe and reads the reply, and — where the host allows — holds a packet in the path so you can read, edit and release the wire bytes of any protocol. L4 flows appear in the same flow list as HTTP, under the same scope, sensitivity and confirmation rules.

  • Packet capture with a hex and ASCII view, scoped by CIDR, interface and direction.
  • In-path hold, mutate, forward or drop: Linux only, through NFQUEUE, with CAP_NET_ADMIN. Capture and inject need CAP_NET_RAW.
  • Off by default (l4.enabled). Without privilege the wire commands answer L4Unavailable. The macOS app's embedded core degrades the same way; since v0.5.2 the app ships a Network Extension capture path, off by default behind an operator toggle.

Attack-surface scanner

The scanner is a plugin that maps a target before you test it. scan.discover drives the embedded browser to crawl an authorized, in-scope target breadth-first, then reads the captured flows back to enumerate injection points — query and body parameters, headers, cookies, path segments. It is a command like any other, so an operator runs it from a UI and an assistant can be tasked with the same call over MCP.

  • Deny-by-default: a target outside the scope is refused before the crawler opens a page.
  • Returns the endpoints found, the injection points, pages crawled and why it stopped.
  • Discovery only today: it reads and enumerates, and never injects. Active fuzzing and injection are on the roadmap.
handweb UI Scan → pick an in-scope target → Discover (TUI: Scan view, then r)
agentscan.discover({ target: "https://staging.example.com/", max_depth: 2, max_pages: 50 })

A real crawl needs a running proxy with its embedded browser. The one-shot aitm scan discover has no browser and an empty store, so it cannot crawl.

Sessions and HAR import and export

A session is a saved flow store: a native aitm-session/1 JSON file. Save one at the end of a test and load it back later; loading replaces the store and makes no upstream requests. Flows can be exported as HAR 1.2 for any tool that reads it, and HAR files or mitmproxy .flows files can be imported; imported flows are marked as imported and are never replayed.

An agent may read and write a host path only when session_io.allow_agent_file_io is on. It can always export to, or import from, in-memory bytes.

handweb UI, operator session ⌘K → session.save: path checkout.json, then flow.export: format har
agentflow.export({ format: "har" }) // returns the HAR as bytes; a path needs session_io.allow_agent_file_io

TLS passthrough for pinned hosts

Some hosts pin their certificates and will refuse any proxy. Rather than break them, list them: aitmproxy tunnels those connections through untouched and records only that they happened. Everything else is decrypted with the local CA and inspected as usual. Patterns accept a leading wildcard, and the list can be changed while the proxy is running. To start with a list, set tls.passthrough in config.yaml. An agent can change the list only when tls.allow_agent_passthrough is on.

handweb UI, operator session ⌘K → tls.passthrough.add: host *.icloud.com
agenttls.passthrough.add({ host: "*.icloud.com" }) // one host per call; needs tls.allow_agent_passthrough

Embedded headless browser

aitmproxy bundles a headless browser engine, obscura, that is already pointed at the proxy and already trusts its certificate. It exists for one reason: to reproduce a finding the way a user's browser would, and to take the screenshot that proves it. The browser is a step type in the PoC format, and its navigation is scope- and SSRF-guarded.

handweb UI Browser panel → enter the URL; the Eval drawer runs window.__aitm (TUI: browser view, g for the URL)
agentbrowser.navigate({ url: "https://staging.example.com/search?q=k7x2" }); browser.eval({ expr: "window.__aitm" }); browser.screenshot()

The one-shot CLI has no browser handle, so the browser.* commands run from a UI, a PoC, a plugin or over MCP.

Certificate management

On first run aitmproxy generates a root certificate authority for your machine only. aitm ca can export it, report whether each trust store has it, install it into the OS trust store (the macOS keychain, or the Linux ca-certificates anchors), and remove it again. Install and uninstall ask for confirmation first; --yes skips the prompt and --dry_run lists the commands without running them.

An assistant can export the certificate and check status. Install and uninstall are refused from an agent unless ca.allow_agent_install is set. The embedded browser trusts the CA on its own and needs no installation.

hand$ aitm ca install
agentca.status() // ca.install is refused unless ca.allow_agent_install is set

All of it, scriptable

Every capability on this page is a registered command. The web UI, the terminal UI and the macOS app call it by that name, an assistant calls it over MCP under the same scope and sensitivity rules, and the self-contained ones also run one-shot from the CLI. Rhai plugins run in a sandbox, reach the flow, HTTP, browser, store and scope through guarded host calls, and can register commands of their own. Whoever issues a command, the activity log records its origin, the command, its redacted arguments and whether it ran.

Try it on your own traffic.

Tap, install, trust the certificate, start the web UI.

$ brew tap mrbrutti/aitmproxy
$ brew install aitm
$ aitm ca install
$ aitm web

aitm web prints a one-time web UI (agent): http://127.0.0.1:8082/#t=… link; open it in a browser. Homebrew installs the Apple Silicon build; Linux uses a package from the download page.
