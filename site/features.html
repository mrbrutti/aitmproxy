Every feature, by hand or by agent.

What follows is the whole surface of aitmproxy. Every action is one registered command, the same on every surface: a person runs it in the app or the terminal UI (and one-shot on the CLI for setup and scripting), an assistant calls it over MCP. A live, held flow is driven from a UI or over MCP — the one-shot aitm CLI does not attach to a running proxy. Each feature below shows the command by hand and as an agent calls it.

Intercept and edit by rule

A rule says which flows to hold: by method, host, path pattern, header or body match, and whether to hold the request, the response, or both. When a rule fires, the flow stops inside the proxy and appears as armed. You can read it, change any part of it and resume, or drop it and answer the client yourself.

Rules can be armed and disarmed without restarting anything. A one-off hold on a single flow needs no rule at all: arm the flow from the list and the next matching request waits.

  • Edit method, URL, headers and body of a held request.
  • Edit status, headers and body of a held response.
  • Every resume records a diff against the original in the flow's history.

Replay and compose

Replay sends a captured request again, optionally with changes, and records the result as a new flow linked to the original. Compose builds a request from nothing: method, URL, headers, body. Both go through the same pipeline as live traffic, so rules and plugins apply to them too.

Replays are how you turn a hunch into evidence: change one header, one parameter, one byte, and compare the two responses side by side.

in appselect flow #41 → add a header → Replay
agentflow.replay({ id: 41, edits: { headers: { "X-Debug": "1" } } })

Map Local and Map Remote

Map Local answers a matching request from a file on disk: a JSON fixture, an HTML page, an image. The client never knows. It is the fastest way to test a UI against a response that does not exist yet, or one that is hard to trigger.

Map Remote rewrites where a request goes: send production hostnames to a local server, swap one API version for another, or point a mobile build at staging without rebuilding it.

hand$ aitm map local add --match 'GET /api/flags' --file ./fixtures/flags.json
agentmap.local.add({ match: "GET /api/flags", file: "./fixtures/flags.json" })
hand$ aitm map remote add --from 'https://api.example.com/*' --to 'http://localhost:4000/*'
agentmap.remote.add({ from: "https://api.example.com/*", to: "http://localhost:4000/*" })

WebSocket inspect, inject and edit

A WebSocket is a flow too. After the upgrade, aitmproxy shows every frame in both directions as it happens: text or binary, with size, timing and direction. Hold a frame with a rule, change it, and let it continue. Or inject a frame of your own toward the client or the server, from the app, the CLI or a plugin.

HTTP/2, decrypted per stream

Modern apps speak HTTP/2, so aitmproxy does too. It negotiates h2 with the client over ALPN, decrypts the connection with the local CA, and presents each multiplexed stream as an ordinary flow — request and response, headers and body — that you read and edit before it goes on. The HEADERS and DATA frames are the flow; the multiplexing is handled for you.

  • ALPN-negotiated h2 on both sides, falling back to HTTP/1.1 when the server only offers it.
  • Pseudo-headers (:method, :path, :authority) are editable like any other header.
  • Intercept rules, replay, Map Local and Remote, and plugins all apply unchanged.
in apphold stream 5 → edit the DATA frame → Resume
agentflow.mutate({ id: 52, edits: { body: '{"query":"query { me { role } }"}' } })

Raw L4 packet interception

Not everything is HTTP. aitmproxy can sit on a raw TCP stream at layer 4, capture the bytes in both directions, and hold a segment the same way it holds a request — so you can read, edit and release the wire bytes of any protocol, from an encrypted database driver to a custom binary RPC. L4 flows carry the same lifecycle, the same commands and the same scripting as HTTP.

  • Per-direction byte capture with a hex and ASCII view, by connection.
  • Hold, edit and resume raw segments; or drop a connection outright.
  • L4 steps are scriptable in the same Rhai and PoC surface as HTTP.
hand$ aitm l4 add --listen 5432 --upstream 'db.internal:5432'
agentl4.add({ listen: 5432, upstream: "db.internal:5432" })

Attack-surface scanner

The scanner is a plugin that maps a target before you test it. scan.discover drives the embedded browser to crawl an authorized, in-scope target breadth-first, then reads the captured flows back to enumerate injection points — query and body parameters, headers, path segments. It is a command like any other, so an operator runs it and an assistant can be tasked with the same call over MCP.

  • Deny-by-default: a target outside the session scope is refused before the crawler opens a page.
  • Returns the endpoints found, the injection points, pages crawled and why it stopped.
  • Discovery today; injection and PoC generation build on the same seam.
hand$ aitm scan discover --target 'https://staging.example.com'
agentscan.discover({ target: "https://staging.example.com" })

Sessions and HAR import and export

A session is a saved capture: every flow, every edit, every finding, with the rules that were active. Save one at the end of a test, reopen it next month, replay from it. Sessions can be exported as HAR for any tool that reads it, and HAR files from a browser or another proxy can be imported and treated like live captures.

hand$ aitm session save checkout.aitm && aitm har export --session checkout.aitm > checkout.har
agentsession.save({ path: "checkout.aitm" }); har.export({ session: "checkout.aitm", path: "checkout.har" })

TLS passthrough for pinned hosts

Some hosts pin their certificates and will refuse any proxy. Rather than break them, list them: aitmproxy tunnels those connections through untouched and records only that they happened. Everything else is decrypted with the local CA and inspected as usual. Patterns accept wildcards, and the list can be changed while the proxy is running.

hand$ aitm tls passthrough add '*.icloud.com' 'pinned.bank.example'
agenttls.passthrough.add({ hosts: ["*.icloud.com", "pinned.bank.example"] })

Embedded headless browser

aitmproxy ships a headless browser that is already pointed at the proxy and already trusts its certificate. It exists for one reason: to reproduce a finding the way a user's browser would, and to take the screenshot that proves it. The browser is a step type in the PoC format, and a command like any other.

hand$ aitm browser open 'https://staging.example.com/search?q=k7x2' --screenshot confirmed.png
agentbrowser.open({ url: "https://staging.example.com/search?q=k7x2", screenshot: "confirmed.png" })

Certificate management

On first run aitmproxy generates a local certificate authority for your machine only. aitm ca can export it, report whether the system trusts it, install it, and remove it again. Installing into the system trust store always asks for confirmation. An assistant can export and check status, but installing is gated behind a human.

hand$ aitm ca install
agentca.status() // install is a human-only command

All of it, scriptable

Everything on this page is reachable from a Rhai plugin, from the CLI, and from an assistant over MCP. Plugins run in a sandbox with a declared capability list; the MCP server exposes the same command set with the same names. Whatever the operator, the audit log records the command, its arguments and its effect.
