The PoC format

A PoC is a saved, re-runnable reproduction of a finding: a few steps, a few matchers and one success condition, in a YAML file a colleague can read top to bottom. Write one when you confirm something; run it again when you need to know whether it is still true.

What a PoC is

Findings decay. A screenshot proves what was true on Tuesday; a PoC proves what is true now. aitmproxy stores a PoC as a declarative file rather than a script so that it has no hidden state, can be diffed and reviewed like code, and can be written by a person first and an assistant second. Every PoC run passes through the proxy, so the flows it generates are captured, inspectable and auditable like any other traffic.

Schema

KeyTypeMeaning
idstring, requiredA stable slug. Used in filenames, findings and the audit log.
info.namestring, requiredOne line a reader understands without opening anything else.
info.severityinfo | low | medium | highCarried onto the finding when the PoC succeeds.
info.tagslist of stringsOptional, filterable.
varsmapDefault values for {{variables}}; see Variables.
stepslist, requiredRun in order. Each step is one of the step types. A step with matchers that fails stops the run.
successall or any of conditionsEvaluated after the last step. Decides whether the finding is confirmed.

Step types

httpsend one request through the proxy
url (required), method (default GET), headers, body, follow_redirects (default false), matchers. The response is kept for later matchers and for {{last.body}}.
browserdrive the embedded headless browser
action is one of navigate (url), screenshot (label), eval (expr, stores the result), click (selector), fill (selector, value). The browser already trusts the proxy and goes through it.
replayre-send a captured flow
flow (id from the session) with optional set_header, set_body, set_query. Useful for PoCs written from a live session.
wsWebSocket exchange
url, then a send list and an expect list of frames; timeout_ms.
waitpause
ms. For targets with eventual consistency.

Matchers and success

Matchers sit inside a step and check its result. Success conditions sit at the end and check the whole run. They share one vocabulary:

typefieldstrue when
wordpart, word (string or list), condition (and or or)the given part contains the word(s)
regexpart, regexthe part matches
statusstatus (int or list)the response status is one of them
headername, equals or containsthe header matches
browser-evalexpr, equalsthe expression, evaluated in the page, equals the value
screenshot-existslabela screenshot with that label was taken

part is one of body, header, status or all. Any matcher takes negative: true to invert it.

Variables

Anything in {{double braces}} is substituted before a step runs. Three names are reserved:

  • {{target}} — the base URL, always supplied on the command line so a PoC file never hard-codes a host.
  • {{marker}} — a random token generated per run, so a reflection cannot be a coincidence or a cache.
  • {{payload}} — by default the marker wrapped in the PoC's vars.payload template; override it per run.

Everything else comes from vars in the file, overridden by --var name=value. Results of earlier steps are reachable as {{last.body}}, {{last.status}} and {{steps.N.body}}.

Complete example

A reflected value in a search parameter. The first step sends the marker and checks it comes back in the body. The second step opens the same page in the embedded browser and keeps a screenshot. Success requires that the page's own JavaScript saw the marker, which is a stronger claim than text in a body.

Running a PoC

Run one file or a directory of them. The exit code is 0 when every PoC's success condition holds, so a PoC can sit in CI as a regression test for a fix. By agent, the same call returns the result as structured data.

hand$ aitm poc run pocs/reflected-xss-search-q.yaml --var target=https://staging.example.com
agentpoc.run({ path: "pocs/reflected-xss-search-q.yaml", vars: { target: "https://staging.example.com" } })

Like every command, a PoC run is recorded in the audit log with its operator, its variables and the flows it produced. A reproduction nobody can trace is not a reproduction.
