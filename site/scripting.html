Rhai scripting

A script is a small Rhai file that defines hooks, functions the proxy calls as each flow passes. A hook can edit the flow, answer it, pause it, or record a finding. Rhai reads like a tidy scripting language, and a script should fit on one screen.

There is no install directory and no manifest. Point the proxy at a .rhai file with --script, list it under scripts: in the config, or keep it in the configured rhai.scripts_dir; Loading and managing has the details. Scripts are read when the proxy starts, and an agent that is allowed to can add or replace one while it runs.

Capability model

A script starts with nothing, and it cannot ask for more: there is no capability header, and a script cannot grant itself anything. What it can reach is fixed by the engine and by a few switches in the config, all off by default. Every host call passes the same scope, rate and SSRF guards a built-in plugin does.

ReachWhat a script gets
The languageStrings, numbers, arrays, maps, blobs and closures. No import, no eval, no clock, and sleep is refused. print and debug write to the log. The language has no file, shell, environment or socket access; the host calls below are the only way out.
The flow in the hookA snapshot of the flow being dispatched: read it, edit it, answer it, pause it or kill it. Edits are applied only if the hook finishes without an error.
finding, log, optionAlways available. finding and log only report; option reads the options set for this script.
http.sendSent through the proxy's own client, and refused unless the host is in scope. Rate-limited; the exchange is captured as a flow. http and https URLs only.
browser.*Needs the embedded browser. navigate is checked against scope and the SSRF policy, like the browser.navigate command. Refused inside a flow hook, because the browser's own traffic passes through the chain that hook is holding; use it from a script command or a PoC script step.
store.get, store.queryRead-only access to captured flows.
scope.list, scope.addscope.list reads. scope.add is refused unless the config sets rhai.allow_scope_add, and it never works from a PoC step. Every call is logged at warn level with the script's name.
HelpersEncoding, hashing, random and regex functions. They are pure functions of their arguments and touch nothing outside the engine, so nothing gates them.
l4.*Present only when the L4 module is enabled. Its calls pass L4's own scope and per-capability agent gates, and a script loaded from a file counts as agent-authored for them.

Each hook gets two seconds of wall-clock time and 64,000 operations; one browser.* call gets thirty seconds of its own. Strings and blobs are capped at 10 MiB, the default body cap, maps at 16,384 entries, and call depth at 64. A hook that runs over, throws, or is refused by a guard is aborted: its edits are discarded and the flow carries on unchanged. A refused host call raises a catchable error that carries capability, host and reason.

The switches live under rhai: in the config file.

  • allow_scope_add: scripts may call scope.add. Off by default, because widening scope also lifts the SSRF block for the host named.
  • scripts_dir: the one directory script.save may write <name>.rhai into. Unset, script.save is refused. Its *.rhai files also load at startup.
  • allow_agent_authoring: an agent over MCP may run script.save, script.reload, script.enable and script.disable. Off by default. The human CLI and an operator-token connection are not gated by it.
  • strict: a script that fails to compile stops startup. By default it is skipped and the error is logged.
  • hook_timeout and browser_timeout (seconds), max_operations, max_string_size, max_array_size, max_map_size, max_call_levels, max_expr_depth, max_function_expr_depth and max_modules: the limits above.

The model is built to grow. A new protocol adds its own namespace, as L4 does, behind the same deny-by-default guards and without a change to the language. A script may name itself and pin the API version it was written for; one that declares an older version than a namespace needs is not loaded. Both constants are read without running the script, so both must be literal strings. NAME also identifies the script in script.list, in script.reload and as the source of its findings.

Hooks

A hook is a top-level function with one of the names below, and these are the only hooks. Define the ones you need. A misspelled on_… name or the wrong number of arguments is not an error, but the loader warns about it and aitm script validate prints the warning.

Scripts run after the built-in plugins, so a script sees a flow once Map rules have rewritten it. They run in the order they were loaded: scripts: entries first, then scripts_dir files by name, then --script flags. A hook that calls halt() stops the remaining scripts and plugins for that event.

load(reg)once, at startup
Called once when the proxy starts, with the registration handle. Register commands with reg.add_command(name, help, |args| …) and options with reg.add_option(name, default, help). A script added later with script.save never gets load run, so its commands and options appear after a restart; its other hooks run at once.
configure()not called today
The loader accepts the name and the catalog lists it, but nothing in the engine calls it yet. Do not rely on it.
on_request_headers(flow)HTTP
The request headers are parsed; the body has not been read.
on_request(flow)HTTP
The whole request is available, before it goes upstream. Edits here reach the server, and flow.set_response(…) answers the client and skips upstream. Most scripts live here.
on_response_headers(flow)HTTP
The response headers are parsed; the body has not been read.
on_response(flow)HTTP
The whole response is available, before it goes to the client. Edits here reach the client.
on_ws_start(flow)WebSocket
A WebSocket connection was established.
on_ws_message(flow, msg)WebSocket
Called for each frame, in either direction. msg.direction is "c2s" or "s2c"; replace the payload with msg.set_text or msg.set_bytes, or call msg.drop() to stop the frame being forwarded.
on_ws_end(flow)WebSocket
The WebSocket connection closed.
on_error(flow, err)any flow
A flow-level error. err is the error text. A failure inside on_error is logged and nothing more, so it cannot feed itself.

A hook works on a snapshot of the flow. Field edits, and calls such as set_response, intercept and kill, are applied when the hook returns, in the order you made them. If the hook throws, times out or runs out of operations, none of it is applied: the flow carries on exactly as it was, the error is logged and published on the bus as a flow error, script.list shows it as last_error, and the next script still runs. A load(reg) that throws is reported the same way and registers nothing.

Functions do not see script-level variables, with one convenience: a top-level const whose value is a literal (a string, number, bool, char, or an array or map of literals) is visible inside every hook and inside the closures you register from load(reg). The engine resolves those names inside functions from the script's constants, so const SQL_ERR = "(?i)SQL syntax"; read from on_response or from a |args| … command body works as written, including as a method receiver (PATHS.contains(p)). A constant computed by a call (const Z = f();) is not visible inside functions; compute it where you use it. A parameter or let with the same name shadows the constant, as usual. Inside a function the constant is read-only, like every Rhai constant: PATHS.push(x) is refused with cannot be called on constant; copy it first (let p = PATHS; p.push(x)).

A closure captures every outer name it mentions when it is created, not when it runs. Inside load(reg) that means a command body naming an optional namespace, such as l4 when the L4 layer is off, fails at load, before any try inside it runs. Call the namespace from a named function and keep the try in the closure: fn recon() { l4.interfaces() } then |args| { try { recon() } catch (e) { … } }.

The flow API

Every hook receives a flow. A read with an obvious empty answer, such as a missing header or the response in on_request, returns an empty value instead of failing. A write that cannot work fails with the fix in the message.

The flow

flow.idstring
The flow's id, as the rest of the tool prints it. Pass it to finding as flow_id.
flow.kind"http" or "ws"
Whether this is an HTTP or a WebSocket flow.
flow.is_replaybool
True when this flow is a replay.
flow.marksarray
The marks on the flow. flow.mark(tag) adds one, once.
flow.commentstring, settable
The operator's comment on the flow.
flow.requestobject
The request side. On a WebSocket flow it reads as empty and writes fail.
flow.responseobject
The response side. It reads as empty in on_request and on_request_headers, and writing to it before a response exists is an error: answer with flow.set_response instead.

Request and response

request.methodstring, settable
Must be an HTTP token such as GET.
request.urlstring, settable
scheme://authority/path?query. A new value may change the path and query only; changing the host is refused. Reach another host with http.send.
request.pathstring, settable
The path without the query. A space or control character is refused; percent-encode it.
request.querymap-like
get, set, remove, has and keys, or query["name"]. Keys match exactly.
request.headers
response.headersmap-like
get(k) returns an empty string when the header is absent. set(k, v) changes an existing header or adds one. Also remove(k), has(k), keys() and headers["Name"]. Names match case-insensitively, and a name or value with a control character is refused.
request.body
response.bodystring, settable
The body as text. A binary body reads as lossy UTF-8; use bytes for the raw data.
request.bytes
response.bytesblob, settable
The body as raw bytes.
request.set_json(map)method
Set the body to the JSON encoding of the map, and Content-Type to application/json.
response.statusint, settable
The response status code.

A script sees a body up to the proxy's body cap, limits.max_body_bytes; a body that was streamed rather than buffered reads as empty.

Controlling the flow

flow.set_response(status, headers, body)method
Answer the client with this response and skip upstream. headers is a map and body a string. Use it in on_request, often followed by halt() so later scripts leave the flow alone.
flow.intercept()method
Pause this flow, as an intercept rule would, for a person or an agent to resume, mutate or kill.
flow.resume()
flow.kill()method
Resume a paused flow, or kill it so the client sees a closed connection.
flow.backup()
flow.revert()method
Snapshot the flow so it can be reverted; restore the flow to its last backup.

The msg argument of on_ws_message.

msg.direction"c2s" or "s2c"
Client to server, or server to client.
msg.opcodestring
"text", "binary", "ping", "pong" or "close".
msg.textstring, settable
The payload as text.
msg.datablob
The payload as bytes.
msg.set_text(s)
msg.set_bytes(b)method
Replace the payload.
msg.drop()method
Do not forward this frame.

Host functions

log(msg)
log.info(msg)
log.warn(msg)
log.error(msg)log
Write to the script log. log(msg) is the same as log.info.
option(name)value
One of this script's options: the default from reg.add_option, overridden by options: on its scripts: entry. An option that is not set reads as ().
finding(map)
halt()see below
Record a finding; stop the chain for this event.
http.send(#{ method, url, headers, body })→ #{ status, headers, body, flow_id }
Send a request through the proxy's client. url is required and method defaults to GET. A refused host raises a catchable error.
store.get(id)
store.query(#{ … })flow maps
get returns one flow, or () if it is not stored. query takes any of host, method, status, kind and is_replay and returns an array. A flow map has id, kind, is_replay, marks, request and response.
scope.list()
scope.add(host)gated
The hosts in scope; add one. scope.add needs rhai.allow_scope_add.
browser.navigate(url)
browser.click(selector)
browser.type_text(selector, text)
browser.screenshot()
browser.evaluate(expr)
browser.get_dom()not inside a flow hook
Drive the embedded browser. screenshot returns PNG bytes. In a script the names are type_text and evaluate because type and eval are reserved words in Rhai; the commands are still browser.type and browser.eval.
b64_encode(s)
b64_decode(s)
url_encode(s)
hex_encode(s)
sha256(s)
md5(s)encoding and hashing
Strings in, strings out; digests are lowercase hex. b64_decode raises an error on invalid base64 or bytes that are not UTF-8. md5 is there because targets still use it, not as a security primitive.
rand_text_alpha(n)
rand_int(a, b)
regex_match(pat, s)
regex_extract(pat, s, group)random and regex
Random values are not cryptographic. regex_extract returns an empty string when nothing matches; an invalid pattern raises an error.
ok(resp)
contains_ci(hay, needle)
json(map)prelude
ok is true for a 2xx status, on an http.send result or a flow.response. contains_ci is a case-insensitive substring test. json is the JSON text of a map.

Findings and halting

A finding is a structured note recorded with finding(...). Findings are held in memory for the current run, the newest 10,000, and read back with script.findings; nothing is written to disk. The persistent store, findings.list, findings.get and findings.record, is separate, and finding(...) does not write to it. To keep a finding, record it there.

A field it does not know is refused with a message that lists the valid ones, and so is an unknown severity. halt() ends processing of the current event by later scripts and later plugins. It does not answer, pause or drop the flow: do that with set_response, intercept or kill. Only the call counts. A hook's return value is ignored, so the way to continue is to not call halt().

Loading and managing

A script loads at startup three ways: with --script <path> on aitm, aitm web or aitm tui, repeated for more than one; from scripts: in the config file; or from the *.rhai files in rhai.scripts_dir. An agent can also add one while the proxy runs.

hand$ aitm web --script ./guard-admin-writes.rhai
agentscript.save({ name: "guard-admin-writes", source: "…" })

script.save checks that the source compiles, writes <scripts_dir>/<name>.rhai and puts the script into the running chain, so its hooks fire on the next event with no restart. The name may use letters, digits, _ and -. An optional enable: false saves it switched off. The reply carries restart_required, which is true only when the script registers commands or options. An agent can do this only when rhai.scripts_dir is set and rhai.allow_agent_authoring is true, and under the ask policy each call waits for approval. Its calls land in the audit log like any other.

An entry under scripts: may also carry options:, which the script reads with option(name). Relative paths are taken from the directory you start aitm in.

script.listread
The loaded scripts in chain order: name, path, api, hooks, enabled and last_error.
script.validate { path | source }read
Compile a file, or script text given inline, without loading it. Reports the name, API, hooks and the commands and options load registers, or the positioned compile error. From an agent, a path must be a .rhai file inside the configured scripts or PoC directory.
script.save { name, source, enable? }sensitive
Compile, write and load, as above.
script.reload { name }sensitive
Recompile a loaded script from its file and swap its hooks in live. A failed recompile keeps the previous version. Commands and options registered in load do not change until a restart.
script.enable { name }
script.disable { name }sensitive
Switch a loaded script's hooks on or off live. Its registered commands stay.
script.findings { limit? }read
What scripts recorded with finding(...) this run, oldest first, and how many the bounded buffer dropped.

From a terminal, aitm script validate compiles a file on this machine and needs no core. aitm script list, enable, disable, reload and save act on the running core's scripts, the same core MCP and the UIs talk to.
