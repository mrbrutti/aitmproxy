Rhai scripting

A plugin is a small Rhai file with a capability header and one or more hooks. It sees every flow as it passes and can edit it, answer it, or record a finding. Rhai reads like a tidy scripting language; a plugin should fit on one screen.

Plugins live in ~/.config/aitm/addons/ or anywhere you point aitm addon load at. They are loaded by hand, by the app, or by an assistant over MCP, and each load is an audited command like any other.

Capability model

Plugins run inside a sandbox and start with nothing. A header comment declares what the plugin needs, and the host grants exactly that. Anything not declared is denied, and a plugin that asks for more than its hooks require is flagged when it loads.

CapabilityGrants
flow.readRead requests, responses and metadata of flows the plugin sees.
flow.writeEdit headers, body, URL and status; call set_response; arm interception.
findingsRecord findings into the session.
wsSee and edit WebSocket frames; inject frames.
fs.read:<path>Read files under one directory, for fixtures and wordlists. No write access exists.
stateA small per-plugin key–value store that survives between flows.

There is no network capability, no shell capability and no path outside the declared directory. Time is available; the clock is not writable. The same guards apply whether a plugin was loaded by a person or by an agent, and the model is designed to grow as new protocols are added without loosening the default.

Hooks

A hook is a top-level function with a well-known name. Define only the ones you need. Hooks run in flow order, one plugin after another in load order, and a hook that returns halt() stops the chain for that flow.

on_request(flow)flow.read
Called when the request headers and body have been read, before the request is sent upstream. Edits here reach the server.
on_response(flow)flow.read
Called when the response has been read, before it is sent to the client. Edits here reach the client.
on_ws_message(flow, msg)ws
Called for each WebSocket frame in either direction. msg.direction is "client" or "server"; msg.text or msg.bytes is editable.
on_intercept(flow)flow.read
Called when a flow becomes armed by a rule or by hand. Useful for tagging or for deciding to resume automatically.
on_flow_end(flow)flow.read
Called when the flow is complete, dropped or errored. Read-only; good for metrics and findings that need the whole exchange.
on_load() / on_unload()none
Plugin lifecycle. Initialise or persist state here.

The flow API

Every hook receives a flow. Reading never needs more than flow.read; each mutating call is listed with the capability it needs.

flow.idint
The flow number shown everywhere else in the tool, so a finding and a UI row match.
flow.statestring
"observed", "intercepted", "resumed" or "dropped".
flow.requestobject
.method, .url, .host, .path, .query (map), .headers, .body (string or bytes), .json() parsed on demand.
flow.responseobject, may be ()
.status, .headers, .body, .json(). Empty in on_request.
headers.has(name) / get(name) / set(name, value) / remove(name)flow.write to set or remove
Case-insensitive. set replaces all existing values.
flow.set_response(status, headers, body)flow.write
Answer the client without going upstream. Usually followed by return halt().
flow.intercept {}flow.write
Arm this flow. It will pause as if a rule had matched, for a person or an agent to deal with.
flow.tag(name)flow.write
Attach a tag visible in every UI and filterable with tag:name.
flow.tlsobject
.sni, .version, .passthrough (bool). Read-only.
state.get(key) / state.set(key, value)state
Per-plugin storage that survives between flows and restarts.

Findings and halting

A finding is a structured note attached to the session and, optionally, to a flow. Findings show up in the app, in aitm findings list, and in a saved session or PoC. halt() ends processing of the current flow by later plugins; it does not drop the flow unless you also answered it.

Complete example

This plugin blocks any non-GET request under /admin that arrives without an X-Admin-Token header, answers the client with a plain 403, records a medium finding tied to the flow, and stops. Authenticated admin writes are marked with a header and continue.

Load it, by hand or by agent, and watch it work:

hand$ aitm addon load ./addons/guard-admin-writes.rhai
agentaddon.load({ path: "./addons/guard-admin-writes.rhai" })
