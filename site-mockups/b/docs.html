Guides / Getting started

Getting started

Install aitmproxy, trust its certificate, and capture and intercept your first request — from the terminal or any of the three UIs.

Install

aitmproxy ships as a single binary for macOS and Linux. On macOS, install it from the Homebrew tap:

shell
$ brew install mrbrutti/aitmproxy/aitm
$ aitm --version

The binary bundles the web UI and the embedded obscura browser, so there is nothing else to download.

Run the proxy

Start the core together with a UI. Each UI is a thin client of the same command bus — pick whichever fits the moment.

shell
$ aitm web          # core + SolidJS web UI
$ aitm tui          # core + ratatui terminal UI
# web UI: http://127.0.0.1:8082/#t=<token>
The token is printed once. Every frontend connects with the operator token class, so the core treats the UIs as operators — never as the agent.

Trust the certificate

To read HTTPS, the client must trust aitmproxy's root certificate. Installing into the OS trust store is always a human-in-the-loop step; the agent cannot install a CA by default.

shell
$ aitm ca status
$ aitm ca install --scope user      # prompts before touching the trust store

Capture your first flow

Point your client at 127.0.0.1:8080 and browse. Every interaction becomes a typed Flow in the list:

aitmproxy · listening on 127.0.0.1:8080AllHTTPSWS
#MethodURLStatusTime
1GET/api/users/me20012ms
2POST/api/auth/login20088ms
3GETwss://api.example.com/ws/chat101—

Intercept and edit

Add a rule to park matching flows instead of setting a global breakpoint. Parked flows wait at the request or response phase until you resume or kill them.

shell
$ aitm flow intercept --url '*/api/cart/*' --phase request
$ aitm flow mutate --id 42 --set-header 'X-Debug: 1'
$ aitm flow resume --id 42

The same actions are available as flow.intercept, flow.mutate and flow.resume on the command bus — which is exactly what the UIs and the MCP agent call.
